# 条件分支节点规则引擎设计文档

## 1. 背景与目标

### 1.1 现状
当前工作流的「条件分支」节点仅支持单一比较：

```json
{
  "left": "{{n3.chechang}}",
  "operator": ">",
  "right": "10000"
}
```

只能输出 `true/false` 两个出口。当业务需要多字段组合判断时，用户不得不串联多个条件节点，流程图冗长且可读性差。

### 1.2 目标
在不破坏现有工作流的前提下，升级条件分支节点，引入轻量规则引擎：

- 支持 **多条件组合**：`AND` / `OR`。
- 支持 **任意层级嵌套**：条件组里可以继续放条件组。
- 支持 **更丰富的运算符**：除 `> < ==` 外，增加 `contains`、`in`、`regex`、`empty` 等。
- 保持 **两个出口** `true/false` 的交互习惯，降低学习成本。
- 与旧版条件节点 **完全兼容**，旧工作流无需手动迁移即可运行。

---

## 2. 术语

| 术语 | 说明 |
|------|------|
| 叶子条件 | 最小判断单元：`字段 运算符 值`。 |
| 条件组 | 由组合器 `AND` 或 `OR` 连接的一组叶子条件或子条件组。 |
| 规则树 | 整个条件分支节点的判断逻辑，根节点是一个条件组。 |
| 求值上下文 | 当前工作流已执行节点的输出集合 `context`，用于 `render()` 解析变量。 |

## 3. 数据模型

### 3.1 新版配置结构

```typescript
interface ConditionRule {
  // 组合器：仅条件组有效
  combinator?: 'and' | 'or'

  // 是否取反（可选）
  negate?: boolean

  // 子规则：仅条件组有效
  rules?: ConditionRule[]

  // 叶子条件字段
  field?: string          // 变量引用，如 "{{n3.chechang}}"
  operator?: Operator     // 运算符
  value?: any             // 比较值，支持变量引用
}

type Operator =
  | '==' | '!='
  | '>' | '>=' | '<' | '<='
  | 'between' | 'not_between'
  | 'contains' | 'not_contains'
  | 'startsWith' | 'endsWith'
  | 'in' | 'not_in'
  | 'regex' | 'not_regex'
  | 'empty' | 'not_empty'
  | 'exists' | 'not_exists'   // 变量是否存在（非 None / 非缺失）
  | 'type'                     // 值的类型：number | string | bool | array | object | null

interface ConditionNodeConfig {
  mode: 'simple' | 'advanced'   // simple = 旧版单条件，advanced = 规则树
  // simple 模式保留旧字段
  left?: string
  operator?: string
  right?: string
  // advanced 模式使用 rule
  rule?: ConditionRule
}
```

### 3.2 配置示例

#### 简单模式（兼容旧版）

```json
{
  "mode": "simple",
  "left": "{{n3.chechang}}",
  "operator": ">",
  "right": "10000"
}
```

#### 高级模式

```json
{
  "mode": "advanced",
  "rule": {
    "combinator": "and",
    "rules": [
      {
        "field": "{{n3.chechang}}",
        "operator": ">",
        "value": "10000"
      },
      {
        "combinator": "or",
        "rules": [
          {
            "field": "{{n3.height}}",
            "operator": ">",
            "value": "1500"
          },
          {
            "field": "{{n3.zhouju}}",
            "operator": ">",
            "value": "3000"
          }
        ]
      }
    ]
  }
}
```

语义：

```
chechang > 10000 AND (height > 1500 OR zhouju > 3000)
```

## 4. 执行引擎设计

### 4.1 核心算法

后端 `workflow_engine.py` 中新增 `_eval_rule_tree(rule, context)`，递归求值：

```python
def _eval_rule_tree(rule: dict, context: dict) -> bool:
    # 1. 如果是组合节点
    if rule.get("combinator") in ("and", "or"):
        rules = rule.get("rules") or []
        if not rules:
            return True  # 空组默认 true（已确认），避免阻塞流程
        results = [_eval_rule_tree(r, context) for r in rules]
        result = all(results) if rule["combinator"] == "and" else any(results)
        return not result if rule.get("negate") else result

    # 2. 如果是叶子条件
    field_raw = rule.get("field", "")
    value_raw = rule.get("value")
    op = rule.get("operator", "==")

    left = render(field_raw, context)
    right = render(value_raw, context)

    result = _eval_leaf(left, op, right)
    return not result if rule.get("negate") else result
```

### 4.2 叶子条件求值

```python
def _eval_leaf(left, op: str, right) -> bool:
    if op == '==': return _cmp(left, right) == 0
    if op == '!=': return _cmp(left, right) != 0
    if op == '>':  return _cmp(left, right) > 0
    if op == '>=': return _cmp(left, right) >= 0
    if op == '<':  return _cmp(left, right) < 0
    if op == '<=': return _cmp(left, right) <= 0

    if op == 'contains':      return _str(right) in _str(left)
    if op == 'not_contains':  return _str(right) not in _str(left)
    if op == 'startsWith':    return _str(left).startswith(_str(right))
    if op == 'endsWith':      return _str(left).endswith(_str(right))

    if op == 'in':            return _str(left) in _to_list(right)
    if op == 'not_in':        return _str(left) not in _to_list(right)

    if op == 'regex':         return bool(re.search(_str(right), _str(left)))
    if op == 'not_regex':     return not bool(re.search(_str(right), _str(left)))

    if op == 'empty':         return _is_empty(left)
    if op == 'not_empty':     return not _is_empty(left)

    if op == 'between':       return _between(left, right)
    if op == 'not_between':   return not _between(left, right)

    if op == 'exists':        return not _is_missing(left)
    if op == 'not_exists':    return _is_missing(left)

    if op == 'type':          return _type_of(left) == _str(right).lower()

    return False


def _between(left, right) -> bool:
    lo, hi = _parse_range(right)
    if lo is None or hi is None:
        return False
    c = _cmp(left, lo)
    if c is None:
        return False
    return c >= 0 and _cmp(left, hi) <= 0


def _parse_range(right):
    try:
        seq = right if isinstance(right, list) else json.loads(right)
        if isinstance(seq, (list, tuple)) and len(seq) == 2:
            return float(seq[0]), float(seq[1])
    except Exception:
        pass
    parts = _str(right).split(',')
    if len(parts) == 2:
        try:
            return float(parts[0]), float(parts[1])
        except ValueError:
            return None, None
    return None, None


def _is_missing(v) -> bool:
    return v is _MISSING


def _type_of(v) -> str:
    if v is None:
        return 'null'
    if isinstance(v, bool):
        return 'bool'
    if isinstance(v, (int, float)):
        return 'number'
    if isinstance(v, str):
        return 'string'
    if isinstance(v, list):
        return 'array'
    if isinstance(v, dict):
        return 'object'
    return type(v).__name__.lower()
```

### 4.3 比较辅助函数

```python
def _cmp(left, right):
    """优先按数字比较，失败退化为字符串比较。"""
    try:
        return float(left) - float(right)
    except (TypeError, ValueError):
        l, r = str(left), str(right)
        return (l > r) - (l < r)

def _is_empty(v):
    if v is None: return True
    if isinstance(v, str): return v.strip() == ''
    if isinstance(v, (list, dict)): return len(v) == 0
    return False

def _to_list(v):
    if isinstance(v, list): return [str(x) for x in v]
    if isinstance(v, str):
        try:
            parsed = json.loads(v)
            if isinstance(parsed, list):
                return [str(x) for x in parsed]
        except Exception:
            pass
        return [x.strip() for x in v.split(',')]
    return [str(v)]
```

## 5. 前端交互设计

### 5.1 总体布局

条件分支配置面板拆成两栏：

- **顶部**：模式切换开关 `简单模式 / 高级模式`。
- **中部**：规则构建器（高级模式）或单行比较（简单模式）。
- **底部**：出口说明 `true / false`。

### 5.2 简单模式

保持现有界面：左值、运算符、右值三个输入框。拖拽变量生成 `{{node.field}}`。

### 5.3 高级模式 —— 规则构建器

采用**树形查询构建器（Query Builder）**组件，参考 react-query-builder 的轻量交互：

```
[全部满足 ▼]
├─ chechang  [大于 ▼]  [10000        ]
├─ [任意满足 ▼]
│  ├─ height [大于 ▼]  [1500         ]
│  └─ zhouju [大于 ▼]  [3000         ]
└─ [+ 添加条件]  [+ 添加条件组]
```

#### 5.3.1 交互细节

| 元素 | 行为 |
|------|------|
| 组合器下拉 | 当前组切换 `全部满足(AND)` / `任意满足(OR)`。 |
| 字段输入框 | 支持拖拽变量，自动生成 `{{node.field}}`；也支持手动输入。 |
| 运算符下拉 | 根据字段类型推荐运算符，默认 `==`。 |
| 值输入框 | 支持常量、变量引用、JSON 数组（用于 `in` / `not_in`）。 |
| `+ 添加条件` | 在当前组末尾新增叶子条件。 |
| `+ 添加条件组` | 在当前组末尾新增一个空的子条件组。 |
| 删除按钮 | 删除当前行或当前组；根组不可删除，至少保留一个条件。 |
| 取反开关 | 可选，对当前行/组取反（`NOT`）。 |

#### 5.3.2 字段建议

- 左侧变量面板支持拖拽到规则构建器的字段输入框。
- 拖拽后文本为 `{{n3.chechang}}`。

#### 5.3.3 规则预览文本

高级模式下，配置面板实时显示一条可读的**规则预览文本**，与节点画布上的摘要一致。示例：

```
chechang > 10000 AND (height > 1500 OR zhouju > 3000)
```

生成规则（伪代码）：

```javascript
function previewRule(rule) {
  if (rule.combinator) {
    const parts = rule.rules.map(previewRule)
    const join = rule.combinator === 'and' ? ' AND ' : ' OR '
    let text = parts.join(join)
    if (rule.negate) text = `NOT (${text})`
    return text
  }
  // 叶子条件
  const neg = rule.negate ? 'NOT ' : ''
  return `${neg}${rule.field} ${rule.operator} ${rule.value}`
}
```

- 节点画布上条件节点卡片底部直接渲染该预览文本，方便不打开面板也能看清判断逻辑。
- 预览文本只作展示，不参与运算。

#### 5.3.4 嵌套层级限制

- 前端规则构建器**最大嵌套层级限制为 5 层**（根组计为第 1 层）。
- 当用户在第 5 层尝试「添加条件组」时，按钮置灰并提示「已达到最大嵌套层级（5 层）」。
- 后端不强制限制（Python 默认递归深度足够），但建议前端在提交时校验，避免超深规则树可读性崩坏。

### 5.4 组件选型建议

项目当前使用 Vue 3。可选方案：

| 方案 | 优点 | 缺点 |
|------|------|------|
| 自研轻量组件 | 无额外依赖，样式完全可控 | 开发量稍大 |
| `vue-query-builder` | 功能完整 | 已停止维护，Vue3 兼容差 |
| `@json2csv/plainjs` 等无关库 | — | 不适用 |

**推荐自研**。规则树是轻量 JSON，组件只需递归渲染即可，约 200 行代码。

## 6. 兼容性策略

### 6.1 旧数据

- 没有 `mode` 字段的旧条件节点，默认 `mode = "simple"`。
- 使用原来的 `left/operator/right` 字段，行为不变。

### 6.2 新旧切换

- 用户在配置面板切换模式时，旧数据不丢失。
- 简单 → 高级：前端自动把 `left/operator/right` 转成单条叶子规则，塞入 `rule`。
- 高级 → 简单：如果规则树只有一条叶子条件，自动回填到 `left/operator/right`；否则提示「当前规则包含组合，切换后会丢失，是否继续？」。

### 6.3 运行期

- 后端只读取 `mode`，两种格式互不影响。
- 结果输出仍然是 `{"result": true/false}`，下游节点无感知。

## 7. 边界与异常

| 场景 | 处理 |
|------|------|
| 条件组为空 | 默认返回 `true`（已确认），避免阻塞流程，并在前端提示「请至少添加一个条件」。 |
| 字段渲染失败 | 视为 `_MISSING`，叶子条件返回 `false`；`exists` 类运算符会据此正确判断「不存在」。 |
| 数值比较时字段非数字 | `float()` 失败则退化为字符串比较。 |
| `in` 运算符右侧格式错误 | 尝试按 JSON 数组解析，失败则按逗号字符串拆分。 |
| `between` 右侧格式错误 | 尝试按 `[a,b]` 或 `"a,b"` 解析，失败则条件返回 `false`。 |
| `type` 运算符 | 支持 `number/string/bool/array/object/null`，布尔值单独归为 `bool`。 |
| 嵌套层级过深 | 后端递归深度由 Python 默认限制（约 1000）兜底，前端限制最大 **5 层**嵌套，防止 UI 崩坏。 |
| 空值比较 | `empty` 视为真；`>` 等数值比较遇到空值按 `0` 或字符串处理，与当前行为一致。 |

## 9. 开发计划

建议按以下顺序开发：

1. **后端规则引擎**：实现 `_eval_rule_tree` 与 `_eval_leaf`，补充单测。
2. **前端规则构建器组件**：实现 `ConditionRuleBuilder.vue`，纯 UI，不联调。
3. **条件节点配置面板改造**：接入模式切换与组件，处理简单/高级切换逻辑。
4. **端到端联调**：复杂规则工作流运行验证。
5. **旧工作流回归**：确保未设置 `mode` 的条件节点行为不变。

**智能知识图谱平台（GraphRAG）** 2025.6 - 至今
**公司**：北京中兵数字科技集团有限公司
**开发环境**：Python + FastAPI + LangChain + LLM + Embedding + Rerank + Milvus + Neo4j + PostgreSQL + Vue

## 项目介绍

该平台以昆仑智平台定义的本体为语义骨架，提供“本体建模 → 知识抽取 → 图谱构建 → GraphRAG 检索 → 智能体应用”的完整知识工程链路，将企业文档、报告等非结构化数据转化为可推理、可检索的结构化知识资产。区别于普通 RAG 只做文本片段召回，平台以本体约束抽取的范围与语义，将抽取结果组织成“实体-关系-实体”的网状知识图谱；问答时采用 GraphRAG 混合检索（向量 + 关键词 + 图谱多路召回、RRF 融合、Rerank 精排、图谱多跳扩展），解决跨文档、多跳关联类问题召回不全的痛点。平台已在多家大型央企及科研院所落地，覆盖装备运维、金融风控等重点行业的数据分析与挖掘。

## 主要功能

1）**本体建模与语义约束**：定义本体类别、概念（实体类型）、属性、关系及关系约束（如“人员-任职于->组织”），支持属性模板跨领域复用与本体版本管理；本体作为知识抽取的 schema，限定抽取哪些概念、属性和关系，确保抽取结果与业务语义一致。

2）**本体引导的知识抽取**：以本体为 schema 指引，用 LLM 从非结构化文档中抽取实体、属性与关系三元组；配合规则引擎对结果做过滤、去重与属性级校验，拦截日期、纯数值、整句等低价值噪声；抽取结果经人工复核闭环确认后入库，沉淀为体系化、可复用的知识资产。

3）**知识图谱构建与图推理**：抽取结果双写关系库与图数据库，以关系库为权威、图库增量同步；按本体关系构建网状图谱，内置规则推理补全隐含关系（置信度闸门 + 人工审核闭环），支持路径发现、影响传播等图分析能力。

4）**GraphRAG 检索与召回（OAG 本体增强生成）**：向量 + BM25 并行召回 + 图谱补召回，三路 RRF 融合 + Rerank 精排；实体属性与关系作为“图谱事实”注入 prompt 且优先采信，弥补纯文本召回对跨文档、多跳问题的盲区；空召回时自动降阈值 + 关键词改写兜底重试；答案强制标注引用来源。经 RAGAS 评测迭代，图谱链路使上下文召回率从 0.80提升至 0.95、空检索显著减少。

5）**智能体构建与技能编排**：以知识库和知识图谱为知识背景构建智能体，SSE 流式问答；支持为智能体配置 skills 接入企业内业务系统，实现“知识问答 + 业务操作”统一入口；支持长短期记忆（会话内上下文压缩 + 用户级长期记忆）。

## 个人职责

## 附：一句话应答（背下来）

- **GraphRAG 的真正价值**：recall 0.54→0.98、空检索 7→0，专治实体对不上的查询——图谱和 BM25 提升“找得全”（检索侧），忠实度靠生成侧约束，两头分开归因。
- **本体驱动 vs 普通 GraphRAG**：抽取不是自由发挥，本体 schema 限定概念/属性/关系，抽取 Prompt 按本体动态组装、后处理按本体校验——保证图谱与业务语义一致。
- **图谱构建核心**：不是把三元组塞进图库，而是双写（关系库权威 + 图库增量同步）+ 实体对齐 + 规则推理补隐含关系 + 审核闭环保证不污染图谱。

## 附：OAG 全流程速记（与 `oag_service.py::query_stream` 对齐）

```
⓪ 总开关 OAG_ENABLED=false → 整体降级纯向量链路
① 向量召回    k=50；距离→相似度(1-score) 阈值过滤；空召回→降阈值0.1 + jieba关键词改写(前6词)重试
② BM25 召回   内存索引懒加载，k=50，分数降序
              前提：chunk_id = f"{file_id}_{chunk_index}" 与图库 Chunk.id 同源（三路同 id 空间才能融合）
③ 实体链接    通道A：库内实体名(≤5000)小写子串匹配问题文本（score=1.0）
              通道B：①∪② 的 chunk_id 反查 MENTIONS 边（mention 计数）
              合并去重 → 种子实体 top8（词面命中优先 → lexical+mention → mention 降序）
④ 图谱召回    ④a 种子实体反查 MENTIONS → 其它分片 top12（向量漏掉的兄弟分片）
              ④b 种子实体展开 1 跳 RELATES 子图（≤40 关系）→「图谱事实」文本（≤1600 字符）
⑤ RRF 三路融合 score = Σ 1/(60+rank+1) → 候选池 top30
              Rerank 精排：cross-encoder(query, 分片) 逐对打分重排 → top12；失败降级保留 RRF 序
              每条标注来源(vector/bm25/graph 组合)
⑥ 流式生成    prompt = 人设 + skills(预算截断) + 会话摘要 + mem0 长期记忆
              user = 【图谱事实】+【参考资料 [编号] 文件名】+ 问题；答案强制带引用
              SSE 先下发推理过程(entities/subgraph/chunks/步骤明细)再流式 token
```

注意：**非三路全并行**——③④依赖①②的召回产物，⑤等③④齐。非全并行、非全串行，"两段式"。

### RRF 一问一答

- **公式**：`RRF(d) = Σ各路 1/(k+rank+1)`，rank 从 0 起，k=60（`OAG_RRF_K`）。
- **为什么不用加权分数**：三路量纲不同（向量相似度∈[0,1]、BM25 无上界、图谱路无分数只有排名）；RRF 只用排名 → 免归一化、免调权、对离群分数鲁棒。
- **k 的作用**：平滑头部差距（rank0=1/61≈0.0164 vs rank1=1/62≈0.0161），防止单路第一名独裁；k 越小头部权重越大，60 为论文推荐值。
- **多路共识（背算例）**：A = 向量rank0 + BM25rank2 + 图谱rank1 ≈ 0.048 > B = 仅向量rank0 ≈ 0.016——多路共识胜过单路头名，正是 BM25 补词面、图谱补跨文档的意义。
- **实现**：dict 按 chunk_id 累加天然去重，复杂度 O(三路总长)；实现在 `providers/retrieval/__init__.py::rrf_fuse`，知识库问答链路与 OAG 共用。
- **RRF 之后为什么还要 Rerank**：RRF 只利用各路名次，没判断分片内容与问题是否真相关；Rerank 用 cross-encoder 对 (query, 分片) 逐对打分，专治"名次靠前但不相关"。实现共享 `providers/rerank`（cross-encoder/LLM 两档，失败返回 None → 调用方保留 RRF 序），OAG 与知识库问答链路共用 `RERANK_ENABLED` 开关与 `RERANK_CANDIDATE_K=30`/`RERANK_TOP_N=12` 参数。

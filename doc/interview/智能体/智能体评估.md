# 智能体评估——详细版（追问细节用）

汇总版见：智能体_汇总.md「评测跑批」小节。本文件展开实现细节与追问预备。

## 一、整体架构：三层分工

- **LangSmith**：评测平台。提供数据集（datasets）+ 实验（experiments）+ 打分展示/跨实验对比。**它本身不定义任何指标**——指标全是我自定义的评估器，打分以 feedback 形式上报。
- **OpenEvals / Agentevals**：judge 工具库（与 LangSmith 同门）。提供 `create_llm_as_judge` 这类**工厂函数**和一组**通用内置 Prompt**（CORRECTNESS/CONCISENESS/HALLUCINATION 等 11 个）。我项目**只用工厂，内置 Prompt 一个没用**。
- **自写脚本** `backend/scripts/langsmith/eval_langsmith.py`：读数据集 → 逐条起真实团队任务（并发 2、单条 300s 超时兜底）→ 三个评估器打分 → 上报 experiments。

## 二、三个评估器的实现

### ① citation_valid 引用有效性（纯代码，零 LLM 成本）

- 口径：结论里的 `[事实N]` 标记必须真实存在且不越界——`max(引用编号) <= 事实卡数`。防"挂着引用说瞎话"。
- 无事实卡分支：**不许出现任何 `[事实N]`**（防凭空挂引用）。此时降级为防幻觉弱校验，区分度低但不算失效。
- 事实卡不只来自知识库：图谱事实、台账统计、工具产出都算——这些场景照常严格校验。
- 已知局限：只校验 `[事实N]` 不校验 `[素材N]`——纯素材场景（Retriever 未命中、只有素材卡）区分度低，几乎白送分。改进方向：target outputs 带上素材卡数量，扩成"有事实卡查事实引用、无事实卡有素材卡查素材引用"双分支。

### ② factuality 事实一致性（OpenEvals 工厂 + 自写 Prompt）

- 代码：`build_openevals_judge()` → `create_async_llm_as_judge(prompt=FACTUALITY_PROMPT, judge=..., feedback_key="factuality", use_reasoning=True)`。
- 依赖：测试集的 `reference` 参考答案。**与知识库无关**——KB 只影响答得好不好，不影响能不能判；纯工具/纯数据任务照样能判。
- 回退：未装 openevals 或 LLM 未配置 → 本地手写 judge（同一容错口径的精简版），保证脚本随时能跑。
- 踩坑：judge LLM 的结构化输出必须**锁 json_mode**——OpenAI 严格 json_schema 模式在 GLM/DeepSeek 兼容端点会退化成自由文本，JsonOutputParser 直接抛错。解法：子类覆写 `with_structured_output` 把 method 锁成 json_mode（已验证端点支持）。
- 判分结果带 `reasoning`（一句话理由），写进 feedback comment，UI 里逐条可查、可人工复核。

### ③ trajectory_valid 轨迹符合度（Agentevals + 自写 Prompt）

- 代码：`build_trajectory_judge()` → agentevals 的 `create_async_trajectory_llm_as_judge`。**OpenEvals 没有轨迹评估，轨迹在兄弟库 Agentevals**——所以 11 个内置 Prompt 里根本找不到对应物。
- 输入构造：把引擎事件流映射成 OpenAI messages 形态的轨迹——user=用户任务；assistant 的 tool_call=节点启动（工具名=节点名，goal=子任务目标）；tool=该节点产出摘要；最后一条 assistant=交付结论。
- 判四条：子任务分解覆盖要点无缺失重复 / 节点顺序符合「规划→并行取证→评审→合成」/ 关键节点失败时后续仍正常收敛 / 无空转（节点无产出却照常合成）或跳步。
- 护栏：轨迹 <3 条消息（只有 user+结论，说明节点没跑起来）直接判异常 0 分；agentevals 未装自动跳过不阻断。

## 三、为什么用自写 Prompt 而不是内置的（核心追问点）

OpenEvals 内置 11 个 Prompt：CORRECTNESS（正确性）/ CONCISENESS（简洁性）/ ANSWER_RELEVANCE（相关性）/ RAG_HELPFULNESS / RAG_GROUNDEDNESS / RAG_RETRIEVAL_RELEVANCE / TOXICITY（毒性）/ HALLUCINATION（幻觉）/ CODE_CORRECTNESS×2 / PLAN_ADHERENCE（计划遵循度）——全部是**英文通用泛化口径**。

与我的三个评估器对照：factuality 的"近亲"是 CORRECTNESS_PROMPT（同为对照参考答案判对错）；trajectory 在 OpenEvals 里没有对应物；citation 是纯代码与库无关。

**不用内置的三个理由**：
1. **领域**：我的 FACTUALITY_PROMPT 是"航空运行领域的评分裁判"中文人设；内置是英文泛化口径，不懂领域判分轻重。
2. **容错口径**：自写版明确三条——"允许表述不同，不允许事实相悖"；"参考答案未覆盖的内容，只要不冲突不算相悖"；"允许同义重组与措辞差异，按语义重合判断而非字面重合"。第三条直接针对回归暴露的真实误伤：开放归纳题答案做了同义重组，内置口径按字面重合判就会误判"不一致"。
3. **评估理念**：判分口径就是评估质量的核心——口径错了评估会系统性误判，**评估不准比不评更糟**（错误分数会误导优化方向）。

面试一句话：OpenEvals 提供的是 judge 工厂 + 通用内置 Prompt；我用它的工厂、Prompt 换成领域定制版。
想用内置的场景：HALLUCINATION_PROMPT（无参考答案时测幻觉）适合当第四个评估器补充进来。

## 四、五个指标与 30 条回归结果

| 指标 | 中文 | 得分 | 口径 |
|---|---|---|---|
| citation_valid | 引用有效性 | 0.67（20/30） | 纯代码校验引用真实性 |
| factuality | 事实一致性 | 0.67（20/30） | LLM judge 对照参考答案 |
| trajectory_valid | 轨迹符合度 | 1.00（30/30） | LLM judge 评执行过程 |
| latency | 延迟 | P50 64s / P99 106s | 30 条耗时分位 |
| error | 错误率 | 0% | 超时/异常占比（早期半截轮曾 22%） |

定位：**第一次全量基线**。意义不在绝对分，在建立回归基准——之后每次改代码重跑一轮看涨跌。

## 五、结果分析（对应追问展开）

① **编排零回归**：trajectory 满分 + error 0%。包括 4 个检索器全未命中的逆境样本——靠台账/图谱兜底照样收敛、结论如实标注证据局限，说明过程护栏可靠。
② **citation 丢分全是"没写引用"不是"引错了"**：事实卡取回来了但结论偶尔不带 `[事实N]` 标记——纯输出格式不稳定，加硬约束 + 无引用自动重试即可修，是确定性收益。
③ **factuality 丢分三类**：约半数是"牵头部门"类细节相悖（Critic 没拦住）；约 1/3 是语料缺失、结论如实说"素材未呈现"——过程对、结果不足，瓶颈在语料覆盖不在编排；少数是开放归纳题自由发挥偏离参考。

**亮点（评估体系价值的实证）**：30 条 Critic 内审全部"0 存疑→可放行"，外部 judge 却拦下 10 条事实不一致——内审会放水，外审必须独立。这正是做评估的意义。

## 六、追问预备

- **LLM judge 可靠吗**：判分带 reasoning 逐条可读、可人工复核；已知缺陷是开放归纳题误伤（已在自写 Prompt 里加"允许同义重组"缓解），仍误伤的测试集要么补参考答案要么换口径。judge 也是 LLM 会犯错——所以能用确定性校验的地方（citation）不用 LLM。
- **怎么跑的**：eval 脚本读数据集 → 逐条起真实团队任务（并发 2、单条 300s 超时，超时记 error 整轮继续）→ 三评估器打分 → 上报 experiments。引擎单条跑批前会预热嵌入模型（避免并发时本地模型重复加载）。
- **打分粒度**：打在整条流水线的 root run 上，**不按单个 agent 打分**——结论是团队合写的，拆开打会失真；各 agent 是 run 树里的子节点，供下钻归因。LangSmith 支持对 child run 挂 feedback，但没做。
- **没接知识库的任务怎么算**：factuality 不依赖知识库（比对参考答案）；citation_valid 无事实卡时降级为"不许出现引用"的防幻觉弱校验；素材引用 `[素材N]` 目前是盲区（改进方向见①）。
- **成本**：每次引擎运行 10~50 条 trace，30 条一轮数千 traces（免费计划 5k/月）——调试期用 `--limit N` 控规模；生产/内网可换 Langfuse 自建。
- **下一步**：citation 输出格式硬约束 + 无引用自动重试（确定性收益最大）；factuality 牵头部门类细节让 Critic 加核对清单；纯素材场景扩 citation 双分支。

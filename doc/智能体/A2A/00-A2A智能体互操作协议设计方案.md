## 1. A2A 是什么：协议要点与 MCP 的分工

### 1.1 协议要点（v0.3.x，Linux Foundation）

A2A 由 Google 2025-04 开源、后捐入 Linux Foundation 的**智能体间互操作协议**，
解决「不同框架/不同厂商/不同信任域的 Agent 如何互相派活」。核心对象四个：

| 对象 | 说明 |
|---|---|
| **AgentCard** | 智能体公开名片：`GET /.well-known/agent-card.json`（v0.2 路径为 `agent.json`）。含 `name / description / url / capabilities{streaming 等} / defaultInputModes / defaultOutputModes / skills[{id,name,description,tags,examples}] / securitySchemes`，用于服务发现 |
| **Message** | `{role: user\|agent, parts: [Part], messageId, contextId}`；Part 三种：TextPart / FilePart / DataPart（结构化 JSON） |
| **Task** | 任务单元：`{id, contextId, status:{state}, artifacts[], history}`；状态机 `submitted → working → (input-required) → completed / failed / canceled`（0.3 增 rejected / auth-required） |
| **Artifact** | 任务产出物：`{artifactId, name, parts[]}`，A2A 的核心交付形态——**对端只交付结果，不暴露过程** |

传输：HTTP(S) + JSON-RPC 2.0。方法 `message/send`（同步）、`message/stream`（SSE：TaskStatusUpdateEvent / TaskArtifactUpdateEvent）、`tasks/get`、`tasks/cancel`。鉴权走标准 HTTP 头（API Key / OAuth / Bearer）。Python 官方 SDK 为 `a2a-sdk`（DefaultRequestHandler + AgentExecutor + A2AStarletteApplication）。

### 1.2 与 MCP 的分工：互补，不替代

| | MCP（已落地） | A2A（本方案） |
|---|---|---|
| 方向 | **纵向**：Agent ↔ 工具/资源 | **横向**：Agent ↔ Agent |
| 粒度 | 工具粒度：`kb_search(query=...)`，参数由 LLM 填 | 任务粒度：「查一下 CA1503 的乘客名单」→ 回一份工件报告 |
| 共享面 | 暴露原子能力（函数签名） | **不透明协作**：只传任务与结果，不共享记忆/提示词/工具/数据源 |
| 本平台落点 | `tool_registry.py` + `scripts/mcp_server.py` | `a2a_client.py` + `scripts/a2a_server.py`（本方案） |
| 形象说法 | 给 Agent 发「工具箱」 | 给 Agent 发「同事通讯录」 |

**一句话辨析（高频追问）**：MCP 回答「Agent 能调用哪些操作」，A2A 回答「Agent 能把活委派给谁」；本平台 ToolAgent 的 LLM 自主工具循环属于前者，跨平台组队协作属于后者，同一平台上两者并存。

### 1.3 本平台边界原则

**进程内 LangGraph 协作不动**。多智能体引擎的共享黑板（facts 编号体系、critic 裁定、并行 superstep）是同进程同信任域的高效形态，A2A 不替换它；A2A 只负责**跨进程 / 跨网络 / 跨信任域**的那一段（对应 §2 场景 1 的 `a2a_agent` 节点与场景 2 的对外服务端）。

## 2. 能用在哪：五个落点

| # | 场景 | 现状缺口 | A2A 怎么补 |
|---|---|---|---|
| 1 | **组队面板新增「远程智能体」成员** | 团队成员只能是本进程内置角色（retriever/data/graph/tool_agent）或配置页智能体（custom） | universal 场景新增角色 `a2a_agent`：节点内 `message/send` 委派远端智能体，artifact 转事实卡入黑板（§6.4） |
| 2 | **平台能力以「智能体」粒度对外** | `mcp_server.py` 只有工具粒度输出，外部宿主要自己编排多工具调用才能完成一件事 | `a2a_server.py` 以任务粒度输出：外部发一句任务，平台直接回工件报告（§7） |
| 3 | **跨部门数据不出域协作** | 数据源注册表（`data_sources`）是 DSN 直连——把库「拉进来」，跨部门给不出 DSN 也给不了 | 把**问题**交出去、把**结论**拿回来：远端部门自持数据与智能体，只回 artifact，DSN/原始数据不跨越信任边界 |
| 4 | **算力分工** | 重任务与轻任务同进程争抢同一批模型（0.6B 路由 + 9B 主模型） | 本地保留 0.6B 轻判定/路由，远端 AgentCard 声明重模型技能，重子任务（深度分析/长文生成）委派远端 |
| 5 | **接入外部 A2A 生态** | 外部 A2A 平台无法把本平台当成员组队；MCP 只能被 Claude/Cursor 类工具型宿主消费 | 标准-AgentCard 即插即用，被任何 A2A 客户端/平台发现与调用（场景 2 的对外面） |

优先级判断：**场景 1 是主菜**（直接增强既有组队体验，且可自产自销闭环验证）；场景 2/5 一套服务端同时满足；场景 3 是架构叙事亮点（对照数据源管理三层分工）；场景 4 顺带成立。

## 3. 总体架构

```
        本平台（进程内 LangGraph 协作，共享黑板 —— 保持不动）
┌──────────────────────────────────────────────────────────────────┐
│ Planner ─► [ retriever │ data_agent │ graph_agent │ tool_agent    │
│              │ a2a_agent（新增） ] 同 superstep ─► critic ─► syn.  │
│                                  │                               │
│        a2a_client.py（A2A 客户端，仿 McpConnection 逐台降级）       │
└──────────────────────────────────┼───────────────────────────────┘
              message/send │ message/stream(SSE)、tasks/get
┌──────────────────────────────────▼───────────────────────────────┐
│ 远端 A2A Server（另一部门平台 / 另一进程 / a2a-sdk 示例）            │
│  /.well-known/agent-card.json ── AgentCard（skills=能力清单）      │
│  message/send ──► 远端智能体执行 ──► Task{status, artifacts}       │
└──────────────────────────────────────────────────────────────────┘

        本平台作为 A2A Server（P1，对标 scripts/mcp_server.py）
┌──────────────────────────────────────────────────────────────────┐
│ scripts/a2a_server.py（独立端口 9801，复用 BearerMiddleware）       │
│  AgentCard.skills = kb_search / graph_search / data_query         │
│                   + 配置页启用智能体（skill id = agent:<id>）       │
│  message/send → 内置 handler（与 MCP 同源）/ assistant / 引擎       │
└──────────────────────────────────────────────────────────────────┘
```

## 4. 数据模型：`a2a_agents` 表（仿 `mcp_servers`）

`models.A2aAgent`，增量迁移 `migration_046`（CREATE TABLE，时间常量跨 PG/sqlite 方言）：

| 字段 | 说明 |
|---|---|
| id | hex12 主键 |
| name | 唯一，`[a-zA-Z0-9_-]{1,32}`，事实卡来源标识 `a2a_<name>` 前缀防撞 |
| base_url | String(500)，`http(s)://host:port`，AgentCard 拉取与 JSON-RPC 根 |
| auth_token | String(300)，Bearer 令牌，**明文落库但接口永不回传**（对齐数据源 password 口径） |
| enabled | 停用 = 组队面板不可选 + 巡检跳过（对齐 MCP「库为准，停用即切断」语义） |
| card_json | Text，最近一次成功拉取的 AgentCard 缓存（前端 skills 展示、节点选技能用） |
| description / sort_order / created_at / updated_at | 同 `mcp_servers` |

## 5. 服务层：`a2a_store.py` + `a2a_client.py`

### 5.1 `a2a_store.py`（仿 `mcp_store.py`，纯 CRUD + 校验）

- `validate_agent(data) -> list[str]`：name 正则、base_url 必须 http(s):// 开头（SSRF 基线：拒绝 file 等协议）、token 可空。
- `list_agents(db)` / `load_enabled_agents(db)` / `create` / `update` / `delete`——与 MCP 注册中心同构；序列化时 token 掩码（只回 `是否已配置`）。

### 5.2 `a2a_client.py`（错误永远是数据，不抛异常——工具循环同款哲学）

```
fetch_agent_card(base_url, token, timeout) -> {ok, card, error, elapsed_ms}
    先 GET /.well-known/agent-card.json，404 回落 /.well-known/agent.json（版本漂移兜底）
send_task(agent, text, skill_id=None, timeout) -> {ok, state, artifacts, text, task_id, error, elapsed_ms}
    POST {base_url}/ JSON-RPC message/send，Headers: Authorization: Bearer <token>
stream_task(...) -> async generator：message/stream SSE → yield 状态帧/工件帧（P1）
```

- httpx 直连 JSON-RPC 薄实现为**默认路径**（协议面小，不引重依赖）；`a2a-sdk` 作为可选依赖，装了也不强制走（与 OTel「SDK 缺失自动降级」传统一致，requirements 注释登记）。
- 超时 `A2A_TIMEOUT`（默认 60s，远端智能体天然比单工具慢）；结果截断 `A2A_RESULT_MAX_CHARS`（默认 4000，对齐 `RESULT_MAX_CHARS`，防黑板爆炸）。

## 6. 客户端接入多智能体：新角色 `a2a_agent`

### 6.1 组队

- `OPTIONAL_AGENTS` 增 `a2a_agent`（远程智能体）——组队面板自动出现卡片；
- 手动勾选走既有 `pickAgents()` 统一出口；自动路由时 LLM 规划可按子任务特征选入（plan step `role="a2a_agent"` + `agent` 字段指定远端卡 id）。
- 多个远端卡 = 多个 `a2a_agent` 节点并行（`PARALLEL_ROLES` 增 `a2a_agent`，与其它取证成员同 superstep）。

### 6.2 节点逻辑（`universal.py` 新增 `_make_a2a_agent`）

```
1 LLM 依据子任务+黑板上下文产出「委派指令」（一句话子任务文本；
  从该卡 card_json 缓存的 skills 里挑一个 skill_id，一并写入 message.metadata）
2 a2a_client.send_task(...)（远端卡 capabilities.streaming=false 时只能 message/send）
3 事件映射（下表）
4 artifacts 逐个转事实卡：grade=a2a_result，extra 记录来源 name/base_url/task_id/skill
5 node_done 摘要：「A2A 委派 flights-pro：1 个任务，产出 2 张工件事实卡，耗时 3.2s」
```

### 6.3 A2A 状态 ↔ 平台机制映射（设计的「对榫」关键）

| A2A 状态/事件 | 平台既有机制 | 说明 |
|---|---|---|
| `working` + SSE 过程 | emit `node` 过程帧 / `token`（P1 流式） | 远端进度流式可见 |
| `input-required` | **clarify 澄清链路**（`{type:'clarify'}` 事件） | 协议状态与平台澄清语义天然同构：P0 先降级记 warning，P1 直通前端澄清卡 |
| `completed` + artifacts | 事实卡（`grade=a2a_result`） | 入黑板 facts 编号体系，Synthesizer 可 `[事实N]` 引用，Critic 可统计 |
| `failed` / 超时 / 连不上 | emit `error` 帧，**节点失败不阻断全图**（对齐 MCP 逐台降级） | 其余并行成员照常 |
| `tasks/get` 轮询 | **Checkpointer 断点恢复**理念同源 | P2：长任务挂起→平台侧 resume 时续查 |

### 6.4 事实卡可信度

不透明协作意味着拿不到远端过程证据。对策：`a2a_result` 单独 grade + 前端素材卡标注来源智能体与 URL，Critic 素材统计分列展示——**来源可见，质量自担**，不在协议层假装可信。

## 7. 服务端：`scripts/a2a_server.py`（P1，对标 `mcp_server.py`）

### 7.1 AgentCard

```json
{
  "protocolVersion": "0.3.0",
  "name": "knowsource-agents",
  "description": "知识本体平台智能体服务（知识检索/图谱核验/台账查询/自定义智能体）",
  "url": "http://127.0.0.1:9801/",
  "capabilities": {"streaming": true, "stateTransitionHistory": false},
  "defaultInputModes": ["text/plain"],
  "defaultOutputModes": ["text/plain", "application/json"],
  "skills": [
    {"id": "kb_search",     "name": "知识库检索",   "tags": ["kb", "rag"]},
    {"id": "graph_search",  "name": "图谱核验",     "tags": ["graph"]},
    {"id": "data_query",    "name": "台账数据查询", "tags": ["data", "nl2sql"]},
    {"id": "agent:agent_xx", "name": "<配置页智能体名>", "tags": ["custom"]}
  ]
}
```

- 内置三技能与 MCP 暴露**同一批 handler**（tool_registry builtin，一处能力两种消费）；`agent:<id>` 技能把智能体配置页的条目（人设/技能/KB/工具白名单）直接上卡。
- `agent-card.json` 与 `agent.json` 两个路径同内容挂载（兼容两类客户端探测）。

### 7.2 JSON-RPC 端点

| 方法 | 行为 |
|---|---|
| `message/send` | 按 skill 路由：内置技能直接跑 handler；`agent:<id>` 走 assistant 单轮（`resolve` + `run_tool_loop`）。完成回 Task `completed` + artifacts（TextPart 摘要 + DataPart 结构化 facts） |
| `message/stream` | SSE：内部事件转 `TaskStatusUpdateEvent(working)` / `TaskArtifactUpdateEvent` → 收尾 `completed`；澄清链路命中回 `input-required` |
| `tasks/get` / `tasks/cancel` | 内存任务表兜底实现（P0/P1 够用；P2 落 agent_runs 对齐 checkpointer） |

鉴权：复用 `BearerMiddleware`（`A2A_EXPOSE_TOKEN`，默认关=不鉴权仅内网）。与 `mcp_server.py`（9800，工具粒度）并存互补，不互相替代。

## 10. 分期实施与验证

### 10.1 分期

| 期 | 内容 | 验收口径 |

### 10.2 P0 冒烟清单（8 项）

1. 迁移：`a2a_agents` 建表，重跑幂等；
2. `test` 端点：正常卡 ok:true / 404 回落 agent.json / 超时 ok:false（均 200 不 500）；
3. 注册 `http://127.0.0.1:9801` → 卡片缓存 skills=3 内置技能；
4. 组队勾选远程成员 → 委派「知识库有哪些机务相关文档」→ 产出 `grade=a2a_result` 事实卡，Synthesizer 引用；
5. 停用远端卡 → 面板不可选；运行中不可达 → 该节点 error 帧不阻断全图；
6. 大结果截断（造 >4000 字符 artifact）；
7. 鉴权：服务端设 token 后无 token 401 → 客户端 ok:false；
8. 协作会话留痕：a2a 节点过程与事实卡可回看。

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| 协议版本漂移（agent.json → agent-card.json；0.3 增 gRPC/REST 传输） | 客户端双路径探测 + 只用最稳定的 JSON-RPC over HTTP 子集；服务端双路径挂载 |
| SDK 依赖 | `a2a-sdk` 可选，默认 httpx 薄实现；requirements 注释登记不锁死 |
| 远端质量不可控 / 结果注入 | 事实卡独立 grade + 来源标注；结果截断；文本进黑板前不做指令执行（只作素材） |
| 安全 | token 明文落库接口永不回传（对齐 password 口径）；base_url 协议白名单；对外服务默认仅内网 + Bearer |
| 语义错位（期望工具却给了任务粒度） | 文档与前端文案明确「远程智能体 ≠ 外部工具」；ToolAgent（MCP）与 a2a_agent（A2A）在组队面板并列呈现，各自 tooltip 说明 |

## 12. 一句话总结

MCP 已让本平台「手上有工具」（tool_registry + 注册中心 + mcp_server 对外），A2A 补的是「通讯录里有同事」——**组队面板能勾选远端智能体当成员（artifact 转事实卡），平台自身也能被别的平台当智能体调用（AgentCard + 任务粒度技能）**；进程内 LangGraph 黑板协作、SSE 事件契约、澄清与断点恢复三条既有主干全部复用，A2A 只做跨边界那一段。

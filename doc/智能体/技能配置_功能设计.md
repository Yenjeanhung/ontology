## 0. 一句话目标

给智能体（OAG）增加「**技能（Skill）**」配置能力：技能是**可管理、可组合、可复用的提示词指令包**，用户在提问时按需勾选，智能体按技能指令调整回答的风格、格式与深度；**不勾选任何技能时，行为与现状完全一致（零回归）**。

---

## 1. 背景与目标

### 1.1 现状：智能体只有一个硬编码的"人格"

当前 OAG 智能体的行为完全由两段硬编码 prompt 决定（`oag_service.py`）：

```
OAG_SYSTEM_PROMPT   ← 固定的"基于知识库与知识图谱的智能体"人设 + 引用规范
OAG_USER_TEMPLATE   ← 图谱事实 + 参考资料 + 问题
```

带来的问题：

| 问题 | 表现 |
|------|------|
| 风格单一 | 回答永远是同一种"综合叙述"风格，无法切换"简洁/深度/表格"等模式 |
| 无法沉淀经验 | 用户调好的一套提问技巧（如"先给结论再给依据"）无法保存复用 |
| 场景割裂 | 财务分析、法律检索、技术调研对输出格式的要求不同，目前只能靠用户每次手写长问题来"凑" |
| 改行为要改代码 | 想微调智能体风格必须改 `OAG_SYSTEM_PROMPT` 重新部署 |

### 1.2 目标

1. **技能管理**：技能可创建、编辑、启用/禁用、删除（CRUD，参照 `llm_configs` 方案管理模式）
2. **按需组合**：提问时勾选若干技能，指令动态合并进 system prompt
3. **过程透明**：推理卡片展示本次生效的技能（延续 OAG"推理过程可视化"原则）
4. **零回归**：不勾选技能 = 现有行为，一行检索逻辑不改；`rag_service`（问答菜单）完全不动
5. **开箱即用**：内置若干预设技能（深度分析、表格输出、简洁模式等）

### 1.3 非目标（v1 明确不做）

- ❌ 工具型技能（Text2Cypher、联网搜索等可调用工具）→ v2，见 [§11](#11-v2-展望)
- ❌ 技能携带检索参数覆盖（如改 `OAG_TOP_N`、跳数）→ v2
- ❌ 知识库级技能绑定（`kb_agent_skill_bindings`）→ v2，v1 只有全局技能池
- ❌ 技能版本管理 / 审核流

## 2. 什么是技能（Skill）

### 2.1 定义

> **技能 = 一段有名字、有描述、可启停的 system prompt 指令增量**。

技术上就是"提示词片段的持久化 + 组合机制"，与 Claude Skills / 自定义指令 同一思想的最小落地。

### 2.2 与相近概念的区别

| | LLM 配置（llm_configs） | 本体（ontologies） | **技能（agent_skills，本设计）** |
|---|---|---|---|
| 管什么 | 用哪个模型、温度等**推理资源** | 写入侧**抽取约束** | 读取侧**回答行为** |
| 生效环节 | `create_llm()` | 图谱抽取 prompt | OAG system prompt |
| 生效范围 | 全局唯一生效（is_active） | 按 KB 绑定 | 每次查询按勾选组合，可多个叠加 |

### 2.3 技能字段

| 字段 | 说明 |
|------|------|
| `name` | 展示名，如「深度分析」 |
| `code` | 唯一编码（预设技能用固定 code 识别），如 `deep_analysis` |
| `description` | 一句话描述，显示在勾选 chips 的 title 里 |
| `instructions` | 指令正文（Markdown），运行时拼入 system prompt |
| `is_enabled` | 启用开关，禁用的技能不出现在选择列表 |
| `sort_order` | 排序，同时决定超预算时的截断优先级 |
| `is_preset` | 是否内置预设（预设技能不可改 code，可改内容，可禁用，不物理删除） |

### 2.4 内置预设技能（首发 4 个）

| code | 名称 | 指令要点 |
|------|------|---------|
| `deep_analysis` | 深度分析 | 先给结论，再分点论证；每个论点标注 [来源N]/[事实]；指出资料间的矛盾与缺口 |
| `table_output` | 表格输出 | 优先用 Markdown 表格整理对比类信息；表后附口头总结 |
| `concise` | 简洁模式 | 200 字以内直给答案，不铺陈过程 |
| `cite_strict` | 严格引用 | 每个结论必须至少一个引用标注；无法引用的推断要显式声明"推测" |

> 预设通过启动时 seed（存在则跳过）写入数据库，用户可自由编辑/禁用，也可新建自己的技能。

## 3. 总体架构

```
┌──────────────────────────── 前端 (Vue 3) ────────────────────────────┐
│  AgentView（改造）                                                    │
│   · 技能管理入口 → SkillManagerModal（新增：CRUD + 启停）              │
│   · 提问区「技能」多选 chips（默认全选已启用技能，可临时取消）          │
│   · 推理卡片显示「已加载技能」                                          │
└──────────────┬───────────────────────────────────────────────────────┘
               │ POST /api/agent/query  {kb_id, query, skill_ids:[...]}
               │ GET/POST/PUT/DELETE /api/agent/skills…
┌──────────────▼───────────── FastAPI ─────────────────────────────────┐
│  routers/agent.py（扩展：技能 CRUD 子资源）                            │
│  services/skill_service.py（新增）   services/oag_service.py（扩展）   │
│    · CRUD / seed 预设                · build_system_prompt(skills)    │
│    · resolve_skills(skill_ids)       · SSE 新增 {type:"skills"} 事件   │
└──────┬──────────────────────────────────────────┬────────────────────┘
       │ SQLite (aiosqlite)                        │ 组装后的 prompt
┌──────▼──────────────┐              ┌────────────▼─────────────────────┐
│  agent_skills 表(新) │              │ OAG 7 步管线（检索逻辑零改动）      │
│  + models.AgentSkill│              │ 仅第 ⑦ 步 SystemMessage 换成组装值  │
└─────────────────────┘              └───────────────────────────────────┘
```

**设计原则**（延续 OAG 设计）：

1. 检索管线（向量召回/实体链接/RRF 融合）**一行不改**，技能只影响第 ⑦ 步的 system prompt；
2. 降级路径 `_stream_vector_only` 同样应用技能，保证行为一致；
3. 技能解析在**路由层同步完成**（db 会话在 SSE 开始前释放，与 ontology_schema 预加载同一模式）。

## 4. 数据模型

### 4.1 新增表 `agent_skills`

```sql
CREATE TABLE IF NOT EXISTS agent_skills (
    id           VARCHAR PRIMARY KEY,
    name         VARCHAR NOT NULL,
    code         VARCHAR NOT NULL,            -- 唯一，预设技能的固定标识
    description  VARCHAR DEFAULT '',
    instructions TEXT NOT NULL DEFAULT '',    -- 指令正文（Markdown）
    is_enabled   INTEGER NOT NULL DEFAULT 1,
    is_preset    INTEGER NOT NULL DEFAULT 0,
    sort_order   INTEGER NOT NULL DEFAULT 0,
    created_at   VARCHAR,
    updated_at   VARCHAR
);
CREATE UNIQUE INDEX IF NOT EXISTS idx_agent_skills_code ON agent_skills(code);
```

同步改动：`backend/sql/schema.sql`（建表）、`backend/sql/migrations.sql`（增量）、`backend/models.py`（`AgentSkill` 模型，参照 `LLMConfig` 写法）。

### 4.2 请求模型扩展

```python
class AgentQueryRequest(BaseModel):
    query: str
    kb_id: str
    skill_ids: list[str] = []   # 新增：勾选的技能 id；空 = 不加载任何技能
```

> **默认值语义**：`[]` 表示"本次不使用技能"（由前端负责默认勾选全部启用技能）；后端不做隐式默认，保证 API 行为可预期、可测试。

## 5. 后端设计

### 5.1 API 一览（挂载于 `/api` 前缀，放在 `routers/agent.py`）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/agent/skills` | 列表（全部，含禁用；管理界面用） |
| POST | `/api/agent/skills` | 创建（校验 code 唯一、非空） |
| PUT | `/api/agent/skills/{id}` | 更新（预设技能禁止改 code） |
| DELETE | `/api/agent/skills/{id}` | 删除（预设技能返回 400，只能禁用） |
| POST | `/api/agent/skills/seed` | 手动触发 seed 预设（幂等，存在即跳过） |

列表返回按 `sort_order, created_at` 排序；前端提问区只展示 `is_enabled=1` 的子集。

### 5.2 SkillService（`services/skill_service.py`，新增）

```python
class SkillService:
    @staticmethod
    async def list(db) -> list[dict]: ...
    @staticmethod
    async def create(db, data) -> dict: ...
    @staticmethod
    async def update(db, skill_id, data) -> dict | None: ...
    @staticmethod
    async def delete(db, skill_id) -> bool: ...
    @staticmethod
    async def seed_presets(db) -> int:           # 启动 + 手动触发，返回新建数
    @staticmethod
    async def resolve(db, skill_ids) -> list[dict]:
        """按 id 批量取启用中的技能；id 不存在/已禁用的静默跳过（容错）。"""
```

- `seed_presets` 在 `server.py` 启动事件中调用（try/except 包裹，失败仅告警不阻断启动）；
- id 使用 `uuid4().hex[:12]`，与项目其他表一致。

### 5.3 Prompt 组装（`oag_service.py` 扩展）

新增纯函数，便于单测：

```python
SKILL_CHAR_BUDGET = 4000   # 技能指令总字符软上限（config.py 可配）

def build_system_prompt(skills: list[dict]) -> str:
    """OAG_SYSTEM_PROMPT + 技能指令块；无技能时原样返回基础 prompt。"""
```

组装格式：

```
{OAG_SYSTEM_PROMPT 原文，不变}

【已启用技能】（以下指令由配置注入，不得违反上述引用规范）
### 技能：深度分析
{instructions}
### 技能：表格输出
{instructions}
```

规则：

1. **顺序**：按 `sort_order` 升序拼接；超预算时从尾部截断 + 日志 warning + SSE 事件中标记 `truncated: true`；
2. **优先级声明**：技能块头部固定加"不得违反上述引用规范"一句话，防止技能指令覆盖 `[来源N]`/`[事实]` 标注体系；
3. **去重**：同 id 只拼一次（前端可能重复传）；
4. `query_stream` / `_stream_vector_only` 两条路径统一走 `build_system_prompt`。

### 5.4 查询流程改造（`routers/agent.py`）

```python
@router.post("/agent/query")
async def agent_query(req: AgentQueryRequest, db=Depends(get_db)):
    kb = ...                                   # 不变
    ontology_schema = ...                      # 不变（预加载模式）
    skills = await SkillService.resolve(db, req.skill_ids)   # 新增：预加载
    return StreamingResponse(
        OAGService.query_stream(req.kb_id, req.query, kb["name"], ontology_schema, skills),
        ...
    )
```

### 5.5 SSE 事件扩展

在现有 `entities` 事件**之前**新增一个事件（推理链第一步）：

```json
data: {"type": "skills", "skills": [{"id": "...", "name": "深度分析", "code": "deep_analysis"}], "truncated": false}
```

`_stream_vector_only` 降级路径同样下发（skills 可能为空数组，前端不渲染该块即可）。

## 7. 一次查询的完整时序

```
用户（勾选 2 个技能，提问）
 │ POST /api/agent/query {kb_id, query, skill_ids:[a,b]}
 ▼
路由层：校验 KB → 预加载 ontology_schema → SkillService.resolve(skill_ids)
 │（db 会话到此为止，SSE 不再持有）
 ▼
OAGService.query_stream(..., skills)
 │ ① 总开关/降级判断（不变）
 │ ② 向量召回（不变） ③ 实体链接（不变） ④ 图谱召回（不变）
 │ ⑤ RRF 融合（不变）
 │ ⑥ SSE: skills → entities → subgraph → chunks（新增 skills 事件）
 │ ⑦ build_system_prompt(skills) → LLM 流式 token → [DONE]
 ▼
前端：推理卡片渲染「已加载技能」→ 回答
```

## 8. 边界与安全

| 场景 | 行为 |
|------|------|
| `skill_ids` 含不存在/已禁用 id | 静默跳过，查询不失败 |
| 全部技能被禁用 / 未勾选 | 等价现状，prompt 无技能块 |
| 技能指令总长超 4000 字符 | 按 sort_order 截断，SSE 标记 `truncated`，日志告警 |
| 技能指令试图覆盖引用规范 | 基础 prompt 在前 + 技能块固定声明"不得违反"，双保险 |
| instructions 为空 | 允许保存（占位草稿），但 resolve 时过滤掉空指令技能 |
| 删除正在被勾选的技能 | 前端保存后同步移除勾选；后端 resolve 天然容错 |
| 降级路径（OAG 关闭/无图谱） | 技能照常生效（只影响 prompt，与检索无关） |

> 提示词注入面评估：技能由本机用户自己配置，属可信输入；唯一外部输入是 KB 文档内容，现状已是"参考资料"隔离，本设计不扩大注入面。

## 10. 测试要点

1. **组装单测**：无技能 = 原文；1 个/多个技能拼接格式；超预算截断顺序；重复 id 去重；空 instructions 过滤
2. **resolve 容错**：不存在 id / 禁用 id / 空 `skill_ids`
3. **CRUD**：code 唯一冲突 409、预设禁删 400、预设禁改 code
4. **seed 幂等**：连跑两次，第二次新增数为 0
5. **端到端**：勾选「表格输出」提问，回答应含 Markdown 表格；SSE 首事件为 `skills`；降级路径同样下发 `skills`
6. **回归**：不带 `skill_ids` 的旧调用（curl 直调）行为与线上完全一致

## 11. 已实现补充：技能导入导出（2026-08-17）

### 11.1 功能概述

支持技能的跨实例共享与在线安装：

- **导出 JSON**：一键将全部技能导出为标准 JSON 文件（ZIP 包技能附带 files 字段）
- **导入文件**：从本地 `.json` 文件批量导入技能，或导入 `.zip` **完整技能包**（SKILL.md + scripts/references/data 配套文件）
- **从 URL 导入**：JSON / SKILL.md / ZIP 文件直链 / GitHub 仓库地址（自动拉取整仓库 zipball）/ SkillsMP 页面
- **格式兼容**：自动识别 `{skills:[...]}` 包裹格式、纯数组格式、单个技能对象格式、skill.json 松散字段
- **重复决策**：导入的 code 与已有技能重复时弹窗，用户选「覆盖更新」（保留启用状态与预设标记）或「跳过重复项」

### 11.2 技能 JSON 标准格式

```json
{
  "skills": [
    {
      "name": "深度分析",
      "code": "deep_analysis",
      "description": "先给结论再分点论证...",
      "instructions": "回答时先直接给出结论...",
      "sort_order": 10
    }
  ]
}
```

也支持直接传入单个技能对象 `{name, code, ...}` 或纯数组 `[{...}, ...]`。

### 11.3 API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/agent/skills/export` | 导出全部技能（无 id/时间戳；ZIP 包技能含 files） |
| POST | `/api/agent/skills/import` | 从 JSON 数组导入（body 可带 `overwrite`） |
| POST | `/api/agent/skills/import-url` | JSON / SKILL.md / ZIP 直链 / GitHub 仓库 / SkillsMP（body 可带 `overwrite`） |
| POST | `/api/agent/skills/import-zip` | 上传 ZIP 技能包（query 可带 `?overwrite=true`） |

导入结果返回 `{imported, updated, skipped, errors, duplicates, details}`；`duplicates` 为重复编码列表 `[{code, name, existing_name}]`，是前端「覆盖/跳过」弹窗的数据源。

### 11.4 接入在线技能源

由于技能本质上就是结构化 JSON，任何能托管 JSON 的平台都可以作为「技能源」：

| 平台 | 接入方式 | 说明 |
|------|---------|------|
| **GitHub** | Raw URL（`raw.githubusercontent.com/...`） | 任何人可 fork/PR 贡献技能到社区仓库 |
| **GitHub Gist** | Gist Raw URL | 个人快速分享技能 |
| **HuggingFace** | Hub 文件下载 URL | 可建立 `knowsource-skills` 社区数据集 |
| **自建 HTTP** | 任意返回 JSON 的 URL | 企业内部技能分发 |

> **v1 实现的是「通用 URL 导入」**——后端做 httpx 代理请求 + 格式兼容解析，前端只提供 URL 输入框。
> 不绑定任何特定平台，因此**天然支持所有返回 JSON 的在线源**。

### 11.5 完整技能 ZIP 包导入（2026-08-17）

支持导入技能市场（SkillsMP / Claude Code 生态）的完整 ZIP 技能包：`SKILL.md`（YAML frontmatter: name/description + 正文指令）+ `scripts/ references/ data/` 等配套文件。

**配套文件存储（v1.2 起为磁盘存储）**：`agent_skills` 的 `files TEXT` 列（migration_008）只存**清单**，文件本体解压到磁盘目录（`file_dir` 列指向，如 `./data/skills/demo-a`，根目录由 `SKILL_FILES_DIR` 配置，migration_009 加列）：

```json
[{"path": "scripts/run.py", "size": 1180, "is_text": true},
 {"path": "assets/logo.png", "size": 8321, "is_text": false}]
```

- path 为相对技能根的 POSIX 路径（含 SKILL.md 自身）；
- 目录名由 code 派生（非法字符归一为 `_`），覆盖导入先清空目录再重解压；删除技能时目录一并清理；
- **存量数据迁移**：server.py 启动时 `sync_skill_files_to_disk(db)` 把旧版本存在 files 列里的 content 迁到磁盘并剥离（幂等，失败不阻断启动）；
- 前端技能卡片显示「📦 N 文件」标签，编辑面板提供只读文件列表 + 解压路径提示（智能体可按路径引用）。

**instructions 资源清单**：导入时在 SKILL.md 正文末尾自动附加哨兵标签包裹的清单块，运行时智能体可知晓配套资源；覆盖导入时先剥旧清单再重生成，保证幂等：

```
<skill-resources>
本技能的配套资源文件已解压至 ./data/skills/demo-a/（相对后端运行目录），智能体可按路径引用：
- scripts/run.py (1.2 KB)
- assets/logo.png (8.1 KB)
</skill-resources>
```

**技能根识别**：剥掉 GitHub zipball 的 `owner-repo-branch/` 唯一顶层壳 → 根级 `SKILL.md` = 单技能包；每个含 `SKILL.md` 的顶层目录各成一技能（多技能包）；无 SKILL.md 时退 `skill.json` → `CLAUDE.md`/`instructions.md` 兼容。frontmatter 手写 mini-YAML 解析（支持单行/引号值、`|`/`>` 块标量多行 description、零缩进续行），正文原样作为 instructions。

**安全上限**（config.py，.env 可覆盖）：上传 20MB / 解压总量 100MB（解压前按 ZipInfo 预检，zip bomb 主防线）/ 条目 200 / 单文件压缩比 100；JSON 导出回流嵌入文本单文件 64KB、单技能总量 256KB（磁盘存储后仅约束导出回流体积）；清单最多 30 行。路径穿越（绝对路径 / `..`）整包拒收（磁盘解压同样走 `_clean_relpath` 清洗）；`__MACOSX/.DS_Store/.git` 过滤。

**重复覆盖两阶段交互**：phase-1 `overwrite=false`（重复项进 `duplicates` 返回，非重复项正常导入）→ 前端弹窗 → 用户选「覆盖更新」则重发全量源 `overwrite=true`（phase-1 已导入项做幂等 update，保留 id / is_enabled / is_preset；sort_order 仅在导入项非 0 时覆盖），或「跳过重复项」以 phase-1 为终态。覆盖命中预设技能时只更新内容，预设位与开关保留。

**GitHub 仓库导入瀑布**：codeload 整仓 zipball（main → master，拿完整技能包）→ 退回 raw 单文件逐试（skill.json / SKILL.md / CLAUDE.md / .claude/skills/SKILL.md）。

**预算调整**：`AGENT_SKILL_CHAR_BUDGET` 默认 4000 → **24000**（市场 SKILL.md 常见 8-15K + 清单）。注意：这是全部勾选技能 instructions 之和的软上限，已部署实例若 .env 显式设过旧值不受影响。另：导出含 files 的 JSON 体积会增大（单技能内容上限 256KB 兜底）。

### 11.6 技能分组 / ZIP 完整导出 / 预设可删除（2026-08-17，migration_009）

**技能分组**：技能保持全局（不做 KB 隔离，分组仅做组织），左侧分组树 + 右侧技能列表（前端三栏：分组树 / 技能列表 / 编辑面板）。

- 新表 `agent_skill_groups(id, name, parent_id, sort_order, created_at, updated_at)`：`parent_id NULL` = 根级，**任意嵌套**；无 DB 外键，service 层维护。
- `agent_skills.group_id` 挂组列（NULL = 未分组）。
- API（`routers/agent.py`）：
  - `GET /agent/skill-groups`：扁平列表 + 每组**直属**技能数（前端建树并累加子孙计数）
  - `POST /agent/skill-groups`：空名 400 / 父不存在 404 / **同级同名 409**
  - `PUT /agent/skill-groups/{id}`：改名查重（同级 + 排除自身）+ 父校验 + **环检测**（沿新父祖先链上行遇到自己 → 400「不能把分组移动到自己/其子分组名下」）；`parent_id` 键存在即生效，显式 null = 移到根级
  - `DELETE /agent/skill-groups/{id}`：**绝不删技能** —— 子分组上移一级（parent 指向被删组的 parent）、子树内技能 group_id 置 NULL（未分组），单事务；返回 `{ok, children_promoted, skills_ungrouped}`
- 技能 CRUD 的 create/update 接受 `group_id`（非空时校验存在）；update 显式传 null = 移到未分组。

**导入导出的分组规则**（三级优先级）：逐项 `group_path`（导出回流，`resolve_group_path` 逐级找或建，如 `写作/润色`）> 请求级 `group_id`（前端当前选中分组）> NULL（未分组）。overwrite 时仅当导入项自带 `group_path` 才移动已有技能分组（请求级 group_id 不动用户手动归类）。ZIP 包 SKILL.md frontmatter 可选透传 `group_path` / `sort_order` / `enabled`（'false'/'no'/'0' → 建档时禁用）。

**ZIP 完整导出**：`GET /agent/skills/export-zip` → `knowsource-skills-YYYYMMDD.zip`：

- 每技能一个顶层目录 `<code>/`，内含 `SKILL.md` + 全部配套文件（从 `file_dir` 磁盘回读，**二进制原样**；旧数据从 files 列 content 重建）；
- `SKILL.md` = YAML frontmatter（`name / description / code / sort_order / group_path / enabled`）+ 正文 = `strip_resource_manifest(instructions)`（资源清单块剥离）；
- 与自有导入器**自洽**（顶层目录含 SKILL.md → 多技能包识别，可直接再导入），亦是社区标准格式。

JSON 导出（`GET /agent/skills/export`）同步增强：带 `group_path`；文本文件内容从磁盘回读嵌入（受 64KB/256KB 上限约束），保证 JSON 回流可完整重建。

**预设技能可删除**：去掉 is_preset 删除保护；删除时写墓碑表 `agent_skill_seed_tombstones(code PK)`，`seed_presets()` 启动补种时跳过墓碑 code（防重启复活）。预设同时可禁用（既有 is_enabled 机制）。

**前端**：`SkillGroupTree.vue`（递归树，hover 操作 ＋ 建子组 / ✎ 改名移动 / 🗑 删除）；`SkillListPage.vue` 三栏重构 + 「导出 ZIP」按钮 + 导入栏「导入到：xxx」目标提示 + 导入刷新修复（phase-1 有实际导入即先刷新列表再弹重复决策窗；覆盖失败弹窗保持可重试；✕ 与「跳过重复项」统一走 close 出口）。

## 0. 一句话目标

给智能体（OAG）增加「**技能（Skill）**」配置能力：技能是**可管理、可组合、可复用的提示词指令包**，用户在提问时按需勾选，智能体按技能指令调整回答的风格、格式与深度；**不勾选任何技能时，行为与现状完全一致（零回归）**。

---

## 1. 背景与目标

### 1.1 现状：智能体只有一个硬编码的"人格"

当前 OAG 智能体的行为完全由两段硬编码 prompt 决定（`oag_service.py`）：

```
OAG_SYSTEM_PROMPT   ← 固定的"基于知识库与知识图谱的智能体"人设 + 引用规范
OAG_USER_TEMPLATE   ← 图谱事实 + 参考资料 + 问题
```

带来的问题：

| 问题 | 表现 |
|------|------|
| 风格单一 | 回答永远是同一种"综合叙述"风格，无法切换"简洁/深度/表格"等模式 |
| 无法沉淀经验 | 用户调好的一套提问技巧（如"先给结论再给依据"）无法保存复用 |
| 场景割裂 | 财务分析、法律检索、技术调研对输出格式的要求不同，目前只能靠用户每次手写长问题来"凑" |
| 改行为要改代码 | 想微调智能体风格必须改 `OAG_SYSTEM_PROMPT` 重新部署 |

### 1.2 目标

1. **技能管理**：技能可创建、编辑、启用/禁用、删除（CRUD，参照 `llm_configs` 方案管理模式）
2. **按需组合**：提问时勾选若干技能，指令动态合并进 system prompt
3. **过程透明**：推理卡片展示本次生效的技能（延续 OAG"推理过程可视化"原则）
4. **零回归**：不勾选技能 = 现有行为，一行检索逻辑不改；`rag_service`（问答菜单）完全不动
5. **开箱即用**：内置若干预设技能（深度分析、表格输出、简洁模式等）

### 1.3 非目标（v1 明确不做）

- ❌ 工具型技能（Text2Cypher、联网搜索等可调用工具）→ v2，见 [§11](#11-v2-展望)
- ❌ 技能携带检索参数覆盖（如改 `OAG_TOP_N`、跳数）→ v2
- ❌ 知识库级技能绑定（`kb_agent_skill_bindings`）→ v2，v1 只有全局技能池
- ❌ 技能版本管理 / 审核流

## 2. 什么是技能（Skill）

### 2.1 定义

> **技能 = 一段有名字、有描述、可启停的 system prompt 指令增量**。

技术上就是"提示词片段的持久化 + 组合机制"，与 Claude Skills / 自定义指令 同一思想的最小落地。

### 2.2 与相近概念的区别

| | LLM 配置（llm_configs） | 本体（ontologies） | **技能（agent_skills，本设计）** |
|---|---|---|---|
| 管什么 | 用哪个模型、温度等**推理资源** | 写入侧**抽取约束** | 读取侧**回答行为** |
| 生效环节 | `create_llm()` | 图谱抽取 prompt | OAG system prompt |
| 生效范围 | 全局唯一生效（is_active） | 按 KB 绑定 | 每次查询按勾选组合，可多个叠加 |

### 2.3 技能字段

| 字段 | 说明 |
|------|------|
| `name` | 展示名，如「深度分析」 |
| `code` | 唯一编码（预设技能用固定 code 识别），如 `deep_analysis` |
| `description` | 一句话描述，显示在勾选 chips 的 title 里 |
| `instructions` | 指令正文（Markdown），运行时拼入 system prompt |
| `is_enabled` | 启用开关，禁用的技能不出现在选择列表 |
| `sort_order` | 排序，同时决定超预算时的截断优先级 |
| `is_preset` | 是否内置预设（预设技能不可改 code，可改内容，可禁用，不物理删除） |

### 2.4 内置预设技能（首发 4 个）

| code | 名称 | 指令要点 |
|------|------|---------|
| `deep_analysis` | 深度分析 | 先给结论，再分点论证；每个论点标注 [来源N]/[事实]；指出资料间的矛盾与缺口 |
| `table_output` | 表格输出 | 优先用 Markdown 表格整理对比类信息；表后附口头总结 |
| `concise` | 简洁模式 | 200 字以内直给答案，不铺陈过程 |
| `cite_strict` | 严格引用 | 每个结论必须至少一个引用标注；无法引用的推断要显式声明"推测" |

> 预设通过启动时 seed（存在则跳过）写入数据库，用户可自由编辑/禁用，也可新建自己的技能。

## 3. 总体架构

```
┌──────────────────────────── 前端 (Vue 3) ────────────────────────────┐
│  AgentView（改造）                                                    │
│   · 技能管理入口 → SkillManagerModal（新增：CRUD + 启停）              │
│   · 提问区「技能」多选 chips（默认全选已启用技能，可临时取消）          │
│   · 推理卡片显示「已加载技能」                                          │
└──────────────┬───────────────────────────────────────────────────────┘
               │ POST /api/agent/query  {kb_id, query, skill_ids:[...]}
               │ GET/POST/PUT/DELETE /api/agent/skills…
┌──────────────▼───────────── FastAPI ─────────────────────────────────┐
│  routers/agent.py（扩展：技能 CRUD 子资源）                            │
│  services/skill_service.py（新增）   services/oag_service.py（扩展）   │
│    · CRUD / seed 预设                · build_system_prompt(skills)    │
│    · resolve_skills(skill_ids)       · SSE 新增 {type:"skills"} 事件   │
└──────┬──────────────────────────────────────────┬────────────────────┘
       │ SQLite (aiosqlite)                        │ 组装后的 prompt
┌──────▼──────────────┐              ┌────────────▼─────────────────────┐
│  agent_skills 表(新) │              │ OAG 7 步管线（检索逻辑零改动）      │
│  + models.AgentSkill│              │ 仅第 ⑦ 步 SystemMessage 换成组装值  │
└─────────────────────┘              └───────────────────────────────────┘
```

**设计原则**（延续 OAG 设计）：

1. 检索管线（向量召回/实体链接/RRF 融合）**一行不改**，技能只影响第 ⑦ 步的 system prompt；
2. 降级路径 `_stream_vector_only` 同样应用技能，保证行为一致；
3. 技能解析在**路由层同步完成**（db 会话在 SSE 开始前释放，与 ontology_schema 预加载同一模式）。

## 4. 数据模型

### 4.1 新增表 `agent_skills`

```sql
CREATE TABLE IF NOT EXISTS agent_skills (
    id           VARCHAR PRIMARY KEY,
    name         VARCHAR NOT NULL,
    code         VARCHAR NOT NULL,            -- 唯一，预设技能的固定标识
    description  VARCHAR DEFAULT '',
    instructions TEXT NOT NULL DEFAULT '',    -- 指令正文（Markdown）
    is_enabled   INTEGER NOT NULL DEFAULT 1,
    is_preset    INTEGER NOT NULL DEFAULT 0,
    sort_order   INTEGER NOT NULL DEFAULT 0,
    created_at   VARCHAR,
    updated_at   VARCHAR
);
CREATE UNIQUE INDEX IF NOT EXISTS idx_agent_skills_code ON agent_skills(code);
```

同步改动：`backend/sql/schema.sql`（建表）、`backend/sql/migrations.sql`（增量）、`backend/models.py`（`AgentSkill` 模型，参照 `LLMConfig` 写法）。

### 4.2 请求模型扩展

```python
class AgentQueryRequest(BaseModel):
    query: str
    kb_id: str
    skill_ids: list[str] = []   # 新增：勾选的技能 id；空 = 不加载任何技能
```

> **默认值语义**：`[]` 表示"本次不使用技能"（由前端负责默认勾选全部启用技能）；后端不做隐式默认，保证 API 行为可预期、可测试。

## 5. 后端设计

### 5.1 API 一览（挂载于 `/api` 前缀，放在 `routers/agent.py`）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/agent/skills` | 列表（全部，含禁用；管理界面用） |
| POST | `/api/agent/skills` | 创建（校验 code 唯一、非空） |
| PUT | `/api/agent/skills/{id}` | 更新（预设技能禁止改 code） |
| DELETE | `/api/agent/skills/{id}` | 删除（预设技能返回 400，只能禁用） |
| POST | `/api/agent/skills/seed` | 手动触发 seed 预设（幂等，存在即跳过） |

列表返回按 `sort_order, created_at` 排序；前端提问区只展示 `is_enabled=1` 的子集。

### 5.2 SkillService（`services/skill_service.py`，新增）

```python
class SkillService:
    @staticmethod
    async def list(db) -> list[dict]: ...
    @staticmethod
    async def create(db, data) -> dict: ...
    @staticmethod
    async def update(db, skill_id, data) -> dict | None: ...
    @staticmethod
    async def delete(db, skill_id) -> bool: ...
    @staticmethod
    async def seed_presets(db) -> int:           # 启动 + 手动触发，返回新建数
    @staticmethod
    async def resolve(db, skill_ids) -> list[dict]:
        """按 id 批量取启用中的技能；id 不存在/已禁用的静默跳过（容错）。"""
```

- `seed_presets` 在 `server.py` 启动事件中调用（try/except 包裹，失败仅告警不阻断启动）；
- id 使用 `uuid4().hex[:12]`，与项目其他表一致。

### 5.3 Prompt 组装（`oag_service.py` 扩展）

新增纯函数，便于单测：

```python
SKILL_CHAR_BUDGET = 4000   # 技能指令总字符软上限（config.py 可配）

def build_system_prompt(skills: list[dict]) -> str:
    """OAG_SYSTEM_PROMPT + 技能指令块；无技能时原样返回基础 prompt。"""
```

组装格式：

```
{OAG_SYSTEM_PROMPT 原文，不变}

【已启用技能】（以下指令由配置注入，不得违反上述引用规范）
### 技能：深度分析
{instructions}
### 技能：表格输出
{instructions}
```

规则：

1. **顺序**：按 `sort_order` 升序拼接；超预算时从尾部截断 + 日志 warning + SSE 事件中标记 `truncated: true`；
2. **优先级声明**：技能块头部固定加"不得违反上述引用规范"一句话，防止技能指令覆盖 `[来源N]`/`[事实]` 标注体系；
3. **去重**：同 id 只拼一次（前端可能重复传）；
4. `query_stream` / `_stream_vector_only` 两条路径统一走 `build_system_prompt`。

### 5.4 查询流程改造（`routers/agent.py`）

```python
@router.post("/agent/query")
async def agent_query(req: AgentQueryRequest, db=Depends(get_db)):
    kb = ...                                   # 不变
    ontology_schema = ...                      # 不变（预加载模式）
    skills = await SkillService.resolve(db, req.skill_ids)   # 新增：预加载
    return StreamingResponse(
        OAGService.query_stream(req.kb_id, req.query, kb["name"], ontology_schema, skills),
        ...
    )
```

### 5.5 SSE 事件扩展

在现有 `entities` 事件**之前**新增一个事件（推理链第一步）：

```json
data: {"type": "skills", "skills": [{"id": "...", "name": "深度分析", "code": "deep_analysis"}], "truncated": false}
```

`_stream_vector_only` 降级路径同样下发（skills 可能为空数组，前端不渲染该块即可）。

## 7. 一次查询的完整时序

```
用户（勾选 2 个技能，提问）
 │ POST /api/agent/query {kb_id, query, skill_ids:[a,b]}
 ▼
路由层：校验 KB → 预加载 ontology_schema → SkillService.resolve(skill_ids)
 │（db 会话到此为止，SSE 不再持有）
 ▼
OAGService.query_stream(..., skills)
 │ ① 总开关/降级判断（不变）
 │ ② 向量召回（不变） ③ 实体链接（不变） ④ 图谱召回（不变）
 │ ⑤ RRF 融合（不变）
 │ ⑥ SSE: skills → entities → subgraph → chunks（新增 skills 事件）
 │ ⑦ build_system_prompt(skills) → LLM 流式 token → [DONE]
 ▼
前端：推理卡片渲染「已加载技能」→ 回答
```

## 8. 边界与安全

| 场景 | 行为 |
|------|------|
| `skill_ids` 含不存在/已禁用 id | 静默跳过，查询不失败 |
| 全部技能被禁用 / 未勾选 | 等价现状，prompt 无技能块 |
| 技能指令总长超 4000 字符 | 按 sort_order 截断，SSE 标记 `truncated`，日志告警 |
| 技能指令试图覆盖引用规范 | 基础 prompt 在前 + 技能块固定声明"不得违反"，双保险 |
| instructions 为空 | 允许保存（占位草稿），但 resolve 时过滤掉空指令技能 |
| 删除正在被勾选的技能 | 前端保存后同步移除勾选；后端 resolve 天然容错 |
| 降级路径（OAG 关闭/无图谱） | 技能照常生效（只影响 prompt，与检索无关） |

> 提示词注入面评估：技能由本机用户自己配置，属可信输入；唯一外部输入是 KB 文档内容，现状已是"参考资料"隔离，本设计不扩大注入面。

## 10. 测试要点

1. **组装单测**：无技能 = 原文；1 个/多个技能拼接格式；超预算截断顺序；重复 id 去重；空 instructions 过滤
2. **resolve 容错**：不存在 id / 禁用 id / 空 `skill_ids`
3. **CRUD**：code 唯一冲突 409、预设禁删 400、预设禁改 code
4. **seed 幂等**：连跑两次，第二次新增数为 0
5. **端到端**：勾选「表格输出」提问，回答应含 Markdown 表格；SSE 首事件为 `skills`；降级路径同样下发 `skills`
6. **回归**：不带 `skill_ids` 的旧调用（curl 直调）行为与线上完全一致

## 11. v2 展望

技能机制稳定后，沿同一张表平滑扩展（加字段即可，不动存量数据）：

1. **参数型技能**：技能携带检索参数覆盖（如 `{oag_top_n: 20, neighbor_hops: 2}`），实现"深度模式=多召回+多跳子图"
2. **工具型技能**：`skill_type` 区分 `prompt / tool`，接 Text2Cypher（呼应 OAG 设计的融合点③）、实体卡片查询等只读工具，走多步 agent 循环
3. **KB 级绑定**：`kb_agent_skill_bindings`，财务库默认带财务分析技能
4. **技能市场/导入导出**：JSON 导入导出，跨实例共享

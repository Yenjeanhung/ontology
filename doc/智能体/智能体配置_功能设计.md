## 0. 一句话目标

把「智能体」从「全局一个 OAG 单例 + 提问时现场勾技能」升级为「**可创建、可命名、可复用、可拖入工作流**的智能体资产」。

---

## 1. 背景与目标

### 1.1 现状：智能体是全局单例，没有「创建好的智能体」这回事

当前 OAG 智能体的行为由两段硬编码 prompt 决定（`oag_service.py`）：

```
OAG_SYSTEM_PROMPT   ← 固定的「基于知识库与知识图谱的智能体」人设 + 引用规范
OAG_USER_TEMPLATE   ← 图谱事实 + 参考资料 + 问题
```

技能（`agent_skills`）已经把「风格/能力」抽出来按需勾选，但**「智能体」本身没有落库**——每次提问都要现场选 KB、勾技能，没有「财务智能体」「法务智能体」这样可复用的对象。

| 问题 | 表现 |
|------|------|
| 无法复用组合 | 「财务库 + 深度分析 + 严格引用」这套组合每次重选 |
| 无法命名沉淀 | 调好的人设 prompt 无法保存成「XX 智能体」 |
| 工作流无法引用 | 工作流要「拖智能体」，但没有对象可拖（见 [工作流设计 §1.4](../工作流/工作流_功能设计.md)） |

### 1.2 目标

1. **智能体 CRUD**：可创建、编辑、启用/禁用、删除（参照 `llm_configs` / `agent_skills` 管理模式）；
2. **可复用**：一个智能体 = KB + 技能 + 人设，可被问答页与工作流节点共同引用；
3. **执行一致**：智能体只是「预置入参」，执行仍走 OAG 管线，检索逻辑零改动；
4. **零回归**：不传 `agent_id` 时行为与现状完全一致。

### 1.3 非目标（v1 明确不做）

- ❌ 多知识库智能体（`agents` 单条记录只绑一个 KB）→ v2
- ❌ 智能体携带检索参数覆盖（改 `OAG_TOP_N`、跳数）→ v2
- ❌ 智能体版本管理 / 审核流
- ❌ 多智能体协作 / 智能体间对话

## 2. 什么是智能体（Agent）

### 2.1 定义

> **智能体 = 知识库(KB) + 技能(Skills) + 人设(System Prompt) +（可选）模型参数**。

技术上就是「一次 OAG 查询所需入参的**持久化打包**」：

```
智能体 = {
  kb_id,          // 问哪个知识库
  skill_ids,      // 默认挂哪些技能
  system_prompt,  // 人设（覆盖/扩展 OAG 默认人设）
  model, temperature,  // 可选，覆盖全局 LLM 配置
}
```

### 2.2 与相近概念的区别

| | 技能（agent_skills） | LLM 配置（llm_configs） | **智能体（agents，本设计）** |
|---|---|---|---|
| 管什么 | 读取侧「回答风格/能力」 | 用哪个模型等「推理资源」 | 「KB × 技能 × 人设」的完整组合 |
| 生效环节 | OAG system prompt 增量 | `create_llm()` | 一次 OAG 查询的整套入参 |
| 粒度 | 最小指令单元，可多个叠加 | 全局唯一生效 | 一个可复用对象，绑定单 KB |

关系：**智能体引用技能**（多对多，存 `skill_ids`）、**智能体绑定知识库**（单 KB）、**智能体可选覆盖模型**。

---

## 3. 字段定义

| 字段 | 类型 | 说明 |
|------|------|------|
| `name` | str | 展示名，如「财务智能体」 |
| `description` | str | 一句话说明 |
| `kb_id` | str | 绑定的知识库 id（v1 单 KB） |
| `system_prompt` | str | 自定义人设；空 = 用 OAG 默认人设 |
| `skill_ids` | list[str] | 默认启用的技能 id（JSON 数组） |
| `model` | str | 可选，覆盖全局模型；空 = 用当前激活配置 |
| `temperature` | float | 可选，覆盖全局温度 |
| `is_enabled` | int | 启用开关，禁用的智能体不出现在选择列表 |

## 4. 数据模型

### 4.1 新增表 `agents`

```sql
CREATE TABLE IF NOT EXISTS agents (
    id            VARCHAR PRIMARY KEY,
    name          VARCHAR(100) NOT NULL,
    description   TEXT DEFAULT '',
    kb_id         VARCHAR NOT NULL,          -- 绑定的知识库（v1 单 KB）
    system_prompt TEXT DEFAULT '',           -- 自定义人设，空 = 用 OAG 默认人设
    skill_ids     TEXT DEFAULT '[]',         -- JSON 数组，默认启用的技能 id
    model         VARCHAR DEFAULT '',        -- 空 = 用当前激活的 LLM 配置
    temperature   REAL DEFAULT 0.7,
    is_enabled    INTEGER NOT NULL DEFAULT 1,
    created_at    VARCHAR,
    updated_at    VARCHAR
);
CREATE INDEX IF NOT EXISTS idx_agents_kb ON agents(kb_id);
```

### 4.2 ORM（`backend/models.py`）

```python
class Agent(Base):
    __tablename__ = "agents"
    id = Column(String, primary_key=True, default=lambda: uuid.uuid4().hex[:12])
    name = Column(String(100), nullable=False)
    description = Column(Text, default="")
    kb_id = Column(String, nullable=False)
    system_prompt = Column(Text, default="")
    skill_ids = Column(Text, default="[]")    # JSON 数组
    model = Column(String, default="")
    temperature = Column(Float, default=0.7)
    is_enabled = Column(Integer, nullable=False, default=1)
    created_at = Column(String, default=lambda: datetime.now().isoformat())
    updated_at = Column(String, default=lambda: datetime.now().isoformat())
```

## 5. 后端设计

### 5.1 API（挂 `/api`，并入 `routers/agent.py`）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/agents` | 列表（含 KB 名、技能数） |
| POST | `/agents` | 创建（校验 kb 存在、skill_ids 有效） |
| GET | `/agents/{id}` | 详情（skill_ids 展开为技能名） |
| PUT | `/agents/{id}` | 更新 |
| DELETE | `/agents/{id}` | 删除 |
| POST | `/agents/{id}/test` | 测试对话（复用 OAG 流式，预览该智能体效果） |

### 5.2 AgentService（`services/agent_service.py`，新增）

```python
class AgentService:
    @staticmethod
    async def list(db) -> list[dict]: ...       # 附 kb_name、skill_count
    @staticmethod
    async def create(db, data) -> dict: ...     # 校验 kb 存在、skill_ids 有效
    @staticmethod
    async def update(db, agent_id, data) -> dict | None: ...
    @staticmethod
    async def delete(db, agent_id) -> bool: ...
    @staticmethod
    async def resolve(db, agent_id) -> dict | None:
        """按 agent_id 展开出 OAG 入参：
        {kb_id, system_prompt, skill_ids, model, temperature}
        不存在/已禁用返回 None；skill_ids 交给 SkillService.resolve 容错过滤。"""
```

### 5.3 执行时展开（`oag_service.py` 小改）

智能体只是「预置入参」，执行仍走 OAG 管线。需要两处小改：

1. **`build_system_prompt` 支持自定义基础人设**：

```python
def build_system_prompt(skills: list[dict], base_prompt: str = OAG_SYSTEM_PROMPT) -> str:
    """base_prompt + 技能指令块；传 agents.system_prompt 时覆盖默认人设。"""
```

2. **`query_stream` / `run` 增加 `system_prompt`、`model`、`temperature` 可选参数**，用于覆盖默认人设与模型（`model`/`temperature` 透传给 `create_llm`，空则沿用当前激活配置）。

### 5.4 `/agent/query` 兼容改造

`AgentQueryRequest` 增加可选字段 `agent_id`：

```python
class AgentQueryRequest(BaseModel):
    query: str
    kb_id: str | None = None          # 传 agent_id 时可不传，以 agent 为准
    skill_ids: list[str] = []
    agent_id: str | None = None       # 新增：引用已配置智能体
```

路由层：`agent_id` 给定时 `AgentService.resolve` 展开 → 覆盖 `kb_id` / `skill_ids` / `system_prompt`；未传时走原逻辑（零回归）。

## 6. 前端设计

### 6.1 智能体管理页（`front/src/components/agent/AgentListPage.vue`，新增）

参照技能管理页的三栏（列表 / 编辑表单）：

| 区块 | 内容 |
|------|------|
| 左列 | 智能体列表（名称 + 启停开关 + KB 名 + 技能数） |
| 右列 | 编辑表单：name / description / KB 下拉 / 技能多选 / system_prompt 多行 / 模型温度（高级折叠） / 「测试对话」入口 |

- 路由：`/agent/configs`（挂在「智能体」菜单下）；
- 「测试对话」内嵌一个轻量对话区，`POST /agents/{id}/test` 流式预览（复用 AgentView 的 SSE 渲染）。

### 6.2 工作流 agent 节点引用

工作流 `agent` 节点两种绑定方式（详见 [工作流设计 §4.3](../工作流/工作流_功能设计.md)）：
- **引用智能体**：`config = { agent_id }`；
- **内联配置**：`config = { kb_id, skill_ids, query_template }`。

`GET /workflow/palette` 的 `agents` 段返回启用中的智能体列表，供节点面板拖拽。

### 6.3 问答页（AgentView）改造

- 顶部新增「智能体」下拉（可选，空 = 快速模式）；
- 选了智能体 → KB 与技能自动填充为该智能体的配置，仍可临时微调；
- 未选智能体 → 与现状完全一致。

## 7. 与工作流模块的关系

```
智能体配置模块（本文档）            工作流模块
───────────────────────          ─────────────
agents 表 + /agents CRUD  ──────▶  工作流 agent 节点
                                   · 引用智能体（agent_id）
                                   · 内联配置（不落库）
```

- 智能体配置模块是**独立可用**的：不建工作流也能用它管理「智能体资产」并在问答页使用；
- 工作流模块是它的**下游消费者**：把智能体作为可拖拽节点类型。

## 8. 安全与边界

| 场景 | 行为 |
|------|------|
| 删除已被工作流引用的智能体 | 工作流运行时报错（提示智能体不存在）；v2 做引用计数 |
| 删除智能体绑定的 KB / 技能 | resolve 时 KB 404 / 技能静默跳过（沿用 `SkillService.resolve` 容错） |
| `system_prompt` 试图覆盖引用规范 | 引用规范仍由 `build_system_prompt` 底层保证，`system_prompt` 只替换人设段 |
| 禁用的智能体 | 列表不出现在选择项；resolve 返回 None |
| 未传 `agent_id` | 零回归，行为同现状 |

> 提示词注入面评估：智能体由本机用户配置，属可信输入；唯一外部输入仍是 KB 文档内容，沿用「参考资料隔离」边界。

## 10. v2 展望

1. **多 KB 智能体**：`agents.kb_id` 支持多知识库 + 检索融合；
2. **参数型智能体**：携带检索参数覆盖（`oag_top_n`、`neighbor_hops` 等），实现「深度模式」；
3. **智能体市场**：导出/导入智能体 JSON，跨实例分享（复用技能导入导出的成熟链路）；
4. **工具型智能体**：智能体绑定只读工具（Text2Cypher 等），走多步 agent 循环。

# 多智能体场景：通用智能体团队（唯一场景，任务类型不限）

> 业务底稿：《G 航空公司航班运行风险管理研究》；总体设计见《多智能体交互.md》§14。
> 本文档是**多智能体场景层的开发定义**：先定义与业务无关的框架契约（引擎 / 接口 / 页面），
> 默认场景是**通用智能体团队**（业务无关、任务类型不限、组合自由勾选）；
> 多智能体是动态的，任意任务类型皆可跑；新业务如需专属编排，实现
> MultiAgentScenario 适配器并在注册表追加一行 import 即可，路由与引擎零改动。
> 一句话定位：**多智能体是业务无关的通用团队；规则/业务系统管"发现"（快、准、召回高），多智能体管"研判/加工"（跨源取证、冲突消解、解释留痕、任务交付）。**
>
> **v6.0 变更（聊天框化 + 会话记忆，本版开发蓝本）**：页面重构为与智能体问答一致的
> 聊天框形态（编制选择 + 会话历史 + 过程折叠卡 + 流式成果气泡），并成为**唯一智能体入口**
> （原「智能体问答」菜单删除，`/agent` redirect 至 `/agent/multi-agent`）；
> 编制选择简化为两档——**自动路由 / 手动选择**，手动选择可混排勾选能力角色与
> 自定义智能体（专家节点）；新增**会话记忆三层**（P1 会话窗口 / P2 滚动摘要 /
> P3 mem0 长期记忆，见 §0.7）。

## 0. 架构总则（业务无关，先读这个）

多智能体能力**不绑定任何业务**，分三层：

```
┌ 通用页面（front MultiAgentPage.vue · 聊天框形态 v6.0）───────┐
│  编制选择（自动路由 / 手动勾选）→ 会话流（历史轮气泡 + 过程     │
│  折叠卡 + 流式成果）→ 会话管理（新会话/历史会话）→ 任务库 chips │
├ 通用路由（routers/multi_agent.py）───────────────────────┤
│  GET /scenarios · GET /scenarios/{sid}/targets ·           │
│  POST /scenarios/{sid}/targets/{tid}/run (SSE) ·            │
│  POST /scenarios/{sid}/run (SSE, body: task + agents 组合)  │
├ 通用引擎（services/multi_agent/engine.py）────────────────┤
│  planner 分解 → plan 声明的并行角色同 superstep 执行 →       │
│  critic（可选组合）→ synthesizer；事件外抛 / LLM 流式 / 降级  │
├ 场景适配器（services/multi_agent/scenarios/*）────────────┤
│  universal（通用团队，默认注册）+ 业务专属适配器按需注册：      │
│  智能体组合、任务计划、节点实现、目标列表、话术模板              │
└──────────────────────────────────────────────────────────┘
```

- **引擎不知道任何业务概念**：state 里只有 `context`（场景自定义上下文）、`plan`、
  `evidence`、`facts`、`verdict`、`conclusion` 六个标准槽位；
- **组合（agents）是通用抽象**：核心角色（Planner / Synthesizer）内置必在，
  能力角色（Retriever / DataAgent / GraphAgent / Critic）由用户自由勾选，流水线
  按组合动态装配——不选 Critic 时并行节点直通 Synthesizer（引擎原生支持，
  零特判）；
- **路由与页面只面向注册表编程**：新增业务场景 = 写一个适配器 + 注册表加一行，
  引擎 / 路由 / 页面零改动；
- **目标（target）是通用抽象**：航班告警、合同、工单、设备……在框架眼里都是
  `{id, title, headline, runnable, …}` 的目标卡；
- **克制边界通用化**：目标卡带 `runnable/note`，规则引擎已给结论的对象不进多智能体。

## 0.5 默认场景：通用智能体团队（adhoc · 对标开源多智能体）

页面的**默认场景**是业务无关的「通用智能体团队」（`scenarios/universal.py`，`adhoc=true`）：
**核心智能体内置、能力智能体自由组队、任务类型不限**——研判、写作、总结、问答皆可，
不是选预置目标，而是**给一段任务描述 + 勾选组合**：

**智能体组合（roster）**：

| 类别 | 智能体 | 说明 |
|---|---|---|
| 核心内置（必在） | Planner · 任务规划 | LLM 把任务分解为 2~4 个可并行子任务（15s 超时回落默认分解） |
| 核心内置（必在） | Synthesizer · 结果合成 | 汇总共享黑板，流式交付最终成果 |
| 能力可选 | Retriever · 知识库取证 | 为每个子任务检索平台全部知识库向量语料（RAG 增强）；未选时子任务由 Worker 用模型知识直接执行 |
| 能力可选 | DataAgent · 数据查询 | 实体台账结构化查询：关键词命中总量、按实体类型聚合、最新明细（解析 properties 真实字段），产出数据事实卡（`grade=data_fact`）；关键词同时匹配实体类型（「告警」→ 运行告警），给合成官真实数字、杜绝编造 |
| 能力可选 | GraphAgent · 图谱事实 | 实体图谱关键词检索（Entity/Relation），产出结构化事实卡 |
| 能力可选 | ToolAgent · 工具调用 | LLM 自主工具循环（bind_tools→多轮），内置 kb_search/graph_search/data_query + MCP 外部工具 |
| 能力可选 | Critic · 评审质控 | 素材交叉验证、充分性硬规则裁定（无素材不出成果 / 少于 3 条建议人工）+ LLM 解释；未选时并行节点直通 Synthesizer |
| 能力可选 | 专家智能体（自定义） | 勾选 `agent:{id}` 引用现有智能体配置（人设+技能），作为**专家节点**入编：Planner 按其专长分解子任务，其节点以 persona+skills 执行（specialist 角色） |

**编制两档（v6.0，页面只有一个编制选择器）**：

| 档位 | 用户操作 | 后端行为 |
|---|---|---|
| **自动路由**（默认，不勾选） | `agents` 传 `[]` | 0.6B 小模型意图路由接管（`router_service.routing_decision`）：chat 高置信直答（编排不启动）/ data·graph·kb 精简组合 / 低置信全组合兜底 |
| **手动选择** | 勾选后 `agents` 传清单 | 元素为角色名（`retriever`/`data_agent`/`graph_agent`/`tool_agent`/`critic`）或 `agent:{id}`（专家节点）；显式组合被尊重，路由仅叠加 NL2Filter / 改写门控 |

Planner / Synthesizer 始终内置，不进勾选列表；勾选列表混排能力角色与自定义智能体。

| 开源范式 | 本实现对应 |
|---|---|
| Plan-and-Solve / HuggingGPT：LLM 把任务分解为子任务 | Planner 用 LLM 动态分解（分解提示词随组合切换：选 Retriever → 检索式子任务；否则 → 模型知识执行的关键环节），计划经 SSE `plan` 事件全程可见 |
| AutoGen GroupChat / CrewAI Crew：角色组合 + 黑板共享状态 | **组合由用户自由勾选**（组队选择器），成员命名取自子任务（Retriever-1..N / Worker-1..N），所有节点读写共享 state（evidence / facts / verdict） |
| MetaGPT 流水线 SOP：角色按序传递中间产物 | 引擎 LangGraph superstep 装配线：并行执行 → critic（可选）→ synthesizer |
| Magentic-One：任务台账 + 重规划 | 首版做一次性规划（重规划留作迭代），Critic 确定性裁定兜底 |
| RAG / GraphRAG：检索增强 | Retriever 检索**平台全部知识库**向量语料（VectorDataService），GraphAgent 关键词检索**实体图谱**（Entity/Relation），均不绑定业务域 |

流程（以全选组合为例）：输入任务 → LLM 规划 → Retriever×N 全库向量检索
（素材卡 `grade=sourced_doc`，含知识库/文件/页码/相似度）→ DataAgent 台账
数据卡（`grade=data_fact`，真实统计/明细）→ GraphAgent 图谱事实卡 →
Critic 素材充分性硬规则裁定 + LLM 解释 → Synthesizer 流式合成带 [素材N]/[事实]
引用的成果（LLM 失败落模板，裁定不变）。任务类型不限：写作任务未选 Retriever 时，
Worker×N 并行产出各章节素材，Synthesizer 汇合成文。

接口：`POST /api/agent/multi/scenarios/{sid}/run`，body `{"task": "…", "agents": […],
"session_id": "…"}`（session_id 首轮省略，后端**懒创建会话**并经 `session` 首帧回传；
agents 语义见上表编制两档；仅 adhoc 场景，否则 400）。业务场景（如告警复核）
保持目标卡模式，二者共用页面、引擎与 SSE 契约。

### 0.6 任务库（可配置任务提示词模板）

任务不是写死的示例，而是**可配置、可编辑的任务库**（`multi_agent_tasks` 表 +
`services/multi_agent/task_store.py`）：每条任务 = `{name, prompt, agents}`——

- `prompt` 是**任务提示词模板**，支持 `{question}` 占位符：选中任务后在输入框
  输入具体问题，运行时替换占位符（未含占位符则拼接在模板之后）；
- `agents` 是该任务的默认智能体组合，选中时自动应用（仍可临时改勾选）；
- 内置 5 条预置任务（研判·主题盘点 / 研判·图谱探查 / 数据·台账统计 /
  写作·简报撰写 / 总结·内容摘要），仅表为空的首次使用播种，删除后不复活；
- CRUD 走 `/api/agent/multi/tasks`，页面左侧任务库列表：点击选中、▶ 直接运行、
  ✎ 编辑提示词、✕ 删除、＋ 新建。

运行组合逻辑（前端 `composeTask`）：`最终任务 = 任务提示词模板（{question} ← 用户问题）`；
未选任务时输入框即自由任务。

### 0.7 会话记忆（v6.0，仿智能体问答三层）

多智能体从「单发任务」升级为「多轮会话」，记忆分层**完全复用现有组件**（不重建）：

| 层 | 载体 | 说明 |
|---|---|---|
| P1 会话窗口 | `chat_sessions` / `chat_messages` + `scene='multi'` | 每轮落库：user=任务原文，assistant=conclusion 全文；读侧近 `CHAT_SESSION_WINDOW_TURNS` 轮 + 字符预算双重约束（复用 `chat_service.load_history`） |
| P2 滚动摘要 | `session.summary` + `summary_until_id` 幂等游标 | 超过触发轮数后 LLM 压缩窗口外旧轮（复用 `maybe_summarize`，会话级、后台化、互斥锁） |
| P3 长期记忆 | mem0 命名空间 `user:{uid}:team:multi` | 会话开始按任务检索相关事实注入；会话结束后台写入结论要点（复用 `memory_store`） |

设计要点：

- **协议**：run body 加 `session_id`（懒创建，标题取首问前 50 字）；SSE 首帧发
  `{"type":"session", "session_id", "title"}`；流末仿 `/agent/query` 的 `_persist_turn`
  三件套（assistant 落库 → 后台滚动摘要 → 后台记忆写入），全部尽力而为、失败仅记日志；
- **注入点（引擎保持低侵入）**：`MultiAgentState` 新增 `history` / `summary` / `memories`
  槽位，仅三处消费——
  ① Planner `_plan_goals`：带摘要 + 近期轮次，支持「再查一下刚才那个」类追问分解；
  ② Synthesizer：带记忆事实 + 历史，综合裁定时有上下文；
  ③ 直答路径 `_build_direct`：带历史（多轮直答连续对话）；
- **隔离**：会话列表 `GET /api/chat/sessions?scene=multi` 过滤，与单智能体问答会话互不可见；
  mem0 空间独立于 `user:{uid}:agent:{aid}`，多智能体结论不污染单智能体长期记忆。

## 1. 场景一定位（组合告警复核）

论文对比实验（38376 架次）：规则引擎召回率 0.60→0.96，但留下 **8923 起误报**每起需人工核查；
研判要跨气象/动态/资质/手册多源取证，口径常打架。

**触发与业务流**：

```
Drools 命中组合规则（如"晚关门 + 雷雨"双条件，论文图 5.8）
  → 告警卡片推送至席位
  → 值班员点卡片上的「AI 复核」
  → 多智能体流水线（本文 §3）
  → 结论卡：维持 / 升级建议 + [来源N]/[事实] 引用 + 响应时限提示
```

**克制边界（同样重要）**：单条件低风险告警（如 SOBT 超 10min 未关舱门）规则引擎已给结论，
**不进多智能体**——目标卡 `runnable=false` 并给出理由。多智能体是能力上限，不是所有告警的必经之路。

## 3. 智能体组合（六角色 × 场景一）

| 角色 | 输入 | 输出 | LLM |
|---|---|---|---|
| Planner | 告警上下文 | 结构化任务清单（JSON，schema 校验） | 否（固定复核模板，快而稳） |
| Retriever ×3 并行 | 分域目标（气象/手册/机组保障） | 证据卡 `{id, source, grade, summary, quote}` | 纯取证，零 LLM |
| GraphAgent | 航班号、告警类型 | 图谱事实卡（历史同类 + 关联实体） | 否（结构化查询） |
| Critic | 证据卡 + 事实卡 | 冲突清单 + 分级裁定 `{conflicts, suggestion, need_human}` | 是（LLM 消解；失败降级硬规则） |
| Synthesizer | 全部材料 | 流式 markdown 结论卡（建议 + 引用 + 时限） | 是（流式；失败降级模板） |

编排（通用引擎按 plan 声明的角色调度；同 superstep 四节点自动并行）：

```
START → planner ─┬→ retriever_weather ─┬→
                 ├→ retriever_manual  ─┼→ critic → synthesizer → END
                 ├→ retriever_crew    ─┤
                 └→ graph_agent       ─┘
```

State（通用引擎定义，并行写竞争用 reducer 消解，对应设计文档 §4.1 黑板模式）：

```python
class MultiAgentState(TypedDict):
    context: dict                                                 # 场景上下文（业务自定义，引擎不解读）
    plan: list[dict]                                              # 任务计划
    evidence: Annotated[dict[str, list[dict]], merge_evidence]    # domain→证据卡
    facts: list[dict]                                             # 图谱/结构化事实卡
    verdict: dict                                                 # critic 裁定
    conclusion: str                                               # synthesizer 结论
```

**证据分级硬规则**（场景一 Critic 兜底，无 LLM 也能裁定）：
`graph_fact(5) > sourced_doc(4) > duty_record(3) > model_knowledge(1)`；
同级冲突（观测 vs 预报）→ 取保守方向（升级优先），并标注"建议人工复核更新"。

## 4. SSE 事件契约（与业务场景无关，复用现有 SSE 通道模式）

| type | 时机 | payload 要点 |
|---|---|---|
| `session` | 流首帧 | `{session_id, title}`（懒创建会话；前端锚定本轮归属并刷新会话列表，v6.0 新增） |
| `team` | 流开始 | 团队名、成员角色清单 |
| `plan` | planner 完成 | 节点清单 `[{id, role, goal}]` |
| `node_start` | 每节点开始 | node / role / goal |
| `node_done` | 每节点完成 | node / summary（一句话干了什么） |
| `evidence` | retriever 完成 | 证据卡数组（domain / grade / source / summary） |
| `fact` | graph_agent 完成 | 图谱/结构化事实卡数组 |
| `conflict` | critic 完成 | 冲突数组 + 总裁定 `{suggestion, need_human}` |
| `token` | synthesizer 流式 | 增量 markdown 文本 |
| `done` | 流结束 | conclusion 全文 + elapsed_ms |
| `error` | 节点失败（已降级） | 可读错误信息 |

流以 `data: [DONE]` 收尾（与 `/api/agent/query` 一致）。

## 5. 接口设计（业务无关）

| 接口 | 方法 | 说明 | 权限 |
|---|---|---|---|
| `/api/agent/multi/scenarios` | GET | 已注册场景列表（id/name/business/description/adhoc） | 免强制（菜单控制） |
| `/api/agent/multi/scenarios/{sid}/targets` | GET | 场景目标列表（通用目标卡，含 runnable/note） | 免强制（菜单控制） |
| `/api/agent/multi/scenarios/{sid}/targets/{tid}/run` | POST (SSE) | 对目标发起多智能体研判 | `agent:view`（显式规则：只读研判，SSE 走 POST 不归 create） |
| `/api/agent/multi/scenarios/{sid}/run` | POST (SSE) | 自由任务协作，body `{"task": "…", "agents": […], "session_id": "…"}`（编制两档见 §0.5；session_id 懒创建，v6.0）；仅 adhoc 场景 | 同上 |
| `/api/chat/sessions` | GET | 会话列表，v6.0 起支持 `scene=multi` 过滤（多智能体会话与单智能体问答互不可见）；重命名/删除/消息拉取复用现有接口 | `agent:view` |
| `/api/agent/multi/tasks` | GET / POST | 任务库：列表（首次自动播种预置）/ 新建（name+prompt+agents） | 免强制（菜单控制） |
| `/api/agent/multi/tasks/{tid}` | PUT / DELETE | 编辑任务提示词/组合/排序；删除（预置任务同样可删，不复活） | 免强制（菜单控制） |

路由前缀 `agent` → 权限模块归属「智能体」模块，无需新增权限点。

## 7. 降级矩阵

| 故障 | 行为 |
|---|---|
| LLM 未配置 / 调用失败 | Critic → 硬规则裁定；Synthesizer → 模板结论；流水线不中断 |
| 单节点超时（30s） | 该节点降级产出，`error` 事件说明 |
| 目标不可研判（runnable=false） | 前端按钮禁用 + 理由；后端同样拒绝兜底 |

## 2. citation_valid 0.67：10 条全是「未引用」，不是「引用错」

确定性校验的两种失败模式：引用了不存在的事实编号（幻觉引用）／该引用而不引用。本轮 10 条失分**全部**是后者——日志统一显示：

```
citation_valid=0｜引用 无｜事实卡 14 张
```

即：引擎取回了 14 张事实卡，但 synthesizer 产出的结论**一个 `[事实N]` 标记都没写**。这是输出格式不稳定问题（同一 prompt 下有时带引用有时不带），不是取证或事实问题——这 10 条里有不少 factuality 仍判 True。

**改进方向**：synthesizer prompt 中把「结论须以 `[事实N]` 标注论断来源」从建议改为硬性要求（含示例 few-shot），或在 synthesizer 后加一道轻量校验：无引用且 facts 非空时自动重试一次。预期该指标可拉到 0.9+。

## 3. factuality 0.67：失分三类，性质不同

逐条看 judge reasoning（已存日志），10 条 False 归为三类：

### 3.1 「牵头部门/职责归属」细节相悖（约半数）
任务要求研判"由谁牵头处置"时，结论给出的部门与参考答案不一致。judge 原文示例：

- 参考答案「总值班室牵头」，结论判「飞行控制室牵头」（[#1] 流控 75 分钟研判）；
- 参考答案「机务维修控制中心牵头，签派放行室配合」，结论「飞行控制室牵头，地面保障部门落实」（[#17] 机务故障简报）；
- 参考答案「高：总值班室启动应急预案；中/低：签派放行室牵头」，结论「通用：飞行控制室牵头」（[#20]）。

这类是**取证命中了语料但事实细节取偏**——多智能体并行取回的素材里"牵头部门"信息未被 critic 拦住，直接进了结论。

### 3.2 语料缺失导致的「诚实但空手」（约 1/3）
检索未命中关键语料，结论如实声明"素材未呈现"，judge 按核心问项缺失判 False：

- [#5] 低风险响应要求整块缺失（语料截断）；
- [#15] 中低风险流控时长阈值（30/60 分钟）未取到；
- [#24/#26/#27] LongMemEval 分项数值、Zep+gpt-4o 具体得分与延迟数据缺失。

注意：trajectory judge 对同几条都判 True（"如实披露缺失、未编造、给补全建议，属合理路径"）——**过程正确、结果不足**。这说明瓶颈在语料覆盖/检索召回，而非编排。

### 3.3 开放归纳题自由发挥偏离参考（少数）
[#18] 归纳"处置原则"，结论给出「分级响应、闭环管理、动态升级、通报备案」，参考答案为「安全第一、先高后低、谁主管谁牵头、闭环管理」——大面积不重合。

**改进方向**：
1. 3.1 类 → critic 增加"部门/职责类关键事实"的专项比对，或 planner 把"牵头部门"列为必取证子项；
2. 3.2 类 → 补语料（LongMemEval/Zep 数值类语料缺失是数据问题不是模型问题），或提高相似度召回；
3. 3.3 类 → 属 judge 口径敏感区（开放归纳题参考答案覆盖不全），可给该类 Example 补充更宽松的 reference 或在 judge prompt 中声明"原则归纳允许同义重组"。

## 4. trajectory_valid 1.00：编排护栏全绿

30 条全部通过，包括几条**检索逆境**样本：

- [#19] worker_1 未命中语料 → 台账/图谱素材补位，收敛正常；
- [#25] 三个 retriever 全部未命中 → data_agent + graph_agent 兜底交付；
- [#29] 四个 retriever 全部未命中 → 图谱 + 台账兜底，结论如实标注证据局限。

judge 判词一致指向：分解覆盖完整、无空转、失败节点后仍收敛、不编造。**编排层（本轮改动的主对象）没有引入任何退化**——这正是 trajectory 指标存在的意义：前两个指标低不代表改动失败，路径分满分说明"地基"稳。

## 5. 一个值得记录的信号：Critic 全绿 vs Judge 拦下 1/3

日志里 30 条 Critic 裁定**清一色**「0 处存疑 → 可采纳交付（置信度 高）」，而外部 factuality judge 判了 10 条事实不一致。Critic 内审完全放水，评估体系把它照了出来——这正对上接入方案 §4.1 的设计动机「防 Critic 放水：素材不足仍放行」。Critic 的存疑检出逻辑是下一轮 prompt 迭代的重点对象。

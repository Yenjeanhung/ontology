## 1. 背景与目标

### 1.1 民航维修的三大成本黑洞

| # | 痛点 | 行业现状 | 后果 |
|---|---|---|---|
| **P1** | **AOG（飞机非计划停场）** | 一架窄体机停场一天，直接损失（航班取消 + 旅客赔偿 + 调机 + 航材运输 + 机组）通常在 **数万至数十万美元** | 排故每多花一小时，就是一小时的 AOG 成本 |
| **P2** | **NFF（No Fault Found / 无故障发现）** ⭐ | 拆下的 LRU 送车间检测却"没毛病"，行业统计占非计划拆换件的 **30%~50%** | 航材周转件需求虚高、拆换人工白费、飞机白停。这是**根因定位不准**的直接代价 |
| **P3** | **重复性故障 / 间歇性故障** | 同一故障在同一架或同一机型上反复出现；间歇性故障时有时无，地面测试往往不复现 | 反复排故、反复停场；民航对重复性故障有强制可靠性监控要求 |

### 1.2 其他现实问题

| # | 问题 | 说明 |
|---|---|---|
| P4 | **FIM/TSM 手册是"通用树"，不认机队个体差异** | FIM 给出的是 OEM 视角的全量可能原因，不区分"本航司机队上哪个原因最常见"。照着 FIM 一步步做，往往耗时很长 |
| P5 | **经验在放行工程师和老师傅脑子里** | 老机务退休 = 机队经验资产清零；新人遇到间歇性故障只能从头摸索 |
| P6 | **跨机型经验不流通** | A320 上验证过的排故经验，A321 上遇到同类故障却没人知道（同系列机型共享大量 LRU 与系统架构） |
| P7 | **MEL 保留与 AD 符合性靠人盯** | 保留到期、AD 生效、重复性 AD 到期，全靠表格 + 人工提醒，容易漏 |

### 1.3 为什么必须是图谱

| 方案 | 能不能解决 |
|---|---|
| FIM/TSM 手册全文检索 | 能查到"标准答案"，但**不知道本机队上哪个原因最常见**，也**不知道历史上怎么修好的** |
| 向量检索历史工单 | 只能找"文字相似的工单"，找不到"这个故障码背后最可能的根因链" |
| 关系型表格（工单表 JOIN IPC 表） | 根因链长度不固定（1~5 跳）、FIM 树是递归结构，SQL 递归难写难调优；**做不了社区发现、相似度、链路预测** |
| **知识图谱** | 多跳路径是原生能力；**IPC 树 + FIM 树天然就是两张图**；相似案例、根因聚类、跨机型迁移都有成熟算法 |

### 1.4 目标

1. **沉淀**：把 IPC（部件树）、FIM（故障树）、FLB/TLB 与 NRC 工单、拆换记录、AD/SB、MEL 中的知识，沉淀为**受本体约束**的结构化资产。
2. **推理**：从「CMS 故障码 / 飞行员描述的现象」出发，跨故障树与部件树做多跳根因推理，输出**按本机队历史数据排序**的根因候选与处置方案。
3. **降 NFF**：用图谱证据（历史拆换后的验证结论、NFF 标记）辅助判断"该不该换件"，减少误换。
4. **自生长**：每完成一次排故，新知识回流图谱，越用越准。
5. **治理**：图计算发现高频根因、高拆换件、故障簇、跨机型可迁移经验；工作流自动盯住 AD 符合性与 MEL 保留到期。

### 1.5 非目标（v1 明确不做）

- ❌ 预测性维护（PHM）/ 发动机性能趋势预测 —— 不做时序预测模型，QAR/ACARS 参数只作**触发信号**与统计来源
- ❌ 航材库存优化与采购决策 —— 只做"可用件号 / 互换性 / 库存查询"
- ❌ 自动下达维修指令或自动放行 —— 系统只给建议，**最终由持照人员确认**（人工节点把关，这也是适航要求）
- ❌ 多航司共享图谱 —— 一期只做**单一航司**，二期再考虑（见 [03 §4](./03-图计算设计.md)）

## 2. 业务价值与 ROI

| 价值点 | 度量方式 | 说明 |
|---|---|---|
| **减少 AOG 时长** | 平均排故时长（MTTR）下降比例 × AOG 小时成本 | 最直接、最容易算清的一笔账 |
| **降低 NFF 率** | NFF 拆换件占比下降 | 直接减少航材周转件需求与拆换人工 |
| **降低重复性故障** | 同机型同故障的重复发生率 | 减少反复停场，也满足可靠性监控要求 |
| **缩短新人成长周期** | 新人独立排故所需时间 | 缓解机务人力紧张 |
| **提升签派可靠性** | Dispatch Reliability 指标 | 航司核心 KPI 之一 |

### ROI 粗算示例（可写进方案书）

> 某中型航司 200 架机队，年非计划排故事件约 2 万起，平均排故 3.5 小时，
> 其中约 15% 触发 AOG（单次停场成本按 8 万元保守估算）。
>
> 若图谱辅助排故使 **平均排故时长下降 20%**、**NFF 拆换率下降 5 个百分点**：
> - 排故工时节省：2 万 × 3.5h × 20% = **1.4 万工时**
> - AOG 次数/时长下降：约 **节省 2400 万元/年**（3000 起 × 8 万 × 10%）
> - NFF 减少带来的航材与人工节省：约 **数百万/年**
>
> 合计年化收益通常在 **数千万量级**，远高于系统建设投入。

**建议**：POC 阶段就与航司约定 MTTR、NFF 率、签派可靠性的**基线值**，否则上线后无法证明价值。

## 3. 数据源与量级

> 以**单一中型航司、200 架机队、3 年历史数据**为参考。

### 3.1 数据源分层

| 层 | 数据源 | 类型 | 量级 | 入库方式 |
|---|---|:--:|---|---|
| **L1 结构化** | **IPC 图解零件目录** | 结构化 | 5 万+ 件号 | **ETL 直入** → 部件树 |
| | **CMS/ECAM/EICAS 故障码字典** | 结构化 | 2 万条 | **ETL 直入** → 故障锚点 |
| | 机队构型（注册号 / MSN / 装机清单） | 结构化 | 200 架 × 数千件 | **ETL 直入** |
| | 航材库存与互换性表 | 结构化 | 5 万条 | **ETL 直入** |
| | **MEL / CDL 清单** | 半结构化 | 3 千条 | **ETL + 轻解析** |
| | **AD / SB 清单** | 半结构化 | 1 万条 | **ETL + 轻解析** |
| **L2 手册** | **FIM / TSM 故障隔离手册** | **半结构化树** | 万级章节 | **⭐ 树结构解析 → 直接建故障树** |
| | AMM / SSM / SWPM | 长文档 | 万级章节 | 按需抽取（主要建"引用"关系） |
| **L3 混合** | **FLB / TLB 技术记录本** | 结构化字段 + 自由文本 | **百万级/年** | 字段直取 + **LLM 约束抽取** |
| | **NRC 非例行工单** | 结构化字段 + 自由文本 | **百万级/年** | 同上 |
| | **部件拆换记录 + 车间修理报告** | 混合 | 十万级 | **LLM 抽取（NFF 判定关键数据源）** |
| **L4 文档** | 可靠性月报、工程指令 EO、故障分析报告 | 半结构化 | 千~万份 | LLM 约束抽取 |
| **L5 时序** | QAR / ACARS 下行参数 | 时序 | 亿级点 | **不入图谱**，仅作触发信号与统计来源 |

### 3.2 ⭐ 关键洞察：本场景有「两棵现成的树」

通用制造业做知识图谱，最难的是从零构建领域知识。民航维修**不是**：

| 树 | 现成来源 | 性质 |
|---|---|---|
| **部件树** | **IPC（图解零件目录）** | 结构化、权威、OEM 维护，直接从 ATA 章节展开 |
| **故障树** | **FIM / TSM（故障隔离手册）** | **本身就是一棵决策树**：故障码 → 可能原因 → 隔离步骤 → 修复措施 |

**这意味着**：

1. 图谱的**主干不需要 LLM 抽取**，解析即可，准确率高、零 token 成本；
2. LLM 抽取的工单知识用于**补充与修正**主干（FIM 是 OEM 通用树，不区分机队个体经验），
   而不是从零建树 —— 这是本场景相比通用装备运维**最大的成本优势**；
3. 项目一期就能拿出一张"完整且可信"的图，POC 说服力完全不同。

## 4. 核心设计：IPC + FIM 双树合一 ⭐

### 4.1 两棵树

```
     IPC 部件树（组成 / 装于）              FIM/TSM 故障树（表现为 / 导致）
     ────────────────────────              ────────────────────────────────
           机型 B737-800                        故障码 29-11341
                │ 包含系统                            │ 上报代码
     ┌──────────┼──────────┐                          ▼
   ATA 29     ATA 32     ATA 27              故障模式：B 系统压力低
   液压       起落架     飞控                        ▲ 表现为
     │ 组成                                          │
  ┌──┴───┐                                     中间原因（FIM 隔离步骤）
液压泵  蓄压器                                        ▲ 导致
PN:65-90751-4                                        │
  │ 组成                                        根因：EDP 压力口渗漏
子部件                                               ▲ 导致
                                                     │
                                               工况：巡航阶段 / 高负载
```

- **部件树**来自 IPC（L1），确定性、准确、层次深
- **故障树**来自 FIM/TSM（L2），同样是确定性的，但**是 OEM 的通用树**

### 4.2 缝合点：`发生于` ⭐

两棵树本来互不相通，靠这条关系缝合：

```
(故障模式) ──发生于──► (部件)
(故障原因) ──发生于──► (部件)
```

缝合后能问出的真正有用的问题：

| 业务问题 | 图上路径 |
|---|---|
| "29-11341 最常见的原因是什么？"（**本机队口径**） | 故障码 → 故障模式 →（表现为逆）→ 根因，按本机队工单频次排序 |
| "ATA 32 起落架失效会影响哪些功能？" | 系统 →（组成下溯）→ 部件 →（发生于逆）→ 故障模式 |
| "这个件在机队上坏过几次？MTBUR 多少？" | 部件 →（发生于逆）→ 故障模式 + 边上的统计属性 |
| "换这个件，可用件号有哪些？能不能互换？" | 部件 →（适用于逆）→ 航材 →（互换）→ 互换件 |
| "这个件有没有 AD 要求？" | 部件 →（受控于）→ 适航文件 |
| "这个故障能不能保留放行？MEL 哪一条？" | 故障模式 →（MEL 条目）→ 手册 + 保留类别 |

### 4.3 完整推理路径（5 跳示例）

```
[CMS 故障码 29-11341 · ATA 29 · CAUTION · 巡航阶段]
   │ 上报代码
   ▼
[故障模式：HYD SYS B PRESS LOW] ──MEL 条目──► [MEL 29-20-1 · B 类 · 3 日历日]
   │ 表现为（逆）
   ▼
[根因候选] ① EDP 压力口渗漏（本机队 43 次 · PageRank 0.0052）
           ② 压力传感器故障（本机队 11 次 · PageRank 0.0031）
           ③ 系统 B 油箱低油量（本机队 8 次）
   │ 发生于
   ▼
[部件：液压泵 PN:65-90751-4 · ATA 29-21 · MTBUR 目标 8000FH]
   │ 组成（逆，上溯）
   ▼
[系统：ATA 29 液压] ──包含系统（逆）──► [机型：B737-800]
   │
   ├── 发生于（逆）──► 该机型历史故障模式
   │                       │ 采取措施
   │                       ▼
   │                   [更换 EDP 压力口封严]（根治 · AMM 29-21-00/401 · 3.5h）
   │                       ├── 需要 ──► [封严件 PN:MS28775-222]（PVG 库存 5 件）
   │                       │                └── 互换 ──► [PN:MS28775-111]
   │                       ├── 需要 ──► [液压油 BMS3-11]
   │                       └── 引用 ──► [AMM 29-21-00/401]
   │
   ├── 受控于 ──────► [SB 737-29-1123]（是否已有改进件？是否可执行终止措施？）
   │
   └── 记录于（逆）──► [历史 NRC 工单]（含验证方式、是否 NFF、实际工时）
```

> 这条路径跨 **5 跳、两棵树、六类数据源**。
> 纯向量检索做不到，SQL JOIN 写不出来 —— 这是图谱价值的直接证明。

## 5. 本体清单

### 5.1 本体类别

**`民航维修领域本体`**（一个本体类别 = 一套完整 schema，可按机型系列分知识库，如 B737 系列 / A320 系列）

### 5.2 本体分类（类别内分组）

| 分类 | 说明 | 数据来源 |
|---|---|---|
| 航空器结构类 | 机队、航空器、ATA 系统、LRU 部件、监控参数 | **IPC + 构型（L1）** |
| 故障类 | 故障代码、故障模式、故障原因、故障征兆、工况 | **CMS 码字典（L1）+ FIM（L2）+ 工单抽取（L3）** |
| 维修类 | 维修措施、航材、工装工具、维修工单、MEL 保留 | **FIM（L2）+ 工单抽取（L3）+ 航材表（L1）** |
| 适航文件类 | 适航文件（AD/SB）、手册、厂商、人员、维修站 | **AD/SB 清单 + 手册（L1/L2）** |

> **启用策略**：共 20 个本体，v1 **启用 16 个核心本体**；
> `监控参数`、`故障征兆`、`工装工具`、`运行影响` 4 个按需启用（它们会显著增加图规模，且不是排故主路径的必需）。

## 9. 典型查询模式

| # | 模式 | 起 → 止 | 跳数 | 业务问题 |
|---|---|---|:--:|---|
| **Q1** | **根因推理**（自下而上） | 故障码/现象 → 根因 | 2~4 | "29-11341 最常见的原因是什么？" |
| **Q2** | **影响面分析**（自上而下） | ATA 系统 → 故障模式 | 2~3 | "ATA 32 起落架问题会导致哪些故障？" |
| **Q3** | **相似案例检索**（横向） | 故障模式 → 相似故障 | 1~2 | "A321 上有没有类似的处理过？" |

## 10. 关键决策点（需确认）

1. **`装于` 指向机型还是单机**？建议 **机型** —— 单机装机清单会让边数暴涨（200 架 × 数千件），且可靠性分析通常是机型口径。单机差异通过工单的 `发生于航空器` 表达。✅/❌
2. **故障模式与故障原因是否分开**？建议 **分开** —— 现象层与根因层是双树设计的基础，合并会丢失因果方向。✅/❌
3. **NFF 是否作为工单处理结果的枚举值**？建议 **是** —— 这是降 NFF 率的唯一数据基础，成本极低价值极高。✅/❌
4. **MEL保留是否独立成实体**？建议 **是** —— 它有生命周期（开保留 → 到期 → 关闭/超期），需要工作流盯。✅/❌
5. **v1 是否启用 4 个可选本体**（监控参数/故障征兆/工装工具/运行影响）？建议 **延后** —— 它们显著增加图规模，但不在排故主路径上。✅/❌
6. **是否按机型系列分知识库**？建议 **是**（B737 系列 / A320 系列各一个 KB），便于权限隔离与本体微调；跨机型迁移通过图嵌入实现（见 [03 §2.4](./03-图计算设计.md)）。✅/❌
7. **一期范围**：单一航司，不做多航司共享图谱。✅/❌

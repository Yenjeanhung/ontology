# 场景四：生物医学与药物重定位图谱

> 状态：**概要** —— 未展开为实施设计。

---

## 0. 一句话

从 PubMed 等海量文献中按本体约束抽取疾病、药物、靶点、基因、通路之间的相互作用，构建生物医学知识图谱，用**链接预测**寻找「老药新用」候选假设，交领域专家审核。

**推荐理由**：这是图计算（尤其知识图谱补全 / 链路预测）在学术界与工业界**价值天花板最高、最被认可**的应用方向，也是公开数据量最大的领域。

---

## 1. 数据源与量级

| 数据源 | 类型 | 量级 | 入库方式 |
|---|---|---|---|
| PubMed 摘要 | 非结构化英文文本 | 3000 万+，日增数千 | **LLM 约束抽取（主战场）** |
| DrugBank | 结构化 | 万级药物 | ETL 直入 |
| FAERS 不良反应报告 | 半结构化 | 千万级报告 | ETL + 统计聚合 |
| ClinicalTrials.gov | 半结构化 | 40 万+ 试验 | ETL 直入 |
| KEGG / GO / Reactome 通路 | 结构化 | 十万级关系 | ETL 直入 |
| 蛋白互作（STRING/BioGRID） | 结构化 | 千万级边 | ETL 直入 |
| 基因疾病关联（DisGeNET） | 结构化 | 百万级 | ETL 直入 |

图规模：节点千万级（基因/蛋白/化合物/疾病/文献），关系边**亿级** → **明确需要分布式图计算框架**。

---

## 2. 本体骨架（草案）

| 本体 | 关键属性 |
|---|---|
| 疾病 | MeSH/DOID 编号、名称、分类、流行病学 |
| 药物 | DrugBank ID、名称、类型（小分子/生物药）、适应症、状态 |
| 靶点 | UniProt ID、名称、类型（受体/酶/离子通道） |
| 基因 | Gene ID、符号、染色体位置 |
| 蛋白 | UniProt ID、名称、功能 |
| 通路 | 通路 ID、名称、所属数据库 |
| 不良反应 | MedDRA 术语、名称、严重程度 |
| 临床试验 | NCT 编号、阶段、状态、入组数 |
| 文献 | PMID、标题、年份、期刊 |

**关系**：`治疗` `靶向` `作用于(激活/抑制)` `引起(不良反应)` `相互作用` `共表达` `参与通路` `编码` `关联(基因-疾病)` `见于(试验-疾病)` `报道于`

---

## 3. 图计算算法映射

| 算法 | 业务问题 |
|---|---|
| **链接预测 / 知识图谱补全** ⭐ | 哪些「药物-疾病」对在结构上高度暗示却尚未被报道？→ **药物重定位假设** |
| **元路径（Metapath）分析** | 药物-靶点-通路-疾病 的路径打分与可解释性证据链 |
| **社区发现** | 疾病模块、蛋白复合物、功能模块划分 |
| **图嵌入（FastRP / node2vec）** | 药物功能相似性、靶点相似性 |
| **中心度** | 枢纽基因、关键靶点（多疾病共有） |
| **子图匹配** | 已知的「药物-靶点-疾病」模式在新实体上的匹配 |

> **设计要点**：链接预测产出的候选必须走 `relation_suggestions` 审核闭环，
> 且**必须附证据链**（共同邻居、元路径、支持文献 PMID），否则科研人员不会采信。

---

## 4. 工作流闭环

```
[定时节点] 每周日凌晨
    │
    ▼
[爬虫节点] PubMed 增量（按 MeSH 词表订阅）
    │
    ▼
[实体服务节点] 本体约束抽取 → 图谱
    │
    ▼
[图计算节点] 链接预测 → 候选「药物-疾病」对（Top-N）
    │
    ▼
[LLM 节点] 生成假设 + 汇总支持文献证据
    │
    ▼
[人工节点] 科研专家审核（approve 模式）
    ├─ 通过 → [实体服务节点] 入库为「假设」关系（标注来源=预测，非文献实证）
    └─ 拒绝 → 写 tombstone，不再推荐
```

> **关键护栏**：预测出的关系入库时**必须标注 `source = predicted`**，
> 与 `source = literature`（文献实证）严格区分，避免污染图谱的可信度。

---

## 5. 契合度与风险

| 维度 | 评价 |
|---|---|
| 本体约束 | ★★★★★ 本体体系成熟（MeSH/UMLS/DOID），约束定义有据可依 |
| LLM 抽取 | ★★★★★ 主战场，文献抽取是经典难题 |
| 图谱 | ★★★★★ 关系最密集 |
| 工作流 | ★★★★☆ 定时 + 人工审核闭环 |
| 图计算 | ★★★★★ 链接预测的王牌应用 |
| 图计算框架 | **亿级边，GraphX/Plato 有真实必要性** |

**风险**

1. **语料是英文为主** —— 当前 `bge-small-zh-v1.5` 是中文 embedding，需换多语言模型（如 `bge-m3` / `multilingual-e5`）。
2. 领域术语密集（基因符号、化合物名），对 LLM 抽取与实体对齐要求高，需引入 UMLS/MeSH 词典做实体标准化。
3. **表述合规**：输出是「研究假设」，**绝不可宣称疗效或给出用药建议**。
4. 文献全文多数有版权，只能取摘要，证据链强度受限。

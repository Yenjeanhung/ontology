# 场景八：民航航班运行监控图谱

> 状态：**已落地，演示可用** —— 定义层、实例层、运行时层全部种子化，函数 / 派生属性 / 工作流 / 定时计划已实测通过。
> 日期：2026-09-09
> 一句话：**以航段为核心、OOOI 里程碑为骨架，把 CDM/ACARS 的滚动预计时间变成图上可实时计算的派生属性，让运行监控从"盯表格"变成"图上推演 + 大模型简报"。**

---

## 与场景二（民航维修）的关系

同为民航，视角互补：**维修看"机"（这架飞机哪里坏了），运行看"航班"（这个航班现在怎么样、会不会延误）**。两个场景共享航司自有数据与民航术语体系；本体编码已做图标签隔离（机型 `OpsAircraftType`、航空器 `OpsAircraft` 加 `Ops` 前缀），可共存于同一系统而不串图。

| 维度 | 场景二：民航维修根因 | 场景八：航班运行监控（本场景） |
|---|---|---|
| 核心对象 | 部件 LRU / 故障模式 / 工单 | 航段 FlightLeg（按日期拆分的执行实例） |
| 图骨架 | IPC 部件树 + FIM 故障树双树缝合 | OOOI 生命周期事件链（时序图） |
| 数据形态 | 半结构化手册 + 工单文本（LLM 抽取刚需） | **几乎全结构化**（CDM/ACARS 消息直接入图） |
| 系统能力侧重 | 本体约束抽取 + 多跳根因推理 + 图计算 | **运行时层**：函数实时计算 + 派生属性 + 工作流闭环 + 定时调度 |

> 本场景是「**结构化导入 + 运行时层**」路线的完整样板：不依赖 LLM 抽取，四条种子命令即可从零复现一个 3.8 万实体 / 10.5 万关系的可演示系统。

---

## 为什么适合这套系统

| 判据 | 本场景表现 |
|---|---|
| **关系密度 + 多跳需求** | 航段 → 状态事件链（16 节点时序）→ 机位/跑道/机组；航段 → 衔接前序 → 延误传播链；延误 → 异常 → 备降机场。"这架飞机上一段延误对本段的影响"天然是 2~4 跳查询 |
| **数据可得性** | 全部航司自有：CDM/A-CDM 机场协同、ACARS 下行、OMIS 运行系统；种子数据按国航 CA 航班号合成，字段口径对齐真实 CDM 报文 |
| **工作流闭环刚需** | 运行监控本质是"**定时批量计算 + 阈值触发 + 简报推送**"——正好是 函数 / 派生属性 / 工作流 / 定时计划 四件套的原生场景 |
| **时间敏感性** | ETD/ETA 随态势滚动更新，要求"计划一改、读取即新值"——派生属性**读时模式**原生满足，无需触发器 |

## 核心模型

```
   航班 Flight（MU5137）                    按日期拆分（同一航班号每天一个执行实例）
        │ 拆分航段
        ▼
   航段 FlightLeg ◄──────── 运行监控核心对象，携带全生命周期里程碑时间
        │                    SOBT/SIBT（计划）  ETD/ETA（预计，滚动更新）
        │                    AOBT/ATOT/ALDT/AIBT（实际，OOOI 四节点）
        │
        ├─ 产生事件 ──► 航段状态事件链（16 类，event_seq 时序相连）
        │                 计划发布 → 登机 → 关门 → 撤轮档(Out) → 滑出 → 起飞(Off)
        │                 → 爬升 → 巡航 → 下降 → 进近 → 落地(On) → 滑入 → 挡轮档(In)
        │                    │发生于机位         │发生于跑道
        │                    ▼                    ▼
        │                   机位 Stand           跑道 Runway
        │
        ├─ 衔接前序 ──► 上一航段（同一架飞机过站衔接，延误沿此边传播）
        │
        ├─ 产生延误 ──► 延误记录（民航局口径原因分类：天气/航司/空管/旅客…）
        │                 │源于异常
        ├─ 发生异常 ──► 异常事件（取消/返航/备降/复飞/空中等待…）──备降于──► 机场
        │
        ├─ 触发告警 ──► 运行告警（撤轮档超时/滑出过长/空中延误超阈值…）
        │
        ├─ 出发于/到达于 ──► 机场（PEK/SHA/PVG…，IATA/ICAO 双码）
        ├─ 计划机型 ──► 机型（A320neo/B737-800/C919）
        ├─ 执飞航空器 ──► 航空器（注册号 B-****，属机型）
        └─ 由机组执飞 ──► 机组（机长/副驾驶/乘务长）
```

**派生属性视角**：航段的时间字段就是"原料"——`预计飞行时长 = ETA−ETD`、`起飞延误 = ETD−SOBT`、`到达延误 = ETA−SIBT`、`当前运行阶段 = now 与 OOOI 里程碑比较`。计算逻辑沉淀为**本体函数**，航段自动获得这 4 个实时属性。

## 交付物

四个脚本全部位于 `backend/scripts/`，按层递进、每层可独立重建：

| 脚本 | 层 | 内容 |
|---|---|---|
| `flight_ops_domain.py` | 领域定义（纯数据） | 类别/本体/属性/关系/约束/模板的全部定义，两个种子脚本共用 |
| `seed_flight_ops_ontology.py` | 定义层 | 类别「民航航班运行监控本体」：**12 本体 / 87 属性 / 21 关系 / 21 三元组约束 / 4 属性模板** |
| `seed_flight_ops_entities.py` | 实例层 | 知识库「航班运行监控图谱（种子数据）」：**37,769 实体 / 105,073 关系**（145 航班 × 14 天 ≈ 2,030 航段，随机种子固定可复现） |
| `seed_flight_ops_runtime.py` | 运行时层 | **4 本体函数 / 4 派生属性 / 2 工作流 / 1 定时计划**（详见 [02-运行时层设计](./02-运行时层设计.md)） |

---

## 快速开始

```bash
cd backend
python scripts/seed_flight_ops_ontology.py          # 1. 定义层（本体/关系/约束）
python scripts/seed_flight_ops_entities.py          # 2. 实例层（全量 14 天；加 --small 为 8航班×2天 小样）
python scripts/seed_flight_ops_runtime.py           # 3. 运行时层（函数/派生属性/工作流/定时计划）
python scripts/seed_flight_ops_runtime.py --verify  # 4. 挑一个航段实体验证派生属性计算
```

重建任意一层：加 `--force`（各脚本按 名称/编码 精准清理自己的数据，不碰其他类别）。

## 术语速查

| 缩写 | 全称 / 中文 | 说明 |
|---|---|---|
| **OOOI** | Out / Off / On / In | 撤轮档 / 起飞 / 落地 / 挡轮档 四个生命周期里程碑 |
| **SOBT / SIBT** | Scheduled Off/In-Block Time | 计划撤轮档 / 挡轮档时间（即 STD/STA） |
| **ETD / ETA** | Estimated Off/In-Block Time | 预计撤轮档 / 挡轮档时间，随运行态势**滚动更新** |
| **AOBT / ATOT / ALDT / AIBT** | Actual … | 实际 OOOI 四时间 |
| **CDM / A-CDM** | Collaborative Decision Making | 机场协同决策机制，预计时间的主要来源 |
| **ACARS / ADS-B** | 飞机通信寻址与报告系统 / 广播式自动相关监视 | 实际时间与位置下行来源 |
| **OCC / AOC** | Airline Operations Center | 航空公司运行控制中心，本场景的目标用户 |
| **过站（turnaround）** | | 同一飞机落地到下次撤轮档的地面保障时段，「衔接前序」关系即描述此衔接 |
| **备降 / 复飞 / 空中等待** | Diversion / Go-around / Holding | 三类常见异常事件，种子数据均有注入 |

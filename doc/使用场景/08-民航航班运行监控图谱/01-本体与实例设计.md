## 1. 定义层总览

类别：**民航航班运行监控本体**（面向航空公司运行控制 OCC/AOC 与航班全生命周期状态监控）。

12 个本体按业务语义分五组（颜色用于图谱可视化区分）：

| 组 | 本体 | 编码 | 一句话 |
|---|---|---|---|
| 航班运行核心类 `#5470c6` | 航班 | `Flight` | 航班号层面的计划对象（如 MU5137），按日期派生航段实例 |
| | **航段** ⭐ | `FlightLeg` | 某日某航班的执行实例，运行监控核心对象，携带 OOOI 全里程碑时间 |
| | 机场 | `Airport` | IATA 三字码 / ICAO 四字码唯一标识（PVG/ZSPD） |
| | 机型 | `OpsAircraftType` | A320neo / B737-800 / C919（`Ops` 前缀与维修域图标签隔离） |
| | 航空器 | `OpsAircraft` | 具体一架执行飞机，注册号（B-1234）唯一标识 |
| 运行状态事件类 `#ee6666` | **航段状态事件** ⭐ | `LegStatusEvent` | 16 类生命周期节点，同航段事件按 `event_seq` 串成时序链 |
| 延误异常类 `#fac858` | 延误记录 | `DelayRecord` | 出发/到达延误，民航局统计口径原因分类 |
| | 异常事件 | `AbnormalEvent` | 取消/返航/备降/复飞/空中等待/中断起飞/滑回 |
| 监控告警类 `#91cc75` | 运行告警 | `OpsAlert` | 撤轮档超时/滑出过长/过站不足/延误超阈值/衔接冲突/状态失联 |
| 保障资源类 `#73c0de` | 机位 | `Stand` | 廊桥位/远机位，撤轮档与挡轮档的发生位置 |
| | 跑道 | `Runway` | 36L/18R，起飞与落地的发生位置 |
| | 机组 | `Crew` | 机长/副驾驶/乘务长，机型资质与飞行小时 |

**规模**：本体 12 / 属性 87 / 关系 21 / 三元组约束 21 / 属性模板 4（模板属性 12，绑定 8 条）。

## 2. 核心本体：航段（FlightLeg）属性字典

18 个属性，按业务语义分四段——**计划 → 预计 → 实际（OOOI）→ 态势**：

| 属性 | 编码 | 类型 | 必填 | 说明 |
|---|---|---|:--:|---|
| 航段号 | `leg_no` | string | ✅ | 业务主键：`航班号-日期-序号`，如 `MU5137-20260908-01` |
| 航班日期 | `flight_date` | date | ✅ | 计划撤轮档日期（本地），运行监控业务日期 |
| 航班号 | `flight_no` | string | ✅ | |
| 出发机场 / 到达机场 | `dep_airport` / `arr_airport` | string | ✅ | IATA 三字码 |
| 计划撤轮档时间 | `sobt` | datetime | ✅ | SOBT/STD |
| 计划挡轮档时间 | `sibt` | datetime | ✅ | SIBT/STA |
| **预计撤轮档时间** | `etd` | datetime | | ETD，随运行态势**滚动更新**（延误航段才有值） |
| **预计挡轮档时间** | `eta` | datetime | | ETA，同上 |
| 实际撤轮档时间 | `aobt` | datetime | | **OOOI-Out** |
| 实际起飞时间 | `atot` | datetime | | **OOOI-Off** |
| 实际落地时间 | `aldt` | datetime | | **OOOI-On** |
| 实际挡轮档时间 | `aibt` | datetime | | **OOOI-In** |
| 当前状态 | `leg_status` | string | | 计划/登机/撤轮档/滑出/起飞/巡航/下降/进近/落地/滑入/挡轮档/到达/取消/备降/返航 |
| 巡航高度 | `cruise_altitude` | number | | 米（FL350 ≈ 10668） |
| 计划过站时长 | `sched_turnaround_min` | number | | 本段到达至下段撤轮档的计划过站时间（分钟） |
| 旅客数 | `pax_count` | number | | |
| 数据来源 | `data_source` | string | | CDM / A-CDM / ACARS / ADS-B / OMIS / 人工 |

> 时间字段的三态设计（计划 SOBT / 预计 ETD / 实际 AOBT）是整个运行时层的原料：派生属性用"预计−计划"算延误、用"预计−预计"算时长、用 now 与实际时间比推断阶段。详见 [02-运行时层设计](./02-运行时层设计.md)。

其余本体的属性字典见 `flight_ops_domain.py` 的 `ATTRIBUTES`（每个属性均带中文 description，可直接支撑前端表单与 LLM 抽取 Prompt）。

## 3. 关系字典（21 条）

| 关系 | 编码 | 语义 | 逆向 |
|---|---|---|---|
| 拆分航段 | `HAS_LEG` | 航班 → 航段 | 属于航班 |
| 出发于 / 到达于 | `DEPARTS_FROM` / `ARRIVES_AT` | 航段 → 机场 | 出港/进港航段 |
| 计划机型 | `PLANNED_AC_TYPE` | 航段 → 机型 | 计划航段 |
| 执飞航空器 | `OPERATED_BY_AC` | 航段 → 航空器 | 执行航段 |
| 属于机型 | `OPS_BELONGS_TO_AC_TYPE` | 航空器 → 机型 | |
| 产生事件 | `HAS_EVENT` | 航段 → 状态事件 | 所属航段 |
| **后继事件** | `NEXT_EVENT` | 状态事件 → 状态事件（生命周期时序） | 前继事件 |
| 发生于机位 / 发生于跑道 | `AT_STAND` / `ON_RUNWAY` | 状态事件 → 机位/跑道 | |
| **衔接前序** ⭐ | `PRECEDING_LEG` | 航段 → 航段：同机过站衔接，**延误传播边** | 衔接后继 |
| 产生延误 | `HAS_DELAY` | 航段 → 延误记录 | 延误航段 |
| 发生异常 | `HAS_ABNORMAL` | 航段 → 异常事件 | 异常航段 |
| 备降于 | `DIVERTED_TO` | 异常事件 → 机场 | |
| 源于异常 | `CAUSED_BY_ABNORMAL` | 延误记录 → 异常事件（归因边） | |
| 触发告警 | `TRIGGERS_ALERT` | 航段 → 运行告警 | 告警航段 |
| 拥有机位 / 拥有跑道 | `HAS_STAND` / `HAS_RUNWAY` | 机场 → 机位/跑道 | |
| 撤轮档于 / 挡轮档于 | `OFF_BLOCK_AT` / `ON_BLOCK_AT` | 航段 → 机位（出发/到达机位） | |
| 由机组执飞 | `CREWED_BY` | 航段 → 机组 | 执飞航段 |

### 三元组约束（21 条）

`CONSTRAINTS` 将上述关系逐条约束为「源本体 → 关系 → 目标本体」，例如：

- `(航段, 出发于, 机场)`、`(航段, 到达于, 机场)` —— 机场关系只允许指向机场本体
- `(航段状态事件, 后继事件, 航段状态事件)` —— 时序链只能在事件之间
- `(延误记录, 源于异常, 异常事件)` —— 归因边不允许跨到资源类本体

本体约束抽取 / 结构化导入在此约束下入图，杜绝"延误记录——到达于→ 机场"这类脏边。

### 属性模板（4 个，绑定 8 处）

| 模板 | 属性 | 绑定到 |
|---|---|---|
| 时间区间属性 | 开始时间/结束时间/时长 | 延误记录、异常事件 |
| 监控数据溯源属性 | 数据来源/更新时间/可信级别 | 航段、航段状态事件 |
| 处置闭环属性 | 处理状态/处理人/处理时间/处理备注 | 延误记录、异常事件、运行告警 |
| 机场位置属性 | 所属机场/名称 | 机位、跑道 |

## 4. 实例层：种子数据设计

知识库：**航班运行监控图谱（种子数据）**。随机种子固定（`random.Random(42)`），两次生成结果完全一致、可复现。

### 4.1 生成策略

| 设计点 | 做法 |
|---|---|
| 航班规模 | 国航 CA 航班号 **145 个 × 14 个运行日**（2026-08-27 ~ 09-09）≈ **2,030 航段**；`--small` 生成 8 航班 × 2 天小样 |
| 状态推导 | 以数据快照时刻 **NOW = 2026-09-09 13:30** 为基准，按各航段计划/实际时间线推导当前状态（已到达/滑入/巡航/滑出/登机/计划/取消），保证时间线自洽 |
| 过站衔接 | **62 架航空器按日排班**，同机相邻航段建「衔接前序」（共 1,239 条）；上一段延误自然传播到下一段的预计时间 |
| 延误注入 | 按概率生成出发/到达延误（民航统计口径 ≥15 分钟计延误），ETD/ETA 仅对延误航段滚动更新（非延误航段为空 = 按计划） |
| 异常注入 | 取消、复飞、空中等待、备降（异常事件 →「备降于」机场），延误记录经「源于异常」归因 |
| 告警注入 | 撤轮档超时 / 空中延误超阈值 / 滑出时间过长，经「触发告警」挂到航段 |
| 事件链 | 每个航段按其时间线生成 16 类生命周期事件，`event_seq` 时序相连（「后继事件」边），地面节点挂机位、起降节点挂跑道 |

### 4.2 规模统计（实际生成结果）

**实体 37,769 条**：

| 本体 | 实体数 | 本体 | 实体数 |
|---|--:|---|--:|
| 航段状态事件 | 32,004 | 异常事件 | 51 |
| 延误记录 | 3,280 | 机位 | 48 |
| 航段 | 2,030 | 机组 | 40 |
| 航班 | 145 | 跑道 | 32 |
| 航空器 | 62 | 机场 | 16 |
| 运行告警 | 55 | 机型 | 6 |

**关系 105,073 条**：

| 关系 | 条数 | 关系 | 条数 |
|---|--:|---|--:|
| 产生事件 | 32,004 | 撤轮档于/挡轮档于 | 2,030 ×2 |
| 后继事件 | 29,974 | 拆分航段/出发于/到达于/计划机型/执飞航空器 | 2,030 ×5 |
| 发生于机位 | 14,006 | 衔接前序 | 1,239 |

### 4.3 分析图迁入

实例层脚本内置 `--sync-graph`：PG 写完后复用页面「图迁入」同一路径（`GraphSyncService.start_run` + UNWIND 批量写入，按 `category_id` 圈定隔离），把实例同步进 Neo4j 分析图并自动重建 GDS 投影，任务进度落在 `graph_sync_runs` 表。

## 5. 与场景二的本体隔离

维修域与运行域都有"机型/航空器"，图标签（Neo4j label）以本体编码生成。本场景编码加 `Ops` 前缀（`OpsAircraftType` / `OpsAircraft`），两个类别可共存同一 Neo4j 库而不串标签；`category_id` 圈定机制保证图迁入与查询按类别隔离。

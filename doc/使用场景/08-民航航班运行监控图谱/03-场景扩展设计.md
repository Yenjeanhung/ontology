## 0. 设计边界与三条扩展轴线

**硬约束（来自函数沙箱）**：函数在子进程沙箱执行，仅放行 `datetime` / `json`，入参只有本实体属性字典——
**凡需要"邻居实体"的计算，函数做不了**。因此本设计的分工是：

| 计算形态 | 承载方式 | 例子 |
|---|---|---|
| 单航段自足计算 | **本体函数 + 派生属性** | 时长/延误/等级/进度（本设计 A/B/C 三组函数） |
| 跨实体链路推理 | **工作流 HTTP 查实体/关系 + LLM** | 延误传播链分析（工作流 E） |
| 全量批量扫描 | **工作流串行物化 + 定时计划** | KPI 落库、当日态势日报（工作流 C/D） |

**三条扩展轴线**（现有 4 函数只覆盖"滚动预计"视角，本设计补齐另外三个运营视角）：

```
A 运行考核 KPI ── 航班正常性统计口径：正点率、延误分级、旅客影响、轮挡偏差
B 地面运行效率 ── OOOI 细分：滑出/滑入耗时，定位"空中准点、地面拥堵"
C 态势感知预警 ── 大屏/值班：飞行进度、到达倒计时、过站衔接冲突风险
```

**统一回退语义**（沿用 02 章口径，保证 2,030 航段"有值率最大化"）：

```
实际(A*) 缺失 → 预计(E*) → 计划(S*)   │  取消航段：仅返回性质明确的值（见各函数），其余返回 None
```

## 1. 新增函数（9 个）

### A 组：运行考核 KPI（民航统计口径）

| # | 函数 | 编码 | 逻辑 | 参数 | 确定性 | 空值语义 |
|:--:|---|---|---|---|:--:|---|
| 5 | 轮挡时长偏差 | `block_time_var_min` | 实际轮挡 `(AIBT−AOBT)` − 计划轮挡 `(SIBT−SOBT)`；实际缺失回退预计 `(ETA−ETD)` | 无 | ✅ | 取消 → None |
| 6 | 是否正点 | `on_time_flag` | 到达时刻（AIBT→ETA→SIBT 回退链）− SIBT < 15 分钟 → 1，否则 0（民航 ≥15 分钟计延误口径） | 无 | ✅ | 恒有值；取消 = 0 |
| 7 | 延误等级 | `delay_level` | 按预计到达延误分级：`严重≥60 / 中度≥30 / 轻度≥15 / 正点`；取消返回 `取消` | `late_min=15` `mid_min=30` `severe_min=60` | ✅ | 恒有值 |
| 8 | 受影响旅客数 | `pax_impact_count` | 取消或到达延误 ≥15 分钟时 = `pax_count`，否则 0 —— 服务/签派资源调配依据 | `late_min=15` | ✅ | 恒有值 |

> **为什么用三个函数分别算延误分级/正点/旅客影响而不互相调用**：沙箱函数之间不可复用，各自独立实现（几十行内），换来任一函数可单独挂派生属性、单独试算。

### B 组：地面运行效率

| # | 函数 | 编码 | 逻辑 | 参数 | 确定性 | 空值语义 |
|:--:|---|---|---|---|:--:|---|
| 9 | 滑出时长 | `taxi_out_min` | `ATOT − AOBT`；持续偏大 = 出港地面拥堵/流量管理 | 无 | ✅ | 未起飞 → None |
| 10 | 滑入时长 | `taxi_in_min` | `AIBT − ALDT`；持续偏大 = 进港滑行拥堵 | 无 | ✅ | 未落地 → None |

### C 组：态势感知与衔接风险

| # | 函数 | 编码 | 逻辑 | 参数 | 确定性 | 空值语义 |
|:--:|---|---|---|---|:--:|---|
| 11 | 衔接冲突风险 | `connection_risk` | 本段计划过站 `sched_turnaround_min`（预存属性）与参数最短过站比较，叠加自身预计延误：`衔接风险`（过站不足且自身已延误≥15）/ `过站紧张`（< 最短过站）/ `正常` / `—`（无前序，首班） | `min_turnaround=45` | ✅ | 恒有值 |
| 12 | 飞行进度 | `flight_progress_pct` | now 在 `[ETD, ETA]`（回退计划区间）线性插值 0~100；未起飞 0、已到达 100 | 无 | ❌ | 取消 → None |
| 13 | 到达倒计时 | `eta_countdown_min` | `ETA(回退 SIBT) − now`（分钟），负值 = 已超预计 | 无 | ❌ | 取消 → None |

> **`connection_risk` 的单实体近似**：真实衔接裕度 = 后继段 SOBT − 本段 ETA（跨实体，函数算不了）。近似口径：延误沿「衔接前序」边传播已经体现在本段 ETA 与预存计划过站时长里，"计划过站本就 < 最短标准，且本段还在延误扩大"即高传播风险——这是 OCC 席位常用的快速筛查口径；精确链路分析交给工作流 E。

## 2. 新增派生属性（9 个）

materialize_mode 按用途分流——**报表统计类落库直读，态势类读时保鲜**：

| 派生属性 | 编码 | 类型 | 绑定函数 | params | 模式建议 | 理由 |
|---|---|---|---|---|---|---|
| 轮挡时长偏差 | `block_time_var_min` | number | block_time_var_min | — | materialized | 日结统计、报表直读 |
| 是否正点 | `on_time_flag` | number | on_time_flag | — | materialized | 正点率聚合 |
| 延误等级 | `delay_level` | string | delay_level | `{"late_min":15,"mid_min":30,"severe_min":60}` | materialized | 列表着色/筛选/分布统计 |
| 受影响旅客数 | `pax_impact_count` | number | pax_impact_count | `{"late_min":15}` | materialized | 服务资源报表 |
| 滑出时长 | `taxi_out_min` | number | taxi_out_min | — | materialized | 机场地面效率分析 |
| 滑入时长 | `taxi_in_min` | number | taxi_in_min | — | materialized | 同上 |
| 衔接冲突风险 | `connection_risk` | string | connection_risk | `{"min_turnaround":45}` | virtual | 随 ETA 滚动即时变化 |
| 飞行进度 | `flight_progress_pct` | number | flight_progress_pct | — | virtual | 大屏刷新即新值 |
| 到达倒计时 | `eta_countdown_min` | number | eta_countdown_min | — | virtual | 倒计时必须实时 |

> 物化类属性由工作流 C 定时刷新（见下），virtual 类在实体详情页/`refresh=true` 时实时计算——与 02 章"读时/定时/按需"三分层完全一致。

## 3. 新增工作流（3 条）

### 工作流 C：运行 KPI 定时物化

把 6 个 materialized 派生属性批量落库（与工作流 A 同构，仅属性集合不同）：

```
start ──► http_mat_1 ──► ... ──► http_mat_6 ──► end(summary)
          轮挡偏差/正点/延误等级/旅客影响/滑出/滑入（POST /materialize/stream?limit=5000 串行）
```

### 工作流 D：当日运行态势日报（LLM）

**角度**：从"单航段简报"（工作流 B）升级到"全天候值班交接日报"。

```
start(run_date) ──► http_today ──► llm_daily ──► end(daily_report)
                  拉当日全部航段      生成态势日报
```

| 节点 | 配置要点 |
|---|---|
| `start` | 输入 `run_date`（默认 `TODAY`，格式 yyyymmdd） |
| `http_today` | `GET /api/entities?ontology_id={航段本体id}&q={{start.run_date}}&page_size=200` —— 航段实体名内嵌日期（`CA8248-20260910-01`），q 按名称即可精确圈定当日 ~145 个航段；返回 items 含已物化属性（延误等级/正点/旅客影响/衔接风险…） |
| `llm_daily` | system：`你是 AOC 值班经理，编写交接班运行日报`；prompt：从列表 JSON 中统计并输出 **① 状态分布（到达/取消/进行中）② 正点率与延误分级分布 ③ TOP5 预计到达延误航段（含旅客数）④ 衔接风险航段清单 ⑤ 建议关注的处置顺序**；只允许引用数据中存在的航段，不编造 |
| `end` | 输出 `daily_report = {{llm_daily.text}}` |

> 定时计划：每日 08:00 触发（`cron`/`daily`），与前一天夜航航班全部落地的时间窗吻合。

### 工作流 E：延误传播链处置简报（LLM + 图遍历）

**角度**：补齐函数做不了的**跨实体链路推理**——"这段延误会不会把后面的航班拖垮"。

```
start(entity_id) ──► http_leg ──► http_prev ──► llm_chain ──► end(advice)
                   本段属性+派生值   衔接前序/后继链    传播分析+调整建议
```

| 节点 | 配置要点 |
|---|---|
| `http_leg` | `GET /api/entities/{{start.entity_id}}/derived-properties?refresh=true`（复用工作流 B 口径） |
| `http_prev` | `GET /api/entities/{{start.entity_id}}` + 关系查询（`GET /api/relations`，按「衔接前序/衔接后继」过滤）取同机前后航段的 `sobt/etd/leg_status` |
| `llm_chain` | system：`你是 AOC 运行控制席，负责延误传播评估`；prompt：结合本段延误与前后段时刻，输出 **① 是否会吃掉后继段过站裕度（差额分钟数）② 连锁影响的后继段数量 ③ 建议动作（换机/调时/取消，附理由）**；无前序/后继时明确说明"链路终端" |
| `end` | 输出 `advice = {{llm_chain.text}}` |

> 触发方式：值班员在工作流页手动对风险航段运行；也可在工作流 D 的日报结论中人工接力执行。

## 5. 落地方式（三步，无代码改动）

1. **加函数**：`seed_flight_ops_runtime.py` 的 `FUNCTIONS` 追加 9 个定义（`code_text` 为沙箱代码字符串；`connection_risk/flight_progress_pct/eta_countdown_min` 记得 `is_deterministic=0`，同 `leg_phase` 的处理）；
2. **挂派生属性**：`DERIVED_PROPS` 追加 9 条，按第 2 节指定 `materialize_mode`（种子默认 virtual，物化类在工作流 C 首次物化后自动切换）；
3. **建工作流/计划**：`_workflow_c/d/e` 构造函数 + 两条定时计划，`python scripts/seed_flight_ops_runtime.py --force` 重建。

**验证清单**：

```bash
python scripts/seed_flight_ops_runtime.py --verify   # 扩展打印 9 个新属性试算值
# 抽查三类代表航段：
#   已到达延误段 CA8248  → block_time_var>0 / on_time_flag=0 / delay_level=中度 / taxi_out_min 有值
#   取消段             → delay_level=取消 / pax_impact=pax_count / progress=None
#   今日未执行段       → connection_risk 正常或紧张 / countdown 为正 / progress=0
```

**视角覆盖检查**（设计自检）：

| 运营问题 | 承载能力 |
|---|---|
| 这个航班现在怎么样？ | 工作流 B（单段简报）+ virtual 派生属性 |
| 今天整体怎么样？ | 工作流 D（态势日报）+ delay_level/on_time_flag 统计 |

| 指标什么时候更新？ | virtual 读时 / 60 分钟 KPI 物化 / 每日 08:00 日报 |

## 7. 风险与注意事项

| 风险 | 对策 |
|---|---|
| `q` 只匹配实体名称/描述（不搜属性值） | 航段名内嵌 yyyymmdd，工作流 D 用日期串搜索即可；勿依赖属性全文检索 |
| 工作流 E 的关系查询 API 参数需实现时确认 | `GET /api/relations` 已存在；实现时以 OpenAPI 实测为准，必要时改用两次实体查询近似 |
| 取消航段多函数分支 | 统一约定：`delay_level=取消`、`on_time_flag=0`、`pax_impact=pax_count`、时长/进度类返回 None |
| `eta_countdown_min` 对历史航段返回大负值 | 语义正确（已超预计 N 分钟）；大屏侧按 `leg_status` 过滤展示 |
| 物化属性与实体重建的时序 | 实体层重建后需重跑运行时层 `--force` 与工作流 C 首轮物化（同 02 章运维手册） |

## 8. 动作（编排模式）：用函数组合业务操作

已随 `seed_flight_ops_runtime.py` 种入 3 个**编排模式（flow）动作**，全部只组合种子函数、零业务代码（对应"动作=审+写、函数=算"的分工）：

| 动作 | code | 编排 | 用途 |
|---|---|---|---|
| 航班放行复核 | `leg.release.check` | `etd_delay_min` → 条件「延误 < 阈值(默认30min)」→ 假分支**中止**并提示转人工；真分支 → `leg_phase` → 写回 `leg_status=放行` | 值班员对风险航段做放行前复核，可撤销 |
| 航段运行快照 | `leg.snapshot` | 串行调 4 个函数 → 汇总输出飞行时长 / 起飞延误 / 到达延误 / 当前阶段 | 只读简报，不写数据 |
| 航班延误告警评估 | `leg.delay.alert` | `etd_delay_min` → `eta_delay_min` → 条件「起飞延误 ≥ 阈值(默认45min)」双出口：告警结论 / 正常结论 | 双分支输出演示，不写数据 |

- **入口**：实体详情（航段）→「实体服务」/ 动作面板执行；支持批量调用与撤销（写回型动作留有前像）。
- **重建**：`python scripts/seed_flight_ops_runtime.py --force`（动作随函数/派生属性一并清理重建）。
- 在服务编辑器「编排模式」打开可查看/修改画布，也可用「✦ AI 辅助（生成草图）」续写。

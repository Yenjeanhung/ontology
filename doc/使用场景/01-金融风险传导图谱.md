# 场景一：金融风险传导与企业关联图谱

> 状态：**概要** —— 未展开为实施设计。若确认做，参考 [02-装备运维故障根因图谱](./02-装备运维故障根因图谱/README.md) 的文档结构展开。

---

## 0. 一句话

用本体约束从公告/文书/工商数据中抽取企业与人的关系，构建关联图谱，用图计算识别担保圈、穿透持股比例、计算风险传导强度，最终接入工作流形成「监测 → 识别 → 人工研判 → 告警」闭环。

**推荐理由**：这是唯一能把 GDS 文档里写的四个能力（FastRP 嵌入、PPR、nodeSimilarity、链路预测）**全部用上**的场景，且每个算法都对应一个可解释的业务问题。

---

## 1. 数据源与量级

| 数据源 | 类型 | 量级（参考） | 获取方式 |
|---|---|---|---|
| 裁判文书 | 非结构化文本 | 亿级（公开） | 爬取 / 公开数据集 |
| 行政处罚 | 半结构化 | 千万级 | 公开 |
| 工商股权与任职 | 结构化 | 亿级边 | 采购 |
| 招股书 / 债券募集书 | 长文档 | 十万级篇 | 公开 |
| 上市公司公告 | 非结构化 | 日增数千 | 公开 |
| 招投标 | 半结构化 | 千万级 | 公开 / 采购 |
| 新闻舆情 | 非结构化 | 日增数万 | 爬取 |
| 债券违约与评级 | 结构化 | 万级 | 采购 |

图规模估算（区域行 / 单一机构视角）：企业 + 自然人节点千万级，股权/担保/任职/交易关系边**千万至亿级** → **超过单机 GDS 舒适区，GraphX/Plato 有真实必要性**。

---

## 2. 本体骨架（草案）

### 实体类型

| 本体 | 关键属性 |
|---|---|
| 公司 | 统一社会信用代码、名称、注册资本、成立日、行业、地域、状态 |
| 自然人 | 姓名、证件号（脱敏）、身份标签 |
| 金融机构 | 机构类型（银行/信托/券商/基金/保险）、牌照 |
| 金融产品 | 产品类型、规模、发行方、到期日 |
| 行业 | 行业代码、层级 |
| 地域 | 行政区划、层级 |
| 事件 | 事件类型（处罚/诉讼/股权变更/债券违约/评级下调/被执行）、金额、日期、状态 |

### 关系类型

`持股` `担保`（含保证/质押/抵押/差额补足的归一化）`任职于` `实控` `供应给` `采购自`
`共同借款` `涉诉` `被处罚` `发行` `投资于` `同址` `同电话` `经办`

> **本体约束的必要性强证据**：无约束时 LLM 会把「质押」「保证」「抵押」「差额补足」抽成一堆五花八门的关系类型；有本体约束后才能稳定归一到 `担保`，这是穿透分析能做的前提。

## 3. 图计算算法映射

| 算法 | 业务问题 | 输出形态 |
|---|---|---|
| **社区发现（Louvain / LPA）** | 哪些企业构成担保圈 / 系族？ | 企业簇标签，圈内风险敞口 |
| **PageRank / Betweenness** | 谁是系统重要性节点？谁是关键控制人？ | 重要性排行 |
| **PPR（Personalized PageRank）** | 从某违约企业出发，风险最可能传导到谁？ | 传导强度排序 |
| **加权最短路径** | A 对 B 的实际穿透持股比例是多少？ | 穿透比例（乘积累加） |
| **环路检测** | 是否存在循环担保 / 循环交易？ | 环路子图（财务造假强信号） |
| **链接预测（nodeSimilarity / 嵌入）** | 有无隐性的未披露关联？ | 隐性关联建议 → 人工审核 |
| **连通分量** | 单一违约事件的最大影响范围 | 风险敞口边界 |

> 链接预测产出的「隐性关联建议」可直接复用 GDS 文档里设计的 `relation_suggestions` + `relation_suggestion_tombstones` 两张表与审核闭环。

## 4. 工作流闭环

```
[定时节点] 每日 02:00
    │
    ▼
[爬虫节点] 抓公告 / 工商变更 / 处罚         ← 复用 crawl_service
    │
    ▼
[实体服务节点] 本体约束抽取入库              ← graph_extraction_service
    │
    ▼
[图计算节点] 重算社区 / PPR / 环路           ← 需新增 graph_compute 节点类型
    │
    ▼
[条件分支] 风险分 > 阈值 ?
    ├─ 是 → [人工节点] 风控员研判 → [通知节点] 企微/邮件告警
    └─ 否 → [结束] 静默归档
```

现有节点类型（`start` `end` `agent` `service` `llm` `condition` `code` `human`）中，
**图计算节点与通知节点目前缺失** —— 图计算可先用 `code` 沙箱节点调用，正式化建议新增 `graph_compute` 节点类型。

## 5. 契合度与风险

| 维度 | 评价 |
|---|---|
| 本体约束 | ★★★★★ 关系类型归一是刚需 |
| LLM 抽取 | ★★★★★ 主战场，非结构化文本占比极高 |
| 图谱 | ★★★★★ 多跳穿透是核心 |
| 工作流 | ★★★★★ 定时 + 条件 + 人工 + 通知全用上 |
| 图计算 | ★★★★★ 算法密度最高 |
| 图计算框架 | **> 5000 万边，GraphX/Plato 有真实必要性** |

**风险**

1. 工商股权、舆情数据需采购，成本不低；纯公开源可做但覆盖率打折。
2. 合规表述要谨慎 —— 定位为「风险线索提示工具」，**不要做成征信评分 / 授信决策**。
3. 穿透持股比例计算涉及多层持股与循环持股，需处理数值精度与环路。

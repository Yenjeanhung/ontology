# 场景五：司法类案检索与裁判要素图谱

> 状态：**概要** —— 未展开为实施设计。

---

## 0. 一句话

从海量裁判文书与法条中按本体约束抽取案件要素，构建「案件-法条-当事人-情节」图谱，用**图结构信号（同法条引用、同法院、同案由）增强类案相似度**，比纯向量检索更准。

**推荐理由**：数据完全公开、获取成本为零、规模足够大，且 LLM 约束抽取与图谱相似度计算在这里都有明确增益。

---

## 1. 数据源与量级

| 数据源 | 类型 | 量级 | 入库方式 |
|---|---|---|---|
| 裁判文书 | 半结构化长文本 | 亿级（公开） | **LLM 约束抽取** |
| 法律法规 / 司法解释 | 结构化条文 | 十万级条 | ETL 直入（条文天然有编号） |
| 指导性案例 | 非结构化 | 千级 | LLM 抽取 |
| 起诉状 / 答辩状 | 非结构化 | —— | LLM 抽取 |
| 合同文本 | 非结构化 | —— | LLM 抽取 |

图规模：案件节点千万级、法条十万级、当事人千万级，引用/相似/同案由关系边**千万至亿级** → 处于「单机 GDS 边缘」，大规模需分布式。

---

## 2. 本体骨架（草案）

| 本体 | 关键属性 |
|---|---|
| 案件 | 案号、案由、法院层级、审级、裁判日期、判决结果、标的金额 |
| 当事人 | 姓名/名称、类型（自然人/法人）、诉讼地位（原告/被告/第三人） |
| 法条 | 法律名、条、款、项、条文内容 |
| 罪名 / 案由 | 名称、分类、层级 |
| 法院 | 名称、层级、地域 |
| 法官 / 审判人员 | 姓名、法院、职务 |
| 律所 / 代理人 | 名称、类型 |
| 证据 | 证据类型、名称、采信情况 |
| 诉讼请求 | 类型、金额、支持情况 |
| 情节 | 情节类型（自首/立功/从犯/累犯/和解等）、认定情况 |

**关系**：`引用法条` `相似于` `上诉自` `代理` `同案由` `同当事人` `适用情节` `审理法院` `采信证据` `支持诉请`

---

## 3. 图计算算法映射

| 算法 | 业务问题 |
|---|---|
| **nodeSimilarity（Jaccard）+ 图嵌入** ⭐ | 类案相似度 —— 融合「引用同一法条」「同一法院」「同一案由」等结构信号，比纯文本向量更准 |
| **社区发现** | 系列案件识别（同一团伙、同一套路贷模式、同类型诈骗的手法簇） |
| **PageRank** | 高频引用法条、高影响力指导性案例 |
| **链接预测** | 本案还可能适用哪些法条？→ 法条适用推荐 |
| **中心度** | 某法条在哪些案由中处于枢纽位置 |

> **为什么图谱比向量强**：两个案由相同、引用法条高度重合的案件，
> 文字表述可能完全不同（纯向量会判为不相似），但结构上高度相似（图谱能识别）。
> 这正是本项目 OAG「向量 + 图谱融合」的价值所在。

---

## 4. 工作流闭环

```
[开始] 新案件要素录入
    │
    ▼
[智能体节点] OAG 融合检索类案（向量 + 图谱 + 图谱事实注入）
    │
    ▼
[条件分支] 最高相似度 >= 0.85 ?
    ├─ 是 → [LLM 节点] 生成裁判要素分析报告（附类案引用）
    └─ 否 → [人工节点] 律师补充检索条件 → 重跑
    │
    ▼
[人工节点] 律师审核（approve 模式）
    │
    ▼
[结束] 输出文书 / 归档
```

---

## 5. 契合度与风险

| 维度 | 评价 |
|---|---|
| 本体约束 | ★★★★☆ 案由/情节体系有官方分类可依 |
| LLM 抽取 | ★★★★★ 主战场，裁判文书要素抽取是典型任务 |
| 图谱 | ★★★★☆ 结构信号对相似度有明确增益 |
| 工作流 | ★★★★★ 检索 + 条件 + 人工审核闭环完整 |
| 图计算 | ★★★★☆ 相似度与社区是核心 |
| 图计算框架 | 单机 GDS 边缘；全量文书上图则需分布式 |

**风险**

1. **表述合规是红线**：定位为「类案检索与裁判要素分析工具」，
   **绝不可做成「量刑预测」「胜诉率预测」**，也不做判决结果推荐。
2. 裁判文书存在地域/年份分布偏差，需注意采样偏差导致的历史偏见放大。
3. 当事人姓名需脱敏处理，尤其自然人案件。

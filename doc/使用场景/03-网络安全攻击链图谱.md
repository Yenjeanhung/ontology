# 场景三：网络安全威胁情报与攻击链图谱

> 状态：**概要** —— 未展开为实施设计。

---

## 0. 一句话

把资产、漏洞、告警、攻击手法、威胁情报建成一张图，用路径分析还原攻击链、用社区发现识别同源团伙、用连通分量评估失陷范围，并接入自动化响应工作流。

**特点**：这是六个场景里**原始数据体量最大**的一个（日均告警百万条级），但也是**LLM 抽取必要性最低**的一个。

---

## 1. 数据源与量级

| 数据源 | 类型 | 量级 | 入库方式 |
|---|---|---|---|
| IDS / WAF / EDR 告警 | 结构化日志 | 日均百万条 | **ETL 直入，非 LLM** |
| NetFlow / DNS 日志 | 结构化 | 日均亿级 | 采样 / 聚合后入图 |
| 资产清单（CMDB） | 结构化 | 十万级 | ETL 直入 |
| CVE / CNVD 漏洞库 | 结构化 | 十万级 | ETL 直入 |
| ATT&CK 知识库 | 结构化 | 千级技术点 | ETL 直入 |
| 威胁情报 feed（IOC） | 半结构化 | 日增万级 | ETL + 轻解析 |
| 安全通告 / 分析报告 | 非结构化文本 | 万级篇 | **LLM 约束抽取** |

图规模：资产 + IP + 域名 + 漏洞 + 样本节点百万级，访问/利用/通信关系边**亿级** → **明确需要分布式图计算框架**。

---

## 2. 本体骨架（草案）

| 本体 | 关键属性 |
|---|---|
| 资产 | 资产编号、类型（服务器/终端/网络设备/容器）、操作系统、业务归属、暴露面、负责人 |
| IP / 域名 | 地址、归属、是否外网、解析记录 |
| 漏洞 | CVE 编号、CVSS 评分、影响组件、利用成熟度 |
| 攻击手法 | ATT&CK Technique ID、战术阶段、名称 |
| 恶意样本 | Hash、家族、类型、首次出现时间 |
| 攻击组织 | 名称、别名、归因地区、活跃时间 |
| 账号 | 账号名、权限级别、所属域 |
| 告警事件 | 告警 ID、时间、设备、规则名、原始等级、处置状态 |

**关系**：`存在漏洞` `利用` `访问` `属于` `C2通信` `同源` `提权至` `横向移动到` `外联至` `归属于(组织)` `对应技术(ATT&CK)` `命中规则`

---

## 3. 图计算算法映射

| 算法 | 业务问题 |
|---|---|
| **路径分析（加权最短路径 / 全路径枚举）** | 从外网入口到核心资产的攻击路径是哪条？ |
| **连通分量 / 可达性** | 一台主机失陷，横向扩散范围有多大？ |
| **社区发现** | 哪些主机属于同一僵尸网络？哪些告警属于同一团伙？ |
| **中心度（Betweenness / Degree）** | 哪台是关键跳板机？哪个账号权限过高？ |
| **图嵌入 + 离群检测** | 哪些主机行为模式异常（偏离其社区）？ |
| **子图匹配** | 是否命中已知的 ATT&CK 攻击链模式？ |

---

## 4. 工作流闭环

```
[事件触发] 告警接入 / 情报更新
    │
    ▼
[代码节点] 告警聚合去重 + 实体关联
    │
    ▼
[图计算节点] 路径分析 / 社区 / 可达性
    │
    ▼
[条件分支] 是否命中完整攻击链 ?
    ├─ 是 → [人工节点] 研判（form 模式：定性 / 定级 / 处置意见）
    │        → [代码节点] 下发阻断 / 隔离
    │        → [通知节点] 工单 + 告警
    └─ 否 → [LLM 节点] 生成告警摘要降噪 → [结束]
```

## 5. 契合度与风险

| 维度 | 评价 |
|---|---|
| 本体约束 | ★★★★☆ 本体稳定，但约束抽取的价值不如文本型场景 |
| LLM 抽取 | ★★☆☆☆ **大部分数据是结构化的，LLM 抽取不是必需品** |
| 图谱 | ★★★★★ 路径与连通性是刚需 |
| 工作流 | ★★★★★ 自动化响应闭环价值最高 |
| 图计算 | ★★★★★ 算法密度最高、最硬核 |
| 图计算框架 | **亿级边，GraphX/Plato 有真实必要性** |

**⚠️ 唯一的架构缺口（必须提前解决）**

现有 `graph_extraction_service` 是 **LLM 逐 chunk 抽取**，面向文档设计。本场景的数据绝大部分是结构化的（日志、资产表、CVE），**用不上这条链路**。

需要额外新增一条 **「结构化数据源 → 图谱」导入通道**：

```
StructuredImportService（新增）
  数据源适配器：CSV / JSON / 数据库直连 / 日志流
    → 列映射配置（哪一列是实体名、哪一列是实体类型、属性怎么取）
    → 实体对齐（与外部 ID 做 upsert 去重）
    → 复用 constraint_set 做三元组合法性校验
    → 复用 EntityService.create_relation 双写入库
```

LLM 在本场景只用在两处：**威胁情报报告摘要生成**、**研判结论的自动成文**。

> 这个缺口其他场景也部分存在（金融的工商数据、供应链的 BOM），
> 因此 `StructuredImportService` 是一个**通用能力**，建议立项时单独考虑。

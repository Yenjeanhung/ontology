# 知识库（Knowledge Base）

> 一句话定位：**系统的顶层组织容器**——文件、向量、图谱、本体绑定都挂在知识库下。创建知识库并绑定一个本体类别，就完成了"用谁的规矩来抽取"的设定。

知识库本身逻辑不复杂，但它是连接**本体定义**与**抽取执行**的枢纽，也是整个系统数据隔离的边界。

---

## 一、这个菜单做什么

| 能力 | 说明 |
|------|------|
| **知识库 CRUD** | 创建、列表、改名/描述、删除 |
| **本体绑定** | 绑定/换绑/解绑一个本体类别（决定抽取模式） |
| **状态总览** | 列表页一次拿全每个库的文件数、处理状态、整体进度 |
| **彻底回收** | 删库即级联清空向量库、图库、上传目录 |

---

## 二、核心概念：本体绑定

知识库与本体类别是**多对一**关系：多个知识库可共享同一个本体类别（如多个金融研报库都用"金融领域本体"），但**一个知识库同时只绑一个类别**。

**绑定决定抽取模式**（这是知识库最重要的语义）：
- 处理文件时调 `OntologyService.get_kb_extraction_constraints(db, kb_id)`；
- **有绑定** → 加载该类别下全部本体/属性/关系/三元组约束 → 动态生成约束 Prompt + 后处理校验（约束抽取）；
- **无绑定** → 自由抽取 + 自动反推候选本体（向后兼容）。

绑定关系存 `kb_ontology_bindings`（kb_id ↔ category_id，UNIQUE(kb_id)），换绑走"先删后插"。

---

## 三、按 kb_id 物理隔离（重要架构）

三个数据层都以 kb_id 为边界，互不污染：

```
知识库「金融研报」(kb_id=A)
├── SQLite: files/chunks/entities/relations 都带 kb_id=A
├── ChromaDB: collection_name = A      ← 整个 collection 独立
├── Kùzu: 所有节点带 kb_id=A 属性
└── 上传目录: uploads/A/
```

**删知识库 = 彻底回收**：`delete` 级联执行——删 `UPLOAD_DIR/{kb_id}` 目录 + `delete_kb_collection(kb_id)`（Chroma）+ `delete_kb_graph(kb_id)`（Kùzu）+ DB 行。无跨库污染、无残留。

---

## 四、列表页状态聚合

`list_all` 用 `selectinload(files)` 一次性加载，并为每个知识库聚合：
- file_count、file_types（后缀集合）；
- processing_files / pending_files / failed_files 计数；
- overall_progress（最大进度）。

**为什么这么做？** 避免 N+1 查询，前端列表页一次拿到全部状态，无需轮询单个文件。KB 详情页还含每个文件的完整处理 detail（分阶段进度 + 时间戳 + elapsed_ms）和 logs 尾部 120 条，抽取完成后回填 graph summary（entity_total/relation_total）。

## 五、关键 API（routers/kb.py）

| 方法 | 路径 | 作用 |
|------|------|------|
| POST | `/kb` | 建库 |
| GET | `/kb` | 列库（含状态聚合） |
| GET | `/kb/{id}` | 库详情 + 文件列表（含 detail/logs） |
| PUT | `/kb/{id}` | 改名/描述 |
| DELETE | `/kb/{id}` | 删库（级联清向量 + 图 + 目录） |
| GET/PUT/DELETE | `/kb/{id}/ontology` | 本体绑定/换绑/解绑 |

## 六、面试可讲的难点与亮点

1. **按 kb_id 三层物理隔离**
   Chroma collection、Kùzu 节点 kb_id 属性、上传目录三层隔离，删库即彻底回收。**为什么？** 多租户/多场景数据不能串库，隔离边界越靠底层越可靠。

2. **本体绑定可热插拔，同套代码两种行为**
   绑定与否决定抽取模式，且无绑定还有反推本体的兜底，用户体验顺滑。体现了"功能开关 + 优雅降级"的设计意识。

3. **列表页 selectinload 聚合，规避 N+1**
   一次查询拿全状态聚合，前端列表无需轮询单文件，性能与体验兼顾。

4. **删除的彻底级联**
   删一个知识库要同步清关系库(SQLite)、向量库(Chroma)、图库(Kùzu)、文件系统四处，任何一处遗漏都会留脏数据。这里的级联清理是数据一致性的关键工程点。

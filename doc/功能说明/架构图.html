数据层 · 三库分工
🟢 SQLite（权威元数据）
本体定义 11 表 · 实体/关系实例 · 知识库/文件 · 模型配置。实体/关系的权威存储。
🟠 ChromaDB（向量）
文本分片向量 · 按知识库分 collection · 相似度检索。
🌸 Kùzu（图数据库）
实体关系图谱 · MENTIONS/RELATES 边 · 可视化与图遍历 · OAG 图谱召回。

🔄 核心数据流水线（端到端主线）

"先定义本体规矩 → 建库绑定 → 上传抽取 → 治理 → 融合问答"
STEP 1
定义本体
本体类别 / 本体属性 / 关系字典 / 三元组约束
→
STEP 2
建库绑定
知识库绑定本体类别，决定抽取按谁的规矩
→
STEP 3
上传处理
解析 → 分块 → 向量化 → 约束抽取 → 双库写入
→
STEP 4
治理
实体编辑/合并 · 图谱清洗（去重去噪）
→
STEP 5
问答
纯向量 RAG 或 OAG 向量+图谱融合问答
🛡️
本体约束双保险
动态约束 Prompt + 代码后处理 O(1) 校验，保证图谱 schema 一致。
🔀
OAG 融合检索
向量 ∪ 图谱召回 → RRF 重排 → 注入图谱事实，推理过程可视化。
🔗
双库一致性
SQLite 权威 + Kùzu 同步，best-effort + 全局写锁，最终一致。
🧹
图谱清洗护栏
并查集合并 + 删除比例阈值 + 不删孤岛，避免误清空。
🧠
先抽取后建模
无本体也能用：自由抽取 → LLM 反推候选本体 → 审核回填。
🔌
可插拔架构
嵌入/向量/LLM/解析/图库 基于接口，配置即切换，业务零改。
🔑
模型配置热更新
多套 LLM 入库 · 单例 reset→rebuild · api_key 掩码哨兵。
📊
向量双源对账
业务表 × 向量库交叉校验，定位"解析成功但向量丢失"坏数据。

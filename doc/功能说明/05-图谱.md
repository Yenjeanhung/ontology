# 图谱（Graph）

> 一句话定位：**知识图谱的可视化与治理**——「图谱」菜单看实体关系的网络结构（基于 Kùzu 图数据库），「图谱清洗」子菜单用算法自动合并重复实体、删除噪声，让图谱保持干净可信。

图谱是 KnowSource 区别于纯文本 RAG 的结构化资产，也是智能体（OAG）能做"关系型问答"的数据基础。

---

## 一、这个菜单做什么

| 子功能 | 路由 | 说明 |
|--------|------|------|
| **图谱可视化** | `/graph` | 实体关系网络展示，支持过滤、按度数分页 |
| **图谱清洗** | `/graph-cleanup` | 重复实体合并、噪声实体删除、无语义关系清理 |

---

## 二、Kùzu 图模型（数据结构基础）

采用 **Reified 关系建模**——关系不是简单二元边，而是"关系节点 + 两条指向端点的边"，额外再建一条直连边方便遍历：

**节点表**：`KnowledgeBase / Document / Chunk / Entity / Relation`

**关系表（边）**：
| 边 | 含义 |
|----|------|
| `HAS_DOCUMENT` | KB → Document |
| `HAS_CHUNK` | Document → Chunk |
| `NEXT_CHUNK` | Chunk → Chunk（带 order_index，保留文档顺序） |
| `MENTIONS` | Chunk → Entity（分片提及实体，**OAG 图谱召回的关键**） |
| `HAS_RELATION` | Chunk → Relation |
| `RELATION_SOURCE` / `RELATION_TARGET` | Relation → Entity（关系的起点/终点） |
| `RELATES` | Entity → Entity（带 relation_id/relation_type，**直连边方便图遍历**） |

> **为什么这样建模？** 关系本身需要挂属性（relation_id/relation_type/来源 chunk），所以用节点承载；同时为高频的"实体邻居"查询建一条 RELATES 直连边，空间换时间。

## 三、图谱可视化

### 3.1 数据来源（`fetch_graph_view`）
按 `kb_id / file_id / entity_query / relation_type` 过滤，分 4 条 Cypher 并行取 Document、Chunk、MENTIONS、Relation，在 Python 侧按 chunk 聚合，拼装成前端要的 `{nodes, edges, records}`：
- 节点 id 形如 `document:xxx / chunk:xxx / entity:xxx / relation:xxx`；
- 实体节点按 entity_type 上色调色板（PERSON 红、ORG 蓝…）；
- entity_query 命中过滤：先收集命中实体 id 集合，再据此过滤 mentions 与 relation 行。

### 3.2 度数排序 + 分页（大图怎么渲染）
超大图不可能一次渲染，`GraphDataService.get_view` 的策略：
1. 取全量 records，统计每个 entity 的度数（作 source/target 次数）；
2. 按度数降序排，取 `[offset, offset+limit]` 的实体子集——**优先展示高关联的核心实体**；
3. 过滤 records 只保留选中实体及其间关系，重建 nodes/edges；
4. summary 回填 `entity_total / entity_shown / has_more`。

> 这是图谱可视化"大图渲染"的典型工程解：先按重要性分页，再重建诱导子图。

### 3.3 关系类型列表
`GET /graph/relation-types` 从 `MATCH (Chunk)-[:HAS_RELATION]->(Relation)` 去重返回，供前端按关系类型筛选下拉。

## 四、图谱清洗 ⭐ 重点

### 4.1 解决什么问题
LLM 抽取不可避免产生：
- (a) 同一实体的多种写法/重复抽取（"华为公司" vs "华为" vs "HUAWEI"）；
- (b) 日期/数值/整句等低价值噪声实体；
- (c) "涉及/提到/关联"等无语义通用关系。

清洗目标：**合并重复、删噪声、删无语义关系**。

### 4.2 两段式：只读建议 + 显式 apply
- **`suggest_cleanup`**：纯只读、确定性启发式，**不入库**。每次重算幂等，避免污染数据。
- **`apply_cleanup`**：前端审核（可改 canonical、取消勾选）后执行写库。

**为什么不直接自动清洗？** 图谱清洗不可逆，需 **human-in-the-loop**，让人拍板再落库。

### 4.3 清洗能力与算法

**① 重复实体合并建议**——按 `entity_type` 分组，组内两两算名称相似度（`difflib.SequenceMatcher.ratio() ≥ 0.72`），用**并查集（union-find，带路径压缩）** 聚簇。canonical 选"度数最高、并列取名字最短"。
- **防误合护栏**：`_are_distinct_products` 拆"品牌前缀 + 末尾型号编码"，品牌相同但型号不同（享界S9 vs 享界G9）视为不同产品不合并。
- **防爆栈护栏**：单类型 > 600 条跳过，规避 O(n²) 计算。

**② 噪声实体删除建议**——只对低价值实体名（空、>24 字疑似整句、含断句标点、命中日期/数值/URL/版本号正则）。
- **刻意不删孤岛节点**：删通用关系后大量实体会临时变孤岛，若再建议删孤岛，会在反复"全部清洗"时级联清空整张图。**孤岛交用户在实体页手动删**。

**③ 无语义关系删除建议**——关系类型命中黑名单（`GRAPH_GENERIC_RELATION_BLOCKLIST` 配置，逗号分隔）。

### 4.4 执行同步双库
`apply_cleanup` 复用 `EntityService.merge_entities / delete_entities / delete_relations`，自动 best-effort 同步 Kùzu。顺序：**先删关系、再删实体**，避免关系端点先于关系本身失效。

### 4.5 三道安全护栏
| 护栏 | 说明 |
|------|------|
| **删除比例阈值** | 单次清洗删除实体（含被合并的）或关系占比 > `GRAPH_CLEANUP_MAX_DELETE_RATIO`（默认 0.5）则整体中止并报错 |
| **先删后改顺序** | merge 内部先 flush 物理删重复/自环关系，再改存活端点，绕开唯一约束冲突 |
| **前端二次确认 + 分范畴执行** | ModalDialog 确认，支持"仅合并 / 仅噪声实体 / 仅无语义关系 / 全部"分范畴清洗，每项可勾选/改 canonical |

> 合并掉的实体也计入"待删数"，防止"用合并变相绕过删除比例护栏"。

## 六、关键 API

**routers/graph.py**：

| 方法 | 路径 | 作用 |
|------|------|------|
| GET | `/graph/relation-types` | 列关系类型（供筛选下拉） |
| GET | `/graph/view` | 图谱可视化主接口（nodes/edges/records/summary，过滤 + 度数分页） |

**清洗（注册在 routers/entity.py）**：

| 方法 | 路径 | 作用 |
|------|------|------|
| GET | `/graph-cleanup/suggestions` | 生成清洗建议（只读，不入库） |
| POST | `/graph-cleanup/apply` | 执行清洗（合并 + 删除，同步双库） |

## 七、面试可讲的难点与亮点

1. **「只读建议 + 显式 apply」两段式清洗，建议不入库**
   确定性启发式每次重算幂等，用户改完 canonical、勾选后才落库。**为什么？** 清洗不可逆，需 human-in-the-loop。

2. **并查集聚簇 + 型号编码防误合 + O(n²) 爆栈防护 三件套**
   抓住"同一实体多种写法"的核心，又用 `_are_distinct_products` 解决"享界S9 vs 享界G9"品牌同、型号异的误合痛点，用单类型上限 600 规避二次方爆炸。有领域考量的算法设计。

3. **「不删孤岛」的血泪教训**
   注释直写"曾导致数据全丢"。因果链：删通用关系 → 实体临时变孤岛 → 若再自动删孤岛 → 反复清洗级联清空。最终策略：孤岛非错误数据，只删低价值名，孤岛交用户手动。非常真实的数据安全反思。

4. **删除比例阈值护栏（默认 50%）**
   单次清洗删除占比超阈即中止并提示分批。把"误操作清空整图"的灾难性后果用硬编码比例卡死，比靠用户谨慎可靠。合并掉的实体也计入，防绕过。

5. **图谱视图的度数排序分页**
   超大图先全量统计度数，按重要性降序分页，重建诱导子图保证只展示选中实体子集。是"大图怎么渲染"的典型工程解。

6. **Reified 关系建模 + RELATES 直连边**
   关系用节点承载属性，同时为高频邻居查询建直连边，空间换时间，兼顾表达力与查询性能。

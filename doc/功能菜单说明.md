# KnowSource 项目功能菜单说明

> 本文档基于 [design.md](./design.md) 整理，说明 KnowSource 项目的功能菜单结构与各项功能用途。
> 标注 **【现有】** 为项目已有功能，**【新增】** 为本体管理功能设计新增的模块。

KnowSource 是一个基于 **RAG + 知识图谱** 的知识库系统（前端 Vue 3，后端 Python/FastAPI，图数据库 Kùzu）。项目通过本体管理约束实体/关系抽取，使知识图谱构建结果符合领域预期。

---

## 一、菜单总览

| 序号 | 菜单 | 主要页面 | 状态 | 一句话说明 |
|------|------|---------|------|-----------|
| 1 | 知识库 | 知识库列表 / 知识库详情 | 【现有】 | 知识库管理，组织文件与绑定本体 |
| 2 | 文件处理 | （知识库详情页内） | 【现有】 | 文件上传、分块、抽取实体与关系 |
| 3 | RAG 问答 | 问答界面 | 【现有】 | 基于知识库的检索增强问答 |
| 4 | 知识图谱 | 图谱可视化 / 图查询 | 【现有】 | 实体关系图谱展示与图遍历 |
| 5 | 向量管理 | 向量索引管理 | 【现有】 | 向量数据维护 |
| 6 | 本体管理 | 本体类别列表 / 详情（四 Tab） | 【新增】 | 本体定义与抽取约束管理 |
| 7 | 属性模板 | 模板列表 | 【新增】 | 跨领域共性属性复用 |
| 8 | 实体管理 | 实体列表 / 详情 / 关系实例 | 【新增】 | 抽取后的实体/关系实例浏览与编辑 |

> 新增菜单建议放在"知识库"菜单旁边或下方（见 [design.md 6.3](./design.md)）。

## 二、现有功能菜单

### 1. 知识库 【现有】

知识库是系统的顶层组织单元，文件、向量、图谱、本体约束均挂在知识库下。

- **知识库列表**：创建/删除/搜索知识库
- **知识库详情页**（`KbDetail.vue`）：
  - 组织该知识库下的文件
  - **本体设置区域**【新增补充】：显示当前绑定的本体类别名称，提供可搜索下拉选择本体类别 / 解绑（组件 `OntologyCategorySelect.vue`）。已绑定时展示该本体类别的本体/关系/三元组概要（只读），便于确认约束范围
  - 文件处理按钮旁显示本体绑定提示

### 2. 文件处理 【现有】

位于知识库详情页内，不单独成菜单。

- **文件上传**：上传文档到知识库
- **文件处理**（`POST /api/files/{fileId}/process`）：
  - 文件分块
  - **实体/关系抽取**：根据知识库绑定的本体类别，动态构建 Prompt（含本体属性与三元组约束）交给 LLM 抽取
  - **后处理校验**：过滤不在本体列表中的实体类型、不匹配三元组的关系；属性类型规整
  - 校验通过后写入 SQLite `entities`/`relations` 并同步 Kùzu
- **无本体绑定时**：保持原有行为（固定类型参考，无硬约束），完全向后兼容

### 3. RAG 问答 【现有】

基于知识库的检索增强问答，结合向量检索与知识图谱。

### 4. 知识图谱 【现有】

- **图谱可视化**：基于 Kùzu 图数据库（`Entity`/`Relation` 节点 + `RELATES` 边）展示实体关系图谱
- **图查询**：图遍历查询

### 5. 向量管理 【现有】

向量索引数据的维护管理。

## 三、新增功能菜单

### 6. 本体管理 【新增】

本体管理采用 **"列表页 → 详情页（四 Tab）"** 的两层结构，所有操作在某个本体类别作用域内进行。

#### 6.1 本体类别列表页 `OntologyCategoryList.vue`

- **路由**：`/ontology-categories`
- **功能**：列出所有本体类别（如"金融领域本体"、"军工领域本体"），支持搜索、创建、删除
- **说明**：本体类别 = 领域/业务场景（不是知识库），多个知识库可共享同一个本体类别
- 点击某类别进入详情页

#### 6.2 本体类别详情页 `OntologyCategoryDetail.vue`

- **路由**：`/ontology-categories/:categoryId`
- **结构**：四个 Tab 承载四个功能模块

| Tab | 名称 | 组件 | 功能 |
|-----|------|------|------|
| Tab 1 | 基本信息 | — | 本体类别名称、描述、所属知识库绑定情况 |
| Tab 2 | 本体管理 | `OntologyEditor.vue` + `OntologyAttributeEditor.vue` + `OntologyTemplatePicker.vue` | 管理本体（类型定义，如"人物""组织"），每个本体可展开编辑多个属性；可引用属性模板并预览合并后的完整属性 |
| Tab 3 | 本体关系定义 | `RelationDictEditor.vue` | 维护关系字典（仅名称 + 描述，如"任职于""持有"），不绑定起终点 |
| Tab 4 | 本体关系设置 | `ConstraintEditor.vue` | 通过三个可搜索下拉（起点本体 / 关系 / 终点本体）组合三元组约束，如 `(人物)-任职于→(组织)` |

**Tab 2 本体管理 详细说明**：
- **本体列表**（`OntologyEditor`）：新增/删除/重命名本体，可设置图谱展示颜色
- **自有属性编辑**（`OntologyAttributeEditor`）：属性名、数据类型（string/number/boolean/date/datetime/text/enum）、必填、枚举值，支持整体保存
- **属性模板引用**（`OntologyTemplatePicker`）：多选引用一个或多个属性模板，展示合并后的完整属性预览与同名冲突提示
- 本体最终属性 = 模板属性（合并）+ 本体自有属性；同名冲突时自有属性优先

**Tab 4 本体关系设置 详细说明**：
- 三个下拉建议使用可搜索下拉组件
- "起点本体"和"关系"选定后，"终点本体"可联动过滤出该关系在已有三元组中允许的目标，减少误配

### 7. 属性模板 【新增】

- **路由**：`/attribute-templates`
- **组件**：`AttributeTemplateList.vue`
- **性质**：**全局菜单**，不归属任何本体类别
- **功能**：
  - 创建/编辑/删除属性模板（如"自然人基础属性""机构基础属性""地址信息"）
  - 每个模板可展开编辑其属性（结构与本体属性编辑器一致：属性名、类型、必填、枚举值）
  - 系统可预置常用模板（`is_system=1` 的内置模板不可删除）
- **用途**：解决跨领域共性属性重复定义问题。例如"自然人基础属性"模板（姓名、性别、住址、身份证号）可被金融领域和军工领域的"人物"本体同时引用，共性属性只维护一份
- **删除规则**：删除模板仅解除所有本体的引用，不影响本体自有属性与已抽取的实体数据

---

### 8. 实体管理 【新增】

实例层菜单，数据来自 SQLite `entities`/`relations` 表（权威存储），编辑/删除操作同步 Kùzu 图数据库。

> 实体/关系实例由文件处理抽取自动生成，本菜单以**浏览与修正**为主。

#### 8.1 实体列表页 `EntityListPage.vue`

- **路由**：`/entities`
- **功能**：
  - 分页展示实体
  - 按名称搜索、按知识库过滤、按本体（类型）过滤
  - 每行显示：实体名、本体类型、所属知识库、来源文件
  - 操作：进入详情编辑、删除（二次确认，同步删除 Kùzu 节点）

#### 8.2 实体详情页 `EntityDetailPage.vue`

- **路由**：`/entities/:entityId`
- **功能**：
  - 展示并编辑实体属性值（表单按本体属性定义动态渲染：string/number/date/enum 等）
  - 展示该实体参与的关系实例（作为起点/终点）
  - 展示来源文件/分块
  - 编辑后同步 Kùzu

#### 8.3 关系实例列表页 `RelationListPage.vue`

- **路由**：`/relations`
- **功能**：
  - 分页展示关系实例（起点实体 → 关系 → 终点实体）
  - 支持按知识库、关系类型过滤，按实体名搜索
  - 操作：删除关系实例（同步删除 Kùzu 的 `RELATES` 边）

## 四、菜单与数据层关系

| 菜单 | 数据来源 | 操作入口 |
|------|---------|---------|
| 知识库 / 文件处理 | SQLite `knowledge_bases` / 文件表 | 知识库菜单 |
| 本体管理 | SQLite 本体定义层表（`ontology_*`） | 本体管理菜单 |
| 属性模板 | SQLite `ontology_attribute_templates` 等 3 张表 | 属性模板菜单 |
| 实体管理（列表/编辑） | SQLite `entities`/`relations`（**权威存储**） | 实体管理菜单 |
| 知识图谱（可视化/遍历） | Kùzu `Entity`/`Relation` + `RELATES` 边 | 图谱页面 |

> 实体/关系实例采用**双库存储**：SQLite 供实体管理菜单（列表/分页/搜索/编辑），Kùzu 供图谱可视化与图遍历。抽取时先写 SQLite 再同步 Kùzu；实体管理中编辑/删除时由 service 层同步操作 Kùzu，保持双库一致。

## 五、术语速查

| 术语 | 所在层 | 说明 |
|------|--------|------|
| 本体类别 | 定义层 | 顶层容器，一个领域本体方案（如"金融领域本体"），知识库绑定到它 |
| 本体 | 定义层 | 归属本体类别的类型定义（如"人物""组织"），可有多个属性 |
| 本体属性 | 定义层 | 本体的字段定义（如"姓名 string 必填"） |
| 属性模板 | 定义层（全局） | 可复用的属性组，跨领域共享，本体引用 + 补充自有属性 |
| 本体关系定义 | 定义层 | 关系字典（如"任职于"），仅名称与描述 |
| 本体关系设置 | 定义层 | 起点本体 + 关系 + 终点本体组成的三元组约束 |
| 实体 | 实例层 | 抽取后生成的实例数据，存 SQLite 并同步 Kùzu |
| 关系 | 实例层 | 抽取后生成的实体间关系实例 |

> 详见 [design.md 1.3 术语约定](./design.md)。

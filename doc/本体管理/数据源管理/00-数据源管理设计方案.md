# 数据源管理设计方案（v1.0，2026-09-25）

> 所属：本体管理 · 数据源管理。上游背景：doc/智能体/多智能体/多智能体DataAgent·本体驱动NL2SQL.md
> （类别即数据源、DataAgent 任务层多选 `TaskBody.data_sources` 已落地）。

## 1. 背景与问题

migration_042 给 `ontology_categories` 加了内联字段 `datasource_dialect` / `datasource_dsn`，
实现了「类别即数据源」的 NL2SQL 链，但存在三个问题：

1. **无管理入口**：两个字段只有 seed 脚本能写，本体类别编辑弹窗（名称+描述）看不到、改不了；
2. **凭据散落**：连接串随类别存，多个类别复用同一实例要重复粘贴 DSN；无连通性测试、无启停；
3. **扩展受限**：对接新类型外部数据源（MySQL、远程 PG、SQLite 文件库…）都要手写 DSN，无结构化表单。

## 2. 方案总览：连接注册表 + 类别单选引用 + 任务层多选

| 层 | 职责 | 粒度 |
| --- | --- | --- |
| 数据源管理页（新） | 管连接：类型/地址/凭据/测试连通/启停 | 一个数据源 = 一个外部库实例 |
| 本体类别（改造） | 管 schema 映射：表/字段/关系本体 + 挂哪个数据源 | 类别 → 数据源 **单选引用** |
| 多智能体任务层（已有） | 跨数据源取数：DataAgent 勾选 N 个类别 | 类别多选 = 数据源多选 |

**为什么类别挂数据源是单选而不是多选**：

- NL2SQL 是**单连接只读执行**：检索子图 → 生成一条 SQL → 连一个库执行。类别若挂多个
  数据源，子图混入两库的表，生成的 SQL 无法执行（跨库需联邦查询，复杂度高、当前无场景）；
- 多数据源诉求已被正确覆盖：一个库建一个类别（各自做 schema 映射），任务层
  `data_sources` 多选类别即可跨库（各库 SQL 独立执行，事实卡分列）；
- Palantir 同构：Foundry 里一个 object type 的 backing dataset 也归属单一数据源。

## 3. 数据模型

### 3.1 新表 `data_sources`（migration_044）

```sql
CREATE TABLE IF NOT EXISTS data_sources (
    id VARCHAR PRIMARY KEY,
    name VARCHAR NOT NULL UNIQUE,           -- 展示名（唯一）
    dialect VARCHAR(20) NOT NULL DEFAULT 'postgres',  -- sqlite / mysql / postgres（可扩展）
    host VARCHAR(255) DEFAULT '',
    port INTEGER DEFAULT 0,
    dbname VARCHAR(255) DEFAULT '',         -- sqlite = 文件路径
    username VARCHAR(128) DEFAULT '',
    password TEXT DEFAULT '',
    dsn TEXT DEFAULT '',                    -- 完整连接串：结构化字段自动拼接，也可直填覆盖
    description TEXT DEFAULT '',
    enabled INTEGER NOT NULL DEFAULT 1,     -- 停用 = 该数据源从 NL2SQL 链与清单中消失
    created_at VARCHAR,
    updated_at VARCHAR
);
ALTER TABLE ontology_categories ADD COLUMN datasource_id VARCHAR DEFAULT '';
```

- **dsn 生成规则**（表单提交时二选一）：
  - 直填 `dsn` → 原样保存（postgres/mysql 为 SQLAlchemy URL，sqlite 为 `file:...?mode=ro`）；
  - 只填结构化字段 → 按方言拼接：`postgresql://user:pass@host:port/dbname`、
    `mysql+pymysql://...`、sqlite 直接取 dbname 路径拼 `file:`。密码经 `quote_plus` 转义。
- **安全口径**（与现状一致）：password 明文存库（单机内网系统），**所有接口不回传
  password**，dsn 掩码输出（`://user:***@`）；加密存储列为 P2。

### 3.2 `ontology_categories.datasource_id`

- 默认 `""` = 不绑数据源（普通业务本体类别，行为与现状完全一致）；
- **存量迁移**（migration_044 内完成，纯 SQL、幂等）：

```sql
INSERT INTO data_sources (id, name, dialect, dsn, description, enabled, created_at, updated_at)
SELECT 'dsmig' || c.id, '迁移 · ' || c.name, c.datasource_dialect, c.datasource_dsn,
       'migration_044 自类别内联配置迁移', 1, '2026-09-25T00:00:00', '2026-09-25T00:00:00'
FROM ontology_categories c
WHERE c.datasource_dialect IS NOT NULL AND c.datasource_dialect != ''
  AND c.datasource_dsn IS NOT NULL AND c.datasource_dsn != '';

UPDATE ontology_categories SET datasource_id = 'dsmig' || id
WHERE datasource_id = '' AND datasource_dialect != '' AND datasource_dsn != '';
```

- 内联字段 `datasource_dialect/dsn` **保留不删**（回滚安全；seed 脚本继续双写）。

### 3.3 连接解析优先级（全链路唯一入口 `resolve_category_datasource`）

```
datasource_id 非空且注册表记录存在：
    记录停用（enabled=0）→ 返回空（明确切断，优先于内联兜底，停用 = 立即失效）
    记录启用 → 注册表 dialect/dsn
    记录不存在（被删但类别残留引用）→ 回落内联
否则（未绑定）→ 类别内联 datasource_dialect/datasource_dsn（存量兜底）
```

放 `services/datasource_service.py`，schema_store 与清单接口共用，杜绝两处口径漂移。
配套：`prepare_nl2sql` 剔除解析不出连接的图谱（位置不明即回落老链，与
nl2sql_query 入口的 dsn 空拦截同口径）。

## 4. 后端 API

风格对齐 MCP 注册中心（`/api/agent/multi/mcp/*`）：失败不抛 500，test 返回 200 + `ok:false`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/datasources` | 列表（password 永不返回，dsn 掩码；附 `used_by` 引用类别数） |
| POST | `/api/datasources` | 新增（name 唯一校验；dsn 直填或结构化拼装） |
| PUT | `/api/datasources/{id}` | 更新（password 传空串 = 保持原值不变） |
| DELETE | `/api/datasources/{id}` | 删除（被类别引用时 409 拒绝，提示先解绑） |
| POST | `/api/datasources/test` | 不落库试连：SELECT 1，超时 3s，返回 `{ok, elapsed_ms, error}` |

类别接口扩展（`routers/ontology.py`）：

- `CreateOntologyCategoryRequest.datasource_id: str = ""`、
  `UpdateOntologyCategoryRequest.datasource_id: str | None = None`（None = 不改，`""` = 解绑）；
- `list_categories` / `get_category_detail` 序列化补
  `datasource_id / datasource_name / datasource_dialect / datasource_dsn_masked`（编辑弹窗回显 + 列表徽标）。

## 5. NL2SQL 链改造（行为兼容）

| 位置 | 改动 |
| --- | --- |
| `schema_store.load_schema_graph` | 类别 dialect/dsn 改经 `resolve_category_datasource` 解析（注册表优先） |
| `schema_store.find_datasource_graphs` | 类别筛选扩为 `dialect != '' OR datasource_id != ''`（用户新建类别只挂引用不写内联也能被选中） |
| `routers/multi_agent.py GET /datasources` | 行仍是**类别**（勾选维度 = category_id，前端 `pickedSources` 语义不变），dialect/dsn 改从注册表解析取，附 `ds_name` |
| `scripts/seed_schema_ontology.py` | 写类别时同步 upsert 注册表记录（`name=迁移 · <类别名>` 同条复用）并回填 `datasource_id`；内联字段继续双写 |
| 校验脚本 `verify_nl2sql.py` | DSN 检查改走 resolve 链 |

**语义红线**（不变）：dialect/dsn 解析为空 = NL2SQL 回落 NL2Filter 老链；dsn 禁指平台主库
（seed 的 `_pg_key` 拒绝逻辑不变）；NL2SQL 只读执行器不动。

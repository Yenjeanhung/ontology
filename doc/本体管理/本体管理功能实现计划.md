# 本体管理功能实现计划

## Context

KnowSource 是基于 RAG + 知识图谱的知识库系统（Vue 3 + FastAPI + SQLite + Kùzu）。当前抽取实体/关系仅靠 LLM System Prompt 列出固定类型，无硬约束，结果不稳定。

本计划按 [doc/design.md](../../doc/design.md) 实现本体管理功能：让用户定义本体类别→本体(类型)+属性→关系字典→三元组约束，绑定到知识库后约束抽取，抽取结果存实体/关系表并同步 Kùzu。共新增 11 张 SQLite 表（无外键），分四阶段全做。

**用户确认的约束**：
- 前端保持现有手写 CSS+SVG 风格，自建可复用基础组件（SearchableSelect、Tab 等），不引入 UI 库
- 四阶段全部实现

## 关键约定（基于现有代码）

| 项 | 现有模式 | 新代码遵循 |
|----|---------|-----------|
| ORM | SQLAlchemy `DeclarativeBase`，`Column(String, primary_key=True, default=lambda: uuid.uuid4().hex[:12])`，时间戳 `Column(String, default=lambda: datetime.now().isoformat())` | 新表**不用 ForeignKey、不用 relationship**，纯 `Column(String)` 逻辑关联；级联删除在 service 层手动做 |
| 建表 | `database.py` 的 `init_db` 读 `sql/schema.sql` 按 `;` 分割逐条执行（IF NOT EXISTS）+ `sql/migrations.sql` 增量 | 新表 CREATE 语句追加到 `sql/schema.sql` 末尾，每条以 `;` 结尾、内部无 `;` |
| Service | `@staticmethod async def method(db: AsyncSession, ...) -> dict`，`select()` 查询，返回 dict，`db.add()`+`commit()`+`refresh()` | 同上 |
| Router | `APIRouter()`，`@router.post("/kb")`，`db: AsyncSession = Depends(get_db)`，调 `Service.method` | 同上，`server.py` 用 `app.include_router(xxx.router, prefix="/api")` 注册 |
| Schema | Pydantic `BaseModel`，`str \| None` 风格 | 同上 |
| 前端 API | 原生 `fetch`，函数式导出（`front/src/api/index.js`） | 同上 |
| 前端组件 | `<script setup>` Composition API，手写 CSS（`--c-bg/--c-fg/--c-border/--c-muted` 等变量）+ 内联 SVG | 同上，组件放 `front/src/components/` |
| 菜单 | `App.vue` 的 `menuItems` computed 数组 `{ to, label, exact, hint }` + 按 `item.to` 匹配 SVG | 新增菜单项 + 对应 SVG |
| 路由 | `front/src/router/index.js` 的 `routes` 数组 | 追加路由 |

## 阶段一：后端本体定义层

### 1.1 ORM 模型 — `backend/models.py` 追加

新增 9 个模型（6 本体定义层 + 3 属性模板），字段与 design.md 3.1–3.6 + 属性模板 3 张表一致。**全部无 ForeignKey**，关联字段用 `Column(String, nullable=False)`。

模型清单：
- `OntologyCategory`（ontology_categories）
- `Ontology`（ontologies，含 category_id、name、description、color、sort_order）
- `OntologyAttribute`（ontology_attributes，含 data_type、is_required、enum_values）
- `OntologyRelation`（ontology_relations）
- `OntologyRelationConstraint`（ontology_relation_constraints，含 source_ontology_id、relation_id、target_ontology_id）
- `KbOntologyBinding`（kb_ontology_bindings）
- `OntologyAttributeTemplate`（ontology_attribute_templates，含 is_system）
- `OntologyTemplateAttribute`（ontology_template_attributes）
- `OntologyTemplateBinding`（ontology_template_bindings，含 ontology_id、template_id）

### 1.2 建表 SQL — `backend/sql/schema.sql` 追加

追加 9 张表 CREATE 语句（IF NOT EXISTS），含 UNIQUE 约束（防重），无 FOREIGN KEY。

### 1.3 Pydantic Schema — `backend/schemas.py` 追加

按 design.md 第四章 API 请求体定义：CreateOntologyCategoryRequest、UpdateOntologyCategoryRequest、CreateOntologyRequest、UpdateOntologyRequest、CreateOntologyAttributeRequest、CreateOntologyRelationRequest、CreateRelationConstraintRequest、BindOntologyCategoryRequest、CreateAttributeTemplateRequest、UpdateAttributeTemplateRequest、CreateTemplateAttributeRequest、BindTemplateRequest 等。

### 1.4 Service — `backend/services/ontology_service.py`（新建）

`OntologyService` 类，`@staticmethod async` 方法，参考 `kb_service.py` 风格。核心方法：
- 本体类别 CRUD：`list_categories`、`get_category_detail`（聚合本体/属性/关系/三元组/绑定）、`create_category`、`update_category`、`delete_category`（**级联删除**：先查删 ontologies→attributes→relations→constraints→bindings，再删 category）
- 本体 CRUD：`list_ontologies`、`create_ontology`、`update_ontology`、`delete_ontology`（级联删属性、引用它的三元组、模板绑定）
- 属性 CRUD：`list_attributes`、`create_attribute`、`update_attribute`、`delete_attribute`、`batch_save_attributes`
- **属性合并**：`get_merged_attributes(db, ontology_id)` 返回 模板属性(按 template.sort_order 合并) + 本体自有属性，同名时自有优先，标记冲突
- 关系字典 CRUD：`list_relations`、`create_relation`、`update_relation`、`delete_relation`
- 三元组 CRUD：`list_constraints`、`create_constraint`、`delete_constraint`
- 知识库绑定：`bind_kb`、`unbind_kb`、`get_kb_binding`
- 属性模板 CRUD：`list_templates`、`create_template`、`update_template`、`delete_template`（解绑引用）、`get_template_detail`
- 模板属性 CRUD：`list_template_attributes`、`create_template_attribute`、`delete_template_attribute`
- 模板绑定：`bind_templates`（多对多）、`unbind_template`、`list_ontology_templates`

### 1.5 Router — `backend/routers/ontology.py`（新建）

按 design.md 4.1–4.5 路径实现端点，`APIRouter()`，依赖 `get_db`。路径前缀在注册时统一加 `/api`，故 router 内路径以 `/ontology-categories`、`/attribute-templates` 起头。

### 1.6 注册 — `backend/server.py`

`from routers import ..., ontology` 并 `app.include_router(ontology.router, prefix="/api")`。

### 1.7 阶段一验证

启动后端，用 API 工具（curl/httpie/浏览器）测试：创建本体类别→加本体→加属性→加关系→加三元组→加属性模板→本体引用模板→绑定知识库。确认 `get_category_detail` 返回合并属性。

## 阶段二：后端实体实例层 + 抽取集成

### 2.1 ORM 模型 — `backend/models.py` 追加

- `Entity`（entities，含 kb_id、ontology_id、entity_type、name、properties(JSON TEXT)、source_file_id、source_chunk_id）
- `Relation`（relations，含 kb_id、relation_def_id、relation_type、source_entity_id、target_entity_id）

### 2.2 建表 SQL — `backend/sql/schema.sql` 追加 2 张表

### 2.3 Schema — `backend/schemas.py` 追加

UpdateEntityRequest（name、description、properties）等。

### 2.4 Service — `backend/services/entity_service.py`（新建）

`EntityService` 类：
- `list_entities(db, kb_id, ontology_id, q, page, page_size)` 分页
- `get_entity(db, entity_id)` 详情（含关联关系）
- `update_entity(db, entity_id, payload)` 同步 Kùzu
- `delete_entity(db, entity_id)` 同步删 Kùzu 节点
- `list_relations`、`get_relation`、`delete_relation`（同步删 Kùzu RELATES 边）
- `upsert_entity_from_extraction(db, kb_id, ontology_id, name, entity_type, properties, source_file_id, source_chunk_id)` 抽取写入入口
- `upsert_relation_from_extraction(...)` 同上

### 2.5 Router — `backend/routers/entity.py`（新建）

按 design.md 4.6 路径：`/entities`、`/entities/{id}`、`/relations`、`/relations/{id}`。在 `server.py` 注册。

### 2.6 抽取服务改造 — `backend/services/graph_extraction_service.py`

- `extract` 方法签名增加 `ontology_constraint: dict | None = None` 参数
- 当传入约束时：动态拼接 `GRAPH_EXTRACTION_SYSTEM_PROMPT`（列出允许的本体类型+属性+三元组），替代固定类型列表；无约束时保持原行为
- 后处理（抽取后）：按本体类型过滤非法实体、按三元组过滤非法关系、属性类型规整（number/boolean/date 转换）
- 调用 `EntityService.upsert_entity_from_extraction` 写 SQLite，再调用 graph_store 写 Kùzu（保留现有 `upsert_document_graph` 调用）

### 2.7 文件服务改造 — `backend/services/file_service.py`

`_process_file_bg` 中调用 `extract` 前：通过 `OntologyService.get_kb_binding` 查 kb_id 绑定的本体类别，有则 `get_category_detail` 构建 `ontology_constraint` 传入；无则不传（兼容）。

### 2.8 Kùzu 适配 — `backend/providers/graph_store/__init__.py`

确认 `upsert_document_graph` / 节点删除接口；实体管理删除时需要按 entity_id 删 Kùzu 节点，若无对应方法则补充 `delete_graph_entity(kb_id, entity_id)`、`delete_graph_relation(...)`。

### 2.9 阶段二验证

绑定本体类别到知识库→处理文件→查 `entities`/`relations` 表有数据→Kùzu 图谱可见→实体管理 API 列表正常→编辑/删除实体后 Kùzu 同步。

## 风险点

- **无外键一致性**：级联删除全靠 service 层，必须覆盖所有关联表，遗漏会留孤儿数据。删除顺序：category→ontologies/relations/constraints/bindings→attributes；ontology→attributes/constraints/template_bindings
- **双库一致性**：SQLite 与 Kùzu 双写，抽取或删除时若一方失败需日志告警；实体管理编辑后必须同步 Kùzu
- **抽取改造兼容**：无 ontology_constraint 时走原逻辑，新增参数默认 None
- **schema.sql 分割**：新增 SQL 语句内部不得含 `;`（如 enum_values 的 JSON），避免被 init_db 误分割
- **前端手写工作量**：四 Tab + 可搜索下拉 + 属性编辑器组件较多，自建基础组件保证复用

## 执行顺序

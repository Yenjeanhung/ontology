## 0. 一句话目标

把「**PostgreSQL 权威本体/实体数据 → Neo4j 分析图**」从手工脚本升级为**产品化的图迁入服务**，在其上建成**图计算任务引擎**（GDS 中心性/社区/相似度）与**图推理层**（规则推理 + 故障传播分析），让民航维修图谱从"能看"（图谱浏览）进化为"**能算、能推、能给维修决策出证据**"的分析资产。

### 1.2 两份 GDS 设计的分工

| | 《GDS实体链接与知识补全》 | 本设计《图迁入与图计算推理》 |
|---|---|---|
| 服务对象 | RAG 问答（OAG） | 维修工程师/分析员 |
| 生效方式 | 问答链路内嵌、自动 | 用户主动分析、工作台 |
| 图的范围 | KB 维度（`kg_<kb>`） | 本体类别维度（领域级，`cat_<cid>`） |
| 关心什么 | 召回率、实体链接精度 | 关键节点/传播链/隐含关系 |
| 共享 | M0 GDS 基础层 + `relation_suggestions` 审核闭环 | |

**为什么分析图按"本体类别"而非 KB 投影**：故障推理是领域问题——"疲劳裂纹波及哪些部件"不该被"数据来自哪个知识库"割裂；实体经 `ontology_id → ontologies.category_id` 天然归属领域。

## 3. M0：GDS 基础层（两份设计共建）

> 方法清单（`gds_available` / `gds_ensure_projection` / 指纹失效 / `_gds_lock` / 防注入）见姊妹篇 4.2~4.5，此处只列**本设计的差异**。

### 3.1 投影 scope 泛化

姊妹篇投影按 KB（`kg_<kb_id>`，`:Entity`+`:RELATES`）；本设计按本体类别：

```cypher
-- 投影名：cat_<category_id>
节点：MATCH (e:Entity {category_id: '<cid>'}) RETURN id(e) AS id
关系：MATCH (a:Entity {category_id: '<cid>'})-[r]->(b:Entity)
      WHERE type(r) <> 'RELATES' AND b.category_id = '<cid>'
      RETURN id(a) AS source, id(b) AS target
```

- 基础层方法泛化：`gds_ensure_projection(scope_type: Literal["kb","category"], scope_id)`
- `category_id` 同样过 `^[a-f0-9]{12}$` 白名单再内联（cypher 投影不支持参数化）
- **迁入时给节点/关系补 `category_id` 属性**（本体归属反查），投影与查询都靠它圈范围

### 3.2 分析图 schema（沿用 sync 脚本已验证的结构）

```
节点：(:Entity:<本体类型名> {id, kb_id, category_id, name, entity_type, ontology_id, description, properties})
关系：[:<关系字典语义名> {relation_id, category_id}]
```

- 与业务抽取图（`:RELATES`+Chunk/Document）标签隔离，互不干扰
- 节点保留 `:Entity` 基标签：实体详情跳转、id 体系与现有页面通用

### 3.3 投影配置（`_tmp_gds_verify.py` 验证过的经验）

- **通用投影**（中心性/社区/嵌入）：UNDIRECTED 全语义关系——Louvain/FastRP 均需无向
- **传播/路径类分析**：不走投影，直接 Cypher 可变长路径（`[:导致*1..3]`，10 万级实测可接受）

## 4. 模块一：图迁入（GraphSyncService）

### 4.1 服务化要点

`sync_seed_to_neo4j.py` 的核心逻辑（分页读取 + 按类型分组 + UNWIND 批量 MERGE + 投影创建）搬入 `backend/services/graph_sync_service.py`，补上产品化能力：

| 能力 | 设计 |
|---|---|
| 迁入范围 | `sync_category(category_id, mode)`——实体经 `ontology_id ∈ 该类别本体集合` 圈定 |
| 全量模式 | `DETACH DELETE` 该类别旧子图 → 重建（10万级 1~2 分钟，简单可靠，**默认**） |
| 增量模式 | 水位 `max(entities.updated_at)`，只迁增量行；删除靠对账（4.3） |
| 进度反馈 | `graph_sync_runs` 任务表（状态/已迁节点数/关系数/耗时/错误），前端轮询 |
| 迁入后动作 | 自动重建投影（M0）+ 计算指纹；完成通知（复用 notifications） |
| 护栏 | 同类别互斥；`dry_run` 预检（统计将迁入数量）；实体数为 0 拒绝执行 |

### 4.2 类型映射

| PostgreSQL 侧 | Neo4j 侧 |
|---|---|
| 本体 `name`（如"故障模式"） | 节点第二标签 `:故障模式` |
| 关系字典 `name`（如"导致"） | 关系类型 `[:导致]` |

标签/关系类型名过 Neo4j 命名校验 + 反引号包裹；本体更名 → 下次全量迁入自动纠正。

### 4.3 删除对账（增量模式补集，P2）

全量天然对账。增量模式：本次扫到的 id 集合与图中 `category_id` 节点做差集，分批 `DETACH DELETE`。运行时 `EntityService.delete_entity` 已有的逐条删除继续保留。

### 4.4 API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/graph-sync/categories` | 可迁入类别列表（实体数/关系数/上次迁入/投影状态/指纹是否失效） |
| POST | `/api/graph-sync/{category_id}/run` | `{mode, dry_run?}` → BackgroundTasks，返回 run_id |
| GET | `/api/graph-sync/runs/{run_id}` | 进度轮询 |
| GET | `/api/graph-sync/{category_id}/runs` | 迁入历史 |

## 5. 模块二：图计算任务（GraphAnalysisService）

### 5.1 算法注册表（v1 五个，GDS 均已验证）

| 算法 | GDS 过程 | 业务语义（民航） | 结果形态 |
|---|---|---|---|
| `pagerank` | `gds.pageRank.stream/write` | 关键节点：故障网络最中心的部件/故障模式 | 榜单 + 写回 `pagerank_score` |
| `betweenness` | `gds.betweenness.stream/write` | 桥接节点：掐断即可阻断传播的关键环节 | 榜单 + 写回 `betweenness_score` |
| `louvain` | `gds.louvain.stream/write` | 故障综合征：互相诱发的故障聚类 | 社区列表 + 写回 `community_id` |
| `node_similarity` | `gds.nodeSimilarity.stream` | 相似故障/相似件号（Jaccard） | 榜单 + 产 `相似于` 建议 |
| `degree` | Cypher 聚合 | 高频拆换/高频故障粗排 | 榜单 |

### 5.2 任务生命周期

```
POST run(algorithm, category_id, params) → graph_analysis_tasks(pending)
  → BackgroundTasks:
     护栏（投影/指纹无效则先重建；_gds_lock 串行重操作）
     → gds.<algo>.stream → top-N 榜单 → task.results(JSON)
     → write 模式：gds.<algo>.write 写回节点属性
     → 产建议：本体约束过滤 + 已存在去重 + tombstone
              → relation_suggestions(source='gds_analysis')
  → 通知 + 前端轮询 done
```

- `params`（JSON）：`top_n`、`write_back`、`label_filter`（如只算"故障模式"）及算法专属参数
- 读投影的任务不加锁；重建投影类操作持 `_gds_lock`

### 5.3 结果三个去向

1. **榜单**：`task.results` 存 top 100（JSON），前端表格直出
2. **写回节点属性**（`pagerank_score`/`community_id`/`betweenness_score`）：只写在分析图（可重建的派生数据），**不回 PostgreSQL**——权威库只收"关系事实"，不收"计算分值"；P2 图谱浏览叠加渲染（节点大小∝中心性、颜色∝社区）
3. **关系建议**：`node_similarity` 高分对 → 按约束映射 `相似于` → 审核闭环（6.4）

## 6. 模块三：图推理

### 6.1 三类推理能力

| 类型 | 机制 | 产物 | 交互 |
|---|---|---|---|
| 规则推理 | 领域规则 + Cypher 可变长路径物化 | `发生于`(间接)、`潜在故障` 等关系**建议** | 审核闭环 |
| 传播分析 | 场景化 Cypher 模板，不落库 | 传播链/影响范围**视图** | 即时查询渲染 |
| 结构推理 | 模块二 nodeSimilarity | `相似于` 建议 | 同规则推理闭环 |

### 6.2 规则推理引擎（v1 内置规则集，不建配置表）

```python
INFERENCE_RULES = [
  # (路径模式,                              推出关系,    置信度)
  ("(部件)-[:组成]->()-[:组成]->(x)",            "组成",     0.95),  # 部件树传递
  ("(故障模式)-[:发生于]->()-[:组成]->(x)",       "发生于",   0.90),  # IPC 上卷：子件故障⇒父件故障
  ("(故障原因)-[:导致]->()-[:表现为]->(x)",       "表现为",   0.80),  # 根因链传导
  ("(故障原因)-[:发生于]->()-[:组成]->(x)",       "发生于",   0.85),
  ("(维修工单)-[:涉及故障]->()-[:发生于]->(x)",   "涉及部件", 0.70),
]
```

执行 `run_inference(category_id)` → 逐规则跑 Cypher（限定 `category_id`，跳数受控）→ 过四道闸：
1. 已存在同向同类型关系 → 丢弃
2. `(源类型, 关系, 目标类型)` 在 `constraint_set` 白名单 → 否则丢弃
3. tombstone：拒绝过的组合不再推
4. `INFERENCE_MIN_CONFIDENCE`（默认 0.7）

产物落 `relation_suggestions`（`source='rule'`，evidence 记录推理路径供审核者回看）。

> v2（本期不做）：规则外置 `inference_rules` 表 + 前端配置、否定条件。

### 6.3 场景化传播分析（同步 API，秒级，不落任务表）

| API | 模板 | 回答的问题 |
|---|---|---|
| `GET .../{cid}/propagation?entity_id=&max_hops=3` | `(:故障模式)-[:导致*1..3]->(x)`，置信度随跳数衰减 | 故障往下会引发什么？ |
| `GET .../{cid}/impact?entity_id=` | 发生于反向 ∪ 组成向上 ∪ 装于→机型 | 部件出问题影响哪些系统/机型？ |
| `GET .../{cid}/similar?entity_id=&top_k=10` | nodeSimilarity 流式 + 标签过滤 | 相似故障案例（排故参考） |
| `GET .../{cid}/path?source_id=&target_id=` | `shortestPath` 全语义关系 | 两实体的关系链（如 AD→部件→故障） |

返回统一结构 `{nodes, edges, chains}`，前端复用图谱浏览的 ECharts 渲染。propagation/impact/path 纯 Cypher 不依赖 GDS，**GDS 不可用也天然可用**。

### 6.4 建议审核闭环（与姊妹篇共用一套）

- 表沿用姊妹篇 6.2 的 `relation_suggestions` + tombstones，**增加 `source` 字段**：`'rule'` / `'gds_analysis'` / `'completion'`
- 审核页面、批准双写链路（`EntityService.create_relation` + `graph_store.upsert_relation`）一份实现三家共用——先开发者落地，后来者复用
- 批准时顺带写一条到分析图（同语义关系名），即时可见；增量迁入随后对齐

## 7. 数据模型（models.py 新增 2 张表）

```python
class GraphSyncRun(Base):
    """图迁入运行记录"""
    __tablename__ = "graph_sync_runs"
    id = Column(String, primary_key=True, default=lambda: uuid.uuid4().hex[:12])
    category_id = Column(String, nullable=False, index=True)
    mode = Column(String, nullable=False)            # full / incremental
    status = Column(String, nullable=False)          # pending/running/done/failed
    entity_count = Column(Integer, default=0)        # 进度计数
    relation_count = Column(Integer, default=0)
    watermark = Column(String)                       # 增量水位 max(updated_at)
    error = Column(Text)
    started_at = Column(String); finished_at = Column(String)
    created_at = Column(String, default=lambda: datetime.now().isoformat())


class GraphAnalysisTask(Base):
    """图计算/推理任务"""
    __tablename__ = "graph_analysis_tasks"
    id = Column(String, primary_key=True, default=lambda: uuid.uuid4().hex[:12])
    category_id = Column(String, nullable=False, index=True)
    kind = Column(String, nullable=False)            # algorithm / inference
    algorithm = Column(String)                       # pagerank/louvain/... 或 'rules_v1'
    params = Column(Text, default="{}")              # JSON
    status = Column(String, nullable=False)          # pending/running/done/failed
    stats = Column(Text, default="{}")               # JSON：规模/耗时/建议数
    results = Column(Text)                           # JSON：top-N 榜单/社区摘要
    error = Column(Text)
    started_at = Column(String); finished_at = Column(String)
    created_at = Column(String, default=lambda: datetime.now().isoformat())
```

（`relation_suggestions` 两张表见姊妹篇 6.2，落地时补 `source` 字段。）

## 12. 风险与对策

| 风险 | 对策 |
|---|---|
| GDS 未装/版本不符 | 启动探测 + 降级（传播/影响/路径 API 纯 Cypher 不受影响）+ 监控黄标 |
| cypher 投影不支持参数化 | `category_id` hex 白名单校验后内联 |
| 社区版 GDS 并发 = 1 | `_gds_lock` 串行化重建类操作；读任务不持锁 |
| 10 万级全量迁入耗时 | UNWIND 批量（脚本已验证 1~2 分钟）+ 后台任务 + 进度反馈 |
| 推理建议洪水 | 置信度阈值 + TOP_N + tombstone + 约束白名单四道闸 |
| 标签/关系名与 Neo4j 保留字冲突 | 命名校验 + 反引号包裹 |
| 分析图被误删 | 可随时全量重建（派生数据定位），PostgreSQL 权威不受影响 |

## 13. 验收标准

**P0**
1. 「图分析」页可见类别迁入状态；点全量迁入后 1~3 分钟完成，进度可见
2. 迁入后 Neo4j 中出现 `:Entity:<本体类型>` 节点与语义关系；投影 `cat_<cid>` 创建成功
3. 重复迁入幂等（全量重建无残留旧标签）

**P1**
1. 五个算法均可运行并出榜单；write 模式后节点带上对应属性
2. `node_similarity` 高分对出现在建议列表（已过约束过滤与去重）

**P2**
1. 传播链查询：任选故障模式展示 `导致*` 链路（含跳数衰减置信度）
2. 规则推理产出建议（带证据路径）；批准后 PostgreSQL 与分析图双写、同组合不再重推；拒绝后 tombstone 生效
3. 已存在关系不出现在建议中

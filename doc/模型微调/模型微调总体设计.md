# 模型微调总体设计（小模型 · 本项目场景落地）

> 定位：在**不改变现有大模型主链路**的前提下，落地 **1 个微调小模型**：
> **查询意图路由**（Qwen3-0.6B + LoRA，4 分类：kb / graph / data / chat）。
> 该任务满足「高频、窄任务、输出格式固定、判错可兜底」的微调适配条件；
> **训练算力上云**：本机显卡较低，微调在 AutoDL（autodl.com）按量租卡完成，
> 本机只做推理部署；生成式主力回答、智能体规划与合成仍全部交给配置的大模型（GLM / DeepSeek / Qwen 等）。

---

## 1. 设计原则

1. **只微调窄任务**：分类、格式化输出——输出空间小、模式固定，小模型微调后足够；
   开放式写作/推理留给大模型，避免"小模型干大活"。
2. **推理端小、训练端上云**：
   - 推理模型保持本机可承载——意图路由 `Qwen3-0.6B`（LoRA，Q4 约 0.5G 显存，可 CPU 推理）；
   - 训练不再是本机约束——AutoDL 按量租卡（RTX 4090 24G 一档即可），
     训练完只把权重拷回本机。
3. **接入零侵入**：微调后的模型不改主链路代码——
   路由模型以独立开关 + 独立模块接入，也可走 OpenAI 兼容端点（ollama / vLLM）复用 `build_llm`。
4. **渐进可回退**：独立开关（config），关掉即回退现有行为；
   小模型不可用/超时一律降级走原路径，绝不阻塞主流程。
5. **职责边界清晰**：小模型只做「入口调度」类决策，**智能体执行环节（Planner / Worker /
   ToolAgent / Synthesizer）仍全部使用主大模型**——小模型只可能减少大模型调用，不会替代它。

---

## 2. 落地点：查询意图路由（入口门卫，智能体仍用大模型）

| 项 | 说明 |
|---|---|
| 场景 | 多智能体/问答入口的意图分类 |
| 现状痛点 | 无路由：全量走多智能体全编制；DataAgent 靠词频强信号规则，召不回自然语言变体 |
| 微调方案 | **LoRA 参数高效微调（PEFT）+ SFT 指令监督** |
| 基座模型 | `Qwen/Qwen3-0.6B`（AutoDL 训练） |
| 接入点 | 新增 `services/query_router.py`，多智能体/问答入口前置 |
| 改动量 | 小（独立模块 + config 开关） |

动机：
- 多智能体当前无前置路由，任何问题都拉起完整编制（Planner → 并行角色 → Synthesizer），
  简单寒暄/单库问题也被过度编排；
- DataAgent 的 `entity_type/name` 强信号判断是纯词频规则（`DATA_STRONG_MIN=3`），
  召不回自然语言变体（"今天航班正常率怎么样"没有实体名就漏）。

**职责边界（重点）**：路由模型是**入口处的一次性门卫**，不是智能体的替代品——

```
用户提问
   │
   ▼
[意图路由小模型] ← 0.6B，本地推理 1 次，<100ms
   │
   ├─ 判为 chat  ──→ 主大模型直接回答，不编排            （省掉整轮编排）
   ├─ 判为 data  ──→ 编制瘦身：只勾 DataAgent+Synthesizer（Planner 输入更小）
   ├─ 判为 graph ──→ 编制瘦身：只勾 GraphAgent+Synthesizer
   └─ 低置信/异常 ──→ 照旧全编制（现状行为，兜底）
   │
   ▼
Planner / Worker / ToolAgent / Synthesizer ← 仍全部用主大模型，不变
```

- 路由模型只在用户提问入口调用一次（输出 label + 置信度）；
- Planner 分解、Worker/ToolAgent 执行、Synthesizer 合成等**智能体执行环节全部仍用主大模型**；
- 多智能体内部本就有大量非模型节点（DataAgent/GraphAgent 固定管线、Critic 硬规则），
  这些不受影响；
- 路由是一次性小推理，只可能**减少**大模型调用（免编排/精简编制），不可能增加。

方案：0.6B 小模型 4 分类（`kb / graph / data / chat`，可多标签），输出 label + 置信度：
- 多智能体入口：chat 类直答不编排；单标签问题只勾选对应能力智能体编制（轻量化 Planner 输入）；
- DataAgent：模型判断含数据查询意图即走强口径，替代词频规则，规则保留为兜底。

形态二选一（本机显卡较低，A/B 都已覆盖低配场景）：
- **A**：进程内 transformers 直推（`services/query_router.py`，无 HTTP 开销；
  有 GPU 用 GPU，无 GPU 自动 CPU——0.6B CPU 单次推理约 1~3 秒，路由非实时关键路径可接受）；
- **B（低配推荐）**：ollama 加载 Q4 量化版（约 0.5G 显存/内存，OpenAI 兼容端点复用 `build_llm`），
  有核显/小显存时更快。

训练数据：现网 `chat_messages` 抽 query 人工标注几百条 + 规则模板扩造（台账词/图谱词/闲聊各数百条），
`DATA_STRONG` 命中记录天然是 data 类正样本。

## 3. 技术选型汇总

| 项 | 选型 | 理由 |
|---|---|---|
| 生成式基座 | **Qwen/Qwen3-0.6B** | 最新一代 0.6B 基座（2025-04 发布）：指令跟随更强、原生 32K 上下文、官方持续维护；Q4 量化约 0.5G 可 CPU 推理；thinking 模式需关闭（见手册 §3.2） |
| 微调方法 | **LoRA**（r=16, alpha=32, target all） | 窄任务只需改输出行为，更新量本征低秩；可训练参数 <1%，小数据过拟合风险低，产物 adapter 几十 MB |
| 训练范式 | **SFT 指令监督**（alpaca 三元组） | 任务就是"按指令输出固定格式 JSON"，instruction→output 成对监督最直接 |
| 训练框架 | **LLaMA-Factory**（配置化） | 一份 yaml 描述数据+训练，可复现；内含 peft/transformers/accelerate |
| 训练算力 | **AutoDL 按量租卡**（RTX 4090 24G 档即可，训练完关机） | 本机显卡低；云上按小时计费，单期训练预算约十几元级 |
| 推理部署 | 本机：ollama Q4（低配推荐）或进程内直推 | 与本机开发环境（win32）最匹配；生产可换 vLLM 同协议 |
| 数据标注 | 现网日志蒸馏 + 人工小批量标注 + 模板扩造 | 几乎不额外造数 |
| 评测 | 300 条人工标注验证集 | 上线前用真实 query 集对比「有/无微调」指标 |

硬件参考：训练（AutoDL 4090 24G）0.6B LoRA 富余，单期训练时长约分钟~小时级；
推理（本机）Q4 约 0.5G——无独显可 CPU 推理（单次 1~3 秒，路由非实时关键路径可接受）。

## 4. 实施路线

1. **造数据**：现网 query 标注 300~500 条 + 模板扩造，合计 1000~2000 条 SFT 三元组（手册 §2）；
2. **AutoDL 训练**：LLaMA-Factory LoRA（r=16），合并导出完整模型（手册 §3）；
3. **本机部署**：scp 下载 → ollama Q4 量化部署（或进程内直推）（手册 §4）；
4. **平台接入**：`services/query_router.py` + config 开关（`ROUTER_ENABLED` / `ROUTER_MODEL_PATH`）；
   多智能体入口接入（chat 直答 / 单标签瘦身 / 低置信全编制兜底）（手册 §5）；
5. **评测验收**：300 条验证集准确率 ≥92% 后放量（手册 §6）。

独立开关、独立回退，未达标可整点放弃，不影响现有链路。

---

## 5. 风险与护栏

| 风险 | 护栏 |
|---|---|
| 意图路由误判 | 保留现词频规则为兜底；置信度低于阈值走全编制；开关随时可关；判错损失上限是"没省到"，不会更差 |
| 领域数据漂移（query 分布变化） | 定期从问答日志增量回流标注，增量续训 |
| 显存/资源争抢（后端同机） | 路由模型懒加载 + 可配 CPU；备选走独立进程（ollama） |
| 本机推理显存不足（低配显卡） | ollama Q4 / CPU 推理，配置级回退 |
| 云端实例数据丢失（AutoDL 关机 15 天释放） | 训练产物（LoRA 权重/合并模型）当次 scp 下载回本机并另存网盘；数据集脚本化可随时重建 |
| 微调过拟合小样本 | LoRA 学习率 2e-4、epoch ≤3、留出 10% 验证集看 loss；宁可欠拟合保持泛化 |
| Qwen3 thinking 模式拖慢/污染 JSON | 训练端非思考模板、推理端 `enable_thinking=False` / `--think=false` 三处关闭（手册 §3.2） |

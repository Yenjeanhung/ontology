# 意图路由模型微调训练与部署手册（Qwen3-0.6B · LoRA）

> 配套《模型微调总体设计.md》。只覆盖 **1 个模型**：
> **查询意图路由**（Qwen3-0.6B + LoRA，LLaMA-Factory，SFT 指令监督）。
> 训练在 AutoDL 云 GPU 上进行（本机显卡低，只承担推理部署），产物 scp 拷回本机接入平台。

## 0. 全流程一览（LoRA 微调 7 步，先建立全局感）

```
① 租卡装环境      AutoDL 租 4090 + 装 LLaMA-Factory            （§1，一次性 ~10 分钟）
② 造数据          SFT 三元组 JSON → 上传实例 + 注册 dataset_info（§2）
③ 写训练 yaml     LoRA 配置一份（r=16, alpha=32, target all）    （§3.3）
④ 训练            llamafactory-cli train → 盯 loss 曲线         （§3.3）
⑤ 合并导出        llamafactory-cli export → 独立完整模型         （§3.3）
⑥ 下载部署        scp 回本机 → ollama Q4 量化 / 进程内直推       （§4）
⑦ 接入验收        query_router.py + 300 条验证集评测             （§5/§6）
```

LoRA 流程与全参微调的流程差异只在 ③④⑤：多一份 LoRA 配置、显存占用小一个量级、
训练产物是 adapter（几十 MB）需要合并导出才能独立部署——其余步骤完全一致。

## 2. 训练数据构造

统一 SFT 格式（LLaMA-Factory alpaca 风格，`finetune/data/ontology_router.json`）：

```json
{"instruction": "判断用户查询的意图类别，从 kb(知识库)/graph(图谱)/data(台账数据)/chat(寒暄杂询) 中选择，输出 JSON：{\"labels\":[],\"confidence\":0.0}", "input": "今天 MU5307 航班正常率怎么样", "output": "{\"labels\":[\"data\"],\"confidence\":0.92}"}
```

- 种子：现网 query（`chat_messages` 用户消息）人工标注 300~500 条
  （按 DataAgent 命中史/图谱命中史辅助粗标）；
- 扩造：台账词表模板（正常率、延误、滑回…）、图谱词表模板（关联、上下游、涉及哪些…）、
  寒暄模板各扩 200~500 条；
- data 类正样本可直接复用词频强信号（`DATA_STRONG`）命中记录；
- 目标量：合计 1000~2000 条；校验脚本确保 output 均为合法 JSON；
- 留出 10% 作验证集（另存 `ontology_router_eval.json`，训练时不参与，仅评测用）；
- **注意**：训练 instruction 必须与线上 `query_router.py` 的 `ROUTER_PROMPT` 逐字一致。

数据集注册（`finetune/data/dataset_info.json`，LLaMA-Factory 靠它找到数据）：

```json
{
  "ontology_router": {
    "file_name": "ontology_router.json",
    "columns": {
      "prompt": "instruction",
      "query": "input",
      "response": "output"
    }
  }
}
```

## 3. LoRA 训练（LLaMA-Factory）

### 3.1 微调方案总览（面试先答这张表）

> 全景分类（SFT/FFT/RLHF/DPO/LoRA/QLoRA 属于哪些维度、如何组合）
> 见《微调方法体系.md》；本节只讲本项目怎么选。

**一句话说清**：用 **LLaMA-Factory** 框架对 `Qwen3-0.6B` 做 **LoRA** 微调（PEFT），
训练范式是 **SFT 指令监督**。

三个层次别混（面试容易被绕进去的坑）——**框架**（用什么工具训）、**微调方案**（动哪些参数）、
**训练范式**（监督信号长什么样）是三码事：

| 层次 | 本项目选型 |
|---|---|
| 训练框架（工具） | LLaMA-Factory |
| **微调方案（动哪些参数）** | **LoRA 参数高效微调（PEFT）** |
| 训练范式（监督信号） | SFT 指令监督（instruction→JSON） |
| 基座 | `Qwen/Qwen3-0.6B`（对话底座） |
| 可训练参数 | <1%（rank 16 低秩旁路，target all） |
| 产物 | LoRA adapter（几十 MB）→ 合并导出完整模型 |

**易混点：全参微调 vs SFT——不是对立面，是两个维度**：

- **全参/LoRA** 回答"动多少参数"（100% vs <1%）；
- **SFT/预训练** 回答"用什么数据教什么"（指令对 vs 海量语料学下一个词）；
- 两者可自由组合。本项目 = **LoRA + SFT**（小模型改行为的业界标准组合）；
  原厂出 Instruct 版 = 全参 + SFT；领域续训 = 全参/LoRA + 继续预训练。

**为什么选 LoRA（面试必问"方案选型依据"）**：

- 基座是对话模型，任务就是"按指令输出固定格式 JSON"——标准 SFT 场景；
- 只需改输出行为、不需要动语言能力 → 更新量低秩，LoRA 近无损；
- 省显存省存储：可训练参数 <1%，产物 adapter 几十 MB，底座可复用；
- 0.6B 虽然也训得起全参，但 LoRA 对小数据（1~2k 条）**过拟合风险更低**，
  且这是"主流标准做法"，面试口径与业界一致。

**为什么基座选 Qwen3-0.6B**：

- 同量级最新一代（2025-04 发布）：指令跟随与格式稳定性强于上代 0.5B、
  原生 32K 上下文、官方持续维护、社区生态新；0.6B 与 4 分类窄任务量级匹配，
  Q4 量化后约 0.5G 本机可推理；
- **面试口径**：别只说"模型比较新"（弱理由，易被追问"新就一定好吗"）。
  强口径三段式：量级匹配任务 → 新基座指令跟随更强、维护活跃 →
  "我清楚它的 thinking 双模特性，训练与推理都做了关闭处理，保证低延迟和纯 JSON 输出"——
  能主动讲出坑与处理，比"用了新模型"本身更加分。

### 3.2 方法原理（面试向）

- **SFT（Supervised Fine-Tuning，指令监督微调）**：把任务写成
  `instruction（指令）/ input（输入）/ output（标准答案）` 三元组，让模型学会
  "按指令、对给定输入、产出目标格式的回答"。与预训练的区别：预训练用海量语料学
  "下一个词"（学语言能力），SFT 用小而精的任务数据学"按指令办事"（学行为对齐）。
  本项目 output 是严格 JSON `{"labels":[...],"confidence":...}`——微调的最大收益之一
  就是**格式稳定性**（纯 prompt 下小模型经常漂移）。
- **LoRA（Low-Rank Adaptation）核心**：冻结全部原权重 W，在每个目标线性层旁边加一条
  低秩旁路 `ΔW = B·A`（A 是 r×d 高斯初始化，B 是 d×r **零初始化**），
  前向变为 `h = Wx + (α/r)·BAx`：
  - B 零初始化 → 训练起点 ΔW=0，模型行为与原模型完全一致，训练稳定不破坏底座；
  - r（rank，秩）= 旁路容量，分类/格式化任务 8~16 足够；`lora_alpha/r` 是缩放系数
    （本例 32/16=2）；`lora_target: all` = 给所有线性层装旁路；
  - 效果：0.6B 模型可训练参数降到 **<1%**（几 M~几十 M），优化器状态同步骤减 →
    显存大降、产物只有几十 MB 的 adapter；
  - 理论依据（加分点）：微调带来的权重更新量本征上就是**低秩的**——
    窄任务不需要满秩自由度，所以低秩旁路能逼近全参微调的效果。
- **QLoRA（本例未用，要能讲清楚）**：在 LoRA 基础上把冻结的主干量化成 4bit NF4
  （+双量化+分页优化器），基座显存再压 ~4 倍，LoRA 旁路仍以 bf16 训练。
  12G 以下小卡训 7B+ 才需要；0.6B 在 4090 24G 上直接 bf16 LoRA，无需量化。
- **训练配置直觉**：
  - `learning_rate: 2e-4`：只训旁路、参数量极小，学习率可比全参微调大 1~2 个数量级；
  - `num_train_epochs: 3`：1~2k 条小数据，防背模板过拟合；
  - `cutoff_len: 1024`：路由样本很短，截断省显存省时间；
  - `template: qwen3`：Qwen3 对话模板，**训练与线上推理的模板必须一致**，
    否则效果劣化——所以手册强调训练 instruction 与线上 `ROUTER_PROMPT` 逐字相同；
  - loss 只算在 output 上（LLaMA-Factory 默认 `train_on_prompt: false`），
    不浪费算力在指令模板部分。
- **Qwen3 特有坑：thinking 模式全程关闭**（面试加分细节）：
  Qwen3 是"思考/非思考"双模模型，默认开思考会先输出 `<think>…</think>` 再给答案——
  路由要求 <100ms 延迟和纯 JSON 输出，思考模式两者都毁。三处都要处理：
  训练端 LLaMA-Factory `template: qwen3` 默认按非思考训练（数据中也没有思考内容）；
  推理端进程内直推 `apply_chat_template(..., enable_thinking=False)`；
  ollama 侧 `--think=false`（或提示词末尾加 `/no_think` 软开关）。
- **合并导出 + 量化部署**：`export` 把 `B·A` 加回 `W` 得到独立完整模型
  （摆脱运行时 peft 依赖，任何推理框架都能加载）；ollama 从 safetensors 导入时
  默认量化为 Q4（fp16 权重压到 4bit 整数，0.6B 从 ~1G 降到 ~0.5G），
  窄任务上精度损失可忽略，上线前用验证集对比确认即可。
- **为什么微调而不是纯 prompt 调大模型**（动机题）：该任务每问必触发（高频）、
  要求稳定 JSON、需要可用作阈值的 confidence；prompt 大模型每次调用有成本与延迟、
  格式偶发漂移；0.6B 专训后在窄任务上准确率可打平大模型，而单次推理近乎零成本。
  标准降本路径：先 prompt 验证任务可行 → 再用日志/模板造数 → 微调小模型固化。

### 3.3 训练实操（yaml → 训练 → 合并导出）

`qwen06b_router_lora.yaml`：

```yaml
model_name_or_path: Qwen/Qwen3-0.6B
stage: sft
do_train: true
finetuning_type: lora
lora_rank: 16
lora_alpha: 32
lora_dropout: 0.05
lora_target: all
dataset: ontology_router
template: qwen3
cutoff_len: 1024
max_samples: 100000
learning_rate: 2.0e-4
num_train_epochs: 3
per_device_train_batch_size: 8
gradient_accumulation_steps: 2
warmup_ratio: 0.03
logging_steps: 10
save_steps: 200
output_dir: saves/qwen06b-router-lora
plot_loss: true
```

```bash
source /etc/network_turbo    # 拉基座权重前先加速（首次运行自动下载 Qwen3-0.6B，约 1.5G）
llamafactory-cli train qwen06b_router_lora.yaml
# 4090 24G 上 0.6B LoRA 显存富余（<6G），无需 QLoRA；换小卡才考虑 quantization_bit: 4
# 1000~2000 条数据 epoch 3 约几分钟~十几分钟；saves/ 下出 adapter（几十 MB）+ loss 曲线图
```

**盯 loss**：`plot_loss: true` 会在 output_dir 生成曲线——
正常形态是前几百步快速下降后趋平；若验证 loss 回升即过拟合，
先减 epoch 或加数据，别急着调 rank。

**合并导出**（adapter → 独立完整模型，便于下载回本机部署）：

```bash
llamafactory-cli export --model_name_or_path Qwen/Qwen3-0.6B \
  --adapter_name_or_path saves/qwen06b-router-lora \
  --export_dir /root/autodl-tmp/models/qwen06b-router-merged --export_size 2
# 产物：完整权重目录（safetensors + tokenizer 配置），scp 下载见 §1.4
```

验收标准：留出 10% 验证集，loss 平稳不反弹；任务级验收见 §6。

### 3.4 面试追问速答

| 可能的追问 | 一句话回答 |
|---|---|
| 全参微调和 SFT 什么区别？ | 不同维度：全参/LoRA 说"动多少参数"，SFT/预训练说"用什么数据教什么"；本项目是 LoRA + SFT 组合 |
| LoRA 为什么有效？ | 微调的权重更新量本征低秩，窄任务不需要满秩自由度；低秩旁路 ΔW=BA 可逼近全参微调 |
| LoRA 的 B 为什么初始化为 0？ | 保证训练起点 ΔW=0，模型行为与原模型完全一致，训练稳定、不破坏预训练知识（A 高斯初始化提供对称性破缺） |
| LoRA 和全参微调差多少？ | 秩足够时窄任务上近无损；换来可训练参数 <1%、产物几十 MB、可多任务多 adapter 复用一个底座 |
| LoRA 学习率为什么是 2e-4 这么大？ | 只训旁路新增参数且 B 从零起步，收敛需要较大步长；全参微调动的是预训练权重，必须用 1e-5 级保守值 |
| rank（r）怎么选？ | 旁路容量：分类/格式化窄任务 8~16 足够，越大越逼近全参但过拟合与显存上升；可从 8 起步看验证集 |
| SFT 的 loss 算在哪？ | 只算 output（回答）部分，LLaMA-Factory 默认 `train_on_prompt: false`，指令与输入不计 loss |
| QLoRA 是什么，你为什么没用？ | 4bit NF4 量化冻结主干 + LoRA 旁路 bf16 训练 + 双量化/分页优化器，为 12G 卡训 7B+ 准备；本项目 0.6B 在 4090 上 bf16 LoRA 就够 |
| 怎么防微调过拟合？ | 学习率 2e-4、epoch≤3、留出 10% 验证集看 loss 平稳、数据去重、宁欠拟合保泛化 |
| 量化会掉点吗？ | 训练侧 QLoRA 基本无损；部署侧 Q4 对 0.6B 窄任务影响可忽略，用验证集对比确认后再上线 |
| 为什么合并导出？ | 把旁路 B·A 加回 W 得独立完整模型，摆脱运行时 peft 依赖，ollama/vLLM 任何推理框架都能直接加载 |
| 训练和推理的 template 为什么必须一致？ | chat 模板决定 prompt 的拼装结构（special token/角色标记），不一致等于训练与推理的输入分布不同，效果劣化 |
| Qwen3 有什么坑？ | thinking 双模：默认先输出 `<think>` 再给答案，毁延迟和纯 JSON；三处关闭——训练端 qwen3 非思考模板、直推 `enable_thinking=False`、ollama `--think=false` 或提示词加 `/no_think` |
| 为什么选微调而不是提示词？ | 高频触发 + 窄任务 + 输出格式固定 + 判错可兜底——四个条件都满足，微调收益稳定；大模型调用省为本地零成本推理 |
| 为什么选 Qwen3-0.6B？ | 量级匹配任务 → 同量级最新一代、指令跟随强、维护活跃 → 我清楚 thinking 双模的坑并做了关闭处理（别只说"模型新"） |

**方案 A（进程内直推）**——按下方骨架实现：

`services/query_router.py`（骨架，方案 A）：

```python
from functools import lru_cache
from config import settings

@lru_cache(maxsize=1)
def _load():
    from transformers import AutoModelForCausalLM, AutoTokenizer
    tok = AutoTokenizer.from_pretrained(settings.ROUTER_MODEL_PATH)
    mdl = AutoModelForCausalLM.from_pretrained(settings.ROUTER_MODEL_PATH, torch_dtype="auto")
    return tok, mdl

async def classify(query: str) -> dict:
    """返回 {"labels": [...], "confidence": float}；任何异常返回 None（调用方走全编制）。"""
    if not settings.ROUTER_ENABLED:
        return None
    try:
        tok, mdl = _load()
        prompt = ROUTER_PROMPT.format(query=query)          # 与 §2 训练 instruction 一致
        ids = tok.apply_chat_template(                      # 必须走 qwen3 chat 模板，与训练一致
            [{"role": "user", "content": prompt}],
            tokenize=True, add_generation_prompt=True,
            enable_thinking=False,                          # Qwen3 关思考，保低延迟与纯 JSON
            return_tensors="pt")
        out = mdl.generate(**ids, max_new_tokens=64, do_sample=False)
        return _parse_json(tok.decode(out[0][ids.input_ids.shape[1]:], skip_special_tokens=True))
    except Exception:
        return None   # 永不阻塞主流程
```

`config.py` 追加：

```python
ROUTER_ENABLED: bool = False
ROUTER_MODEL_PATH: str = "./data/models/query-router"
```

接入点（多智能体入口拿到 `query` 后先 `classify()`）：
- `chat` → 主大模型直答，不编排；
- 单标签 → 只勾选对应能力智能体进 Planner 输入（编制瘦身）；
- `None` / 低置信度 → 走现状全编制（兜底）；
- **边界**：路由之后 Planner / Worker / ToolAgent / Synthesizer 的模型选择不变，
  仍全部走 `create_llm()` 主大模型——路由只决定"要不要编排、编排谁"。

回退：`ROUTER_ENABLED=false` 即恢复现状。

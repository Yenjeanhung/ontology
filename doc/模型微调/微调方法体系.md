# 模型微调方法体系（三个正交维度 × 方法全景）

> 回答核心问题：**SFT、FFT、RLHF、DPO、LoRA、QLoRA 不是同一维度的并列项**——
> 它们分属 3 个正交维度：**训练范式**（用什么数据教什么）、**参数范围**（动多少权重）、
> **数值精度**（是否量化）。日常说的"方法名"大多是这三个维度的组合词。
> 本项目映射：**LoRA + SFT**（LLaMA-Factory 一份 yaml 两个关键字：
> `finetuning_type: lora` 定维度②，`stage: sft` 定维度①）。

---

## 0. 一张表看清三个维度（正交、可自由组合）

| 维度① 训练范式（教什么） | 维度② 参数范围（动多少权重） | 维度③ 数值精度（量化与否） |
|---|---|---|
| CPT 继续预训练（领域语料） | FFT 全参微调（~100% 权重） | bf16/fp16 混合精度（默认） |
| SFT 监督微调（指令→回答对） | 部分层微调（冻结底层只训顶层） | 8bit LLM.int8 |
| RLHF 奖励模型 + PPO | PEFT 参数高效（<1% 权重） | 4bit NF4（QLoRA 用） |
| DPO 直接偏好优化（偏好对） | ↳ 低秩旁路：LoRA / QLoRA / DoRA | |
| GRPO 组相对策略优化（免价值模型） | ↳ 加性前缀/模块：Adapter / Prefix / P-Tuning v2 | |
| 蒸馏 大模型输出当 SFT 数据 | ↳ 缩放类：IA³ / BitFit | |

任一"方法名" ≈ 跨维度组合，例：

| 组合 | 维度①×②×③ | 是谁在用 |
|---|---|---|
| FFT + SFT + bf16 | 全参 + 监督微调 | 原厂炼 Instruct 版 |
| **LoRA + SFT + bf16** | 低秩旁路 + 监督微调 | **本项目意图路由（主流小模型改行为）** |
| QLoRA + SFT + NF4 | 4bit 主干 + LoRA + 监督微调 | 12G 小卡训 7B |
| FFT + SFT → FFT + RLHF | 三阶段对齐 | ChatGPT 式完整后训练 |

## 1. 维度①：训练范式（监督信号是什么）

**CPT（Continual Pre-Training，继续预训练）—— 领域基座团队的活，应用层很少亲手做，面试知道概念即可**
- 数据：领域海量无标注语料；目标：学"下一个词"（自回归 cross-entropy）；
- 用途：给基座**注入领域知识**（法律/医疗语料续训）；窄任务不需要，成本高。

**SFT（Supervised Fine-Tuning，监督微调）—— 一切后训练的地基**
- 数据：`instruction / input / output` 三元组（指令→标准回答对）；
- 目标：学"按指令办事"——行为对齐 + 输出格式稳定；loss 只算 output 部分；
- 与预训练的区别：预训练学**语言能力**（海量语料），SFT 学**指令行为**（小而精的任务数据）；
- 本项目的 4 分类 JSON 输出就是标准 SFT 场景。

**RLHF（Reinforcement Learning from Human Feedback，基于人类反馈的强化学习）**
- 三阶段：SFT → 人类标注偏好对训**奖励模型 RM**（Reward Model）→ **PPO**
  （Proximal Policy Optimization，近端策略优化）强化学习优化策略
  （用 KL 惩罚约束不偏离 SFT 初值太远）；
- 解决 SFT 管不了的问题："哪种回答**更好**"没有唯一标准答案，只能靠偏好相对比较；
- 缺点：流程重（要训 RM）、PPO 训练不稳、超参敏感、实现成本高。

**DPO（Direct Preference Optimization，直接偏好优化）—— RLHF 的简化替代**
- 核心洞察：RLHF 的目标可以数学变形，**跳过奖励模型和 RL**，直接用偏好对
  `(chosen, rejected)` 做一个类似分类的损失（隐式奖励 = 策略与参考模型的对数比）；
- 优点：等价优化目标、实现简单（一份偏好数据 + SFT 式训练即可）、稳定；
- 变体：**ORPO**（Odds Ratio Preference Optimization，比值偏好优化——并入 SFT 单阶段）、
  **KTO**（Kahneman-Tversky Optimization，卡尼曼-特沃斯基优化——只需单边好/坏标注）、
  **SimPO**（Simple Preference Optimization，简化偏好优化）、
  **IPO**（Identity Preference Optimization，恒等偏好优化）——知道名字和一句话区别即可；
- 位置：RLHF/DPO 都在 **SFT 之后**（先教会说话，再教偏好）。

**GRPO（Group Relative Policy Optimization，组相对策略优化）—— DeepSeek 系的 RL 简化**
- 出身：DeepSeekMath 提出，DeepSeek-R1 的推理能力训练就用它；
- 核心改动：同一 prompt **采样一组回答**，用组内奖励的相对比较（减组均值）当优势——
  **免 critic/价值模型**（PPO 要额外训一个与策略同大的价值网络估基线），
  显存与工程复杂度大幅下降；
- 与 DPO 的区别：DPO 把 RL 蜕化为**离线监督损失**（不再采样、不在线更新）；
  GRPO 仍是**在线 RL**（要采样、要 KL 约束），只是把基线从价值模型换成组内均值；
- 奖励来源与 RLHF 相同：偏好模型或规则奖励都行（R1 用规则奖励：答案对 + 格式对）。

**蒸馏（Distillation）**：严格说是 SFT 的**数据来源**——用强模型（大模型）生成回答
当 SFT 标签训小模型（如 DeepSeek-R1 蒸馏版）；**RFT**（Rejection Sampling Fine-Tuning，
拒绝采样微调）/ **STaR**（Self-Taught Reasoner，自举推理）：模型自己做对才保留为
训练数据，用于推理能力增强。

**选型直觉**：有标准答案 → SFT；只有"哪个更好"的相对偏好 → DPO/RLHF/GRPO；
要注入大量领域知识 → CPT。本项目 4 分类有唯一标准 JSON 答案 → SFT 足够，
暂不需要 DPO/RLHF（未来若要调"回答语气/拒绝边界"这类无标准答案的偏好才用得上）。

## 2. 维度②：参数更新范围（动多少权重）

**FFT（Full Fine-Tuning，全参微调）**
- 100% 参数参与更新；同数据下效果上限最高，但：显存最大（要存全部参数+梯度+优化器状态，
  约为参数量 × 16 字节）、易**灾难性遗忘**、每个任务存一份完整权重；
- 0.6B 也训得起 FFT，但本项目不用：小数据（1~2k 条）全参过拟合风险更高，
  且 LoRA 才是业界改窄行为的标准做法（面试口径一致性）。

**部分参数微调**（Partial Fine-Tuning）：冻结 Embedding/底层，只训顶层若干层；
**BitFit**（Bias-only Fine-Tuning，仅偏置微调）：只训所有 bias（~0.1% 参数）。
简单但容量受限，现在多被 PEFT 取代。

**PEFT（Parameter-Efficient Fine-Tuning，参数高效微调）—— 可训练参数 <1%**
- **低秩旁路类（当前主流）**：
  - **LoRA**（Low-Rank Adaptation，低秩适配）：冻结 W，旁路 `ΔW = B·A`（A 高斯初始化，
    B 零初始化），前向 `h = Wx + (α/r)·BAx`；理论依据：微调的更新量本征低秩；
  - **QLoRA**（Quantized LoRA，量化低秩适配）：LoRA + 把冻结主干量化为 4bit NF4
    （+Double Quantization 双量化 + Paged Optimizer 分页优化器）；
  - **DoRA**（Weight-Decomposed LoRA，权重分解低秩适配）：把权重分解为幅度×方向
    分别低秩更新，小秩下更接近 FFT；
  - **LoRA+**（LoRA with Different Learning Rates，A/B 差异化学习率）、
    **rsLoRA**（Rank-Stabilized LoRA，秩稳定——缩放按 √r 修正）、
    **AdaLoRA**（Adaptive LoRA，秩自适应分配）——知道名字即可；
- **加性前缀类**：**Prefix Tuning**（前缀微调：每层注意力前加可训练前缀 KV）、
  **P-Tuning v2**（Deep Prompt Tuning，深层提示微调——≈ 每层前缀，与 Prefix 基本同义）、
  **Prompt Tuning**（软提示微调：只在输入层加 soft prompt，最省但容量最小）、
  **Adapter**（适配器模块：层间插入小瓶颈模块，**改变推理图有额外延迟**，LoRA 可合并无延迟）；
- **其他**：**IA³**（Infused Adapter by Inhibiting and Amplifying Inner Activations：
  逐通道可训练缩放向量，比 LoRA 更少参数）。

**选型直觉**：改行为（分类/格式/风格/遵循指令）→ LoRA 足够；注入新知识 → CPT 或 FFT
（LoRA 学不进大量新知识，只能引导既有能力的使用方式）。

## 3. 维度③：数值精度 / 量化（怎么省着训）

- **混合精度 bf16/fp16**（BFloat16 / Float16）：默认，权重主副本 fp32 + 计算用 bf16；
- **LLM.int8（8-bit Integer Quantization，8比特整数量化）**：bitsandbytes，主干 8bit，
  早期方案，已被 NF4 取代；
- **NF4（4-bit NormalFloat，4比特正态浮点）**：QLoRA 提出的 4bit 数值格式（信息论最优），
  配双量化与分页优化器；
- **正交性**：量化可与维度①②任意叠加——通常与 PEFT 组合成 QLoRA（训练侧）；
- **区分（易混点）**：训练侧量化（QLoRA/NF4，为了省显存训练）vs **部署侧量化**
  （**GGUF** Q4/Q8、**AWQ**（Activation-aware Weight Quantization，激活感知权重量化）、
  **GPTQ**（GPT Post-Training Quantization，训练后量化），为了省显存推理）
  ——后者与微调方法无关，本项目 ollama 的 Q4 就属于部署侧，别在面试里混为一谈。

## 5. 面试速答

| 追问 | 一句话回答 |
|---|---|
| SFT 和 LoRA 是一类东西吗？ | 不是：SFT 是训练范式（教什么），LoRA 是参数范围（动多少）；可组合成"LoRA + SFT"（本项目） |
| FFT 和 SFT 的区别？ | 不同维度：FFT/LoRA 说动多少参数，SFT/CPT/RLHF 说用什么数据教什么；原厂 Instruct 版 = FFT + SFT |
| QLoRA 和 LoRA 的区别？ | QLoRA = LoRA + 冻结主干量化 4bit NF4，省的是基座显存；LoRA 旁路本身始终 bf16 训练 |
| RLHF 和 DPO 什么区别？ | 目标同源；RLHF 要训奖励模型再 PPO（重、不稳），DPO 数学变形后免 RM 免 RL，直接偏好对做类分类损失（轻、稳）；都在 SFT 之后 |
| GRPO 和 PPO 什么区别？ | 都是在线 RL；PPO 需额外训价值模型估基线（显存大、不稳），GRPO 同一 prompt 采样一组回答、用组内均值当基线，免价值模型（DeepSeek-R1 采用） |
| 什么时候 RLHF/DPO、什么时候 SFT？ | 有唯一标准答案→SFT；只有相对偏好（语气/安全边界）→DPO/RLHF |
| PEFT 有哪几类？ | 低秩旁路（LoRA 系）、加性前缀（Prefix/P-Tuning v2/Prompt Tuning）、加性模块（Adapter）、缩放（IA³/BitFit） |
| LoRA 能学新知识吗？ | 基本不能——它只引导既有能力的使用方式；注入大量新知识要 CPT/FFT（加分认知） |
| 训练量化 vs 部署量化？ | QLoRA 的 NF4 省训练显存；GGUF Q4/AWQ/GPTQ 省推理显存，两回事 |

## 6. 本项目落地：意图路由模型（Qwen3-0.6B + LoRA + SFT）

> 把前五个维度的通用知识落到本项目：一个 4 分类意图路由模型，用 LLaMA-Factory 做 LoRA + SFT。
> 训练 / 部署的可执行步骤在《训练与部署手册.md》，本节只讲选型依据与方法原理（面试向）。

### 6.1 方案选型（三个层次别混）

**一句话说清**：用 **LLaMA-Factory** 框架对 `Qwen3-0.6B` 做 **LoRA** 微调（PEFT），训练范式是 **SFT 指令监督**。

三个层次别混——**框架**（用什么工具训）、**微调方案**（动哪些参数）、**训练范式**（监督信号长什么样）是三码事：

| 层次 | 本项目选型 |
|---|---|
| 训练框架（工具） | LLaMA-Factory |
| **微调方案（动哪些参数）** | **LoRA 参数高效微调（PEFT）** |
| 训练范式（监督信号） | SFT 指令监督（instruction→JSON） |
| 基座 | `Qwen/Qwen3-0.6B`（对话底座） |
| 可训练参数 | <1%（rank 16 低秩旁路，target all） |
| 产物 | LoRA adapter（几十 MB）→ 合并导出完整模型 |

**易混点：全参微调 vs SFT——不是对立面，是两个维度**：
- **全参/LoRA** 回答"动多少参数"（100% vs <1%）；
- **SFT/预训练** 回答"用什么数据教什么"（指令对 vs 海量语料学下一个词）；
- 两者可自由组合。本项目 = **LoRA + SFT**（小模型改行为的业界标准组合）；原厂出 Instruct 版 = 全参 + SFT；领域续训 = 全参/LoRA + 继续预训练。

**为什么选 LoRA（方案选型依据）**：
- 基座是对话模型，任务就是"按指令输出固定格式 JSON"——标准 SFT 场景；
- 只需改输出行为、不需要动语言能力 → 更新量低秩，LoRA 近无损；
- 省显存省存储：可训练参数 <1%，产物 adapter 几十 MB，底座可复用；
- 0.6B 虽然也训得起全参，但 LoRA 对小数据（1~2k 条）**过拟合风险更低**，且是"主流标准做法"，面试口径与业界一致。

**为什么基座选 Qwen3-0.6B**：
- 同量级最新一代（2025-04 发布）：指令跟随与格式稳定性强于上代 0.5B、原生 32K 上下文、官方持续维护、社区生态新；0.6B 与 4 分类窄任务量级匹配，Q4 量化后约 0.5G 本机可推理；
- **面试口径**：别只说"模型比较新"（弱理由，易被追问"新就一定好吗"）。强口径三段式：量级匹配任务 → 新基座指令跟随更强、维护活跃 → "我清楚它的 thinking 双模特性，训练与推理都做了关闭处理，保证低延迟和纯 JSON 输出"——能主动讲出坑与处理，比"用了新模型"本身更加分。

### 6.2 方法原理（项目向）

- **SFT**：把任务写成 `instruction / input / output` 三元组，让模型学会"按指令、对给定输入、产出目标格式的回答"。本项目 output 是严格 JSON `{"labels":[...],"confidence":...}`——微调最大收益之一是**格式稳定性**（纯 prompt 下小模型经常漂移）。
- **LoRA 核心**：冻结全部原权重 W，在每个目标线性层旁加低秩旁路 `ΔW = B·A`（A 高斯初始化，B **零初始化**），前向 `h = Wx + (α/r)·BAx`：B 零初始化 → 训练起点 ΔW=0，模型行为与原模型完全一致，训练稳定不破坏底座；r（秩）= 旁路容量，分类/格式化任务 8~16 足够；`lora_alpha/r` 是缩放系数（本例 32/16=2）；`lora_target: all` 给所有线性层装旁路；效果：0.6B 可训练参数降到 <1%，产物只有几十 MB 的 adapter；理论依据：微调带来的权重更新量本征低秩，窄任务不需要满秩自由度。
- **QLoRA（本例未用）**：在 LoRA 基础上把冻结主干量化成 4bit NF4（+双量化+分页优化器），基座显存再压 ~4 倍；12G 以下小卡训 7B+ 才需要。
- **训练配置直觉**：`learning_rate: 2e-4`（只训旁路、参数量极小，可比全参大 1~2 个数量级）；`num_train_epochs: 3`（1~2k 条小数据防过拟合）；`cutoff_len: 1024`（路由样本短）；`template: qwen3`（训练与推理模板必须一致）；loss 只算 output（LLaMA-Factory 默认 `train_on_prompt: false`）。
- **Qwen3 特有坑：thinking 模式全程关闭**：Qwen3 是"思考/非思考"双模，默认开思考会先输出 `<think>…</think>` 再给答案——路由要 <100ms 延迟和纯 JSON，思考模式两者都毁。三处都要处理：训练端 `template: qwen3` 按非思考训练；推理端 `apply_chat_template(..., enable_thinking=False)`；ollama 侧 `--think=false`（或提示词末尾加 `/no_think`）。
- **合并导出 + 量化部署**：`export` 把 `B·A` 加回 `W` 得独立完整模型（摆脱 peft 依赖）；ollama 导入默认量化 Q4（0.6B 从 ~1G 降到 ~0.5G），窄任务精度损失可忽略，上线前用验证集对比确认。
- **为什么微调而不是纯 prompt**：该任务每问必触发（高频）、要求稳定 JSON、需要可作阈值的 confidence；prompt 大模型有成本与延迟、格式偶发漂移；0.6B 专训后窄任务准确率可打平大模型，单次推理近乎零成本。标准降本路径：先 prompt 验证可行 → 造数 → 微调固化。

### 6.3 基座模型目录文件构成（Qwen3-0.6B，`ll -h` 实测）

HF transformers 格式模型目录 = **权重 + 结构 + 分词器** 三类，加载顺序：`config.json` 搭骨架 → `model.safetensors` 灌权重 → 分词器做文本↔token 互转。

**权重 + 结构（模型的"身体"）**

| 文件 | 大小 | 作用 |
|---|---|---|
| `model.safetensors` | 1.5G | 模型权重本体，bf16（0.6B 参数 × 2 字节 + embedding）。safetensors 只存张量、反序列化不执行代码（对比 pickle 格式 `.bin` 无安全风险）；更大模型分片为 `model-0000X-of-0000N.safetensors` + `model.safetensors.index.json` 索引 |
| `config.json` | 726B | 模型"图纸"，训练启动时打印的就是它：28 层 decoder、16 注意力头 / 8 KV 头（GQA 省 KV cache）、词表 151936、RoPE theta 1e6、`max_position_embeddings: 40960`；加载第一步读它决定网络结构 |
| `generation_config.json` | 239B | 推理默认生成参数（temperature/top_p/top_k/eos_token_id），**只影响 `generate()` 输出风格，与训练无关**；部署时 ollama/vLLM 参考它，Modelfile `PARAMETER temperature 0.0` 覆盖的正是这层 |

**分词器（模型的"嘴巴和耳朵"）**

| 文件 | 大小 | 作用 |
|---|---|---|
| `tokenizer.json` | 11M | fast tokenizer 一体化定义：词表 + 合并规则 + 归一化 + special token 打包一个 JSON，Rust 实现加载快，transformers 默认优先用它 |
| `tokenizer_config.json` | 9.6K | 分词器行为配置：bos/eos/pad 映射、**chat_template**（Qwen3 对话模板）——LLaMA-Factory `template: qwen3` 对应的就是它，训练数据按此拼对话格式 |
| `vocab.json` + `merges.txt` | 2.7M + 1.6M | BPE 底层原料：token→id 词表 + 字节对合并优先级表；tokenizer.json 相当于它俩的编译产物，保留两份是兼容只认 slow 格式的老代码 |

**元数据（与运行无关）**

| 文件 | 作用 |
|---|---|
| `.cache/` | `hf download` 工作目录（下载锁、断点分片），加载用不到，拷贝/打包模型时可整删 |
| `.gitattributes` | HF Hub git LFS 大文件声明，纯仓库元数据 |
| `LICENSE` / `README.md` | 许可证（Qwen3 系 Apache-2.0）与模型卡 |

与 LoRA 的关系：微调时基座整套**只读不动**，训练只产出 `saves/` 下的 adapter——合并导出（`export`）的输入正是"基座 + adapter"两样。

### 6.4 本项目面试追问速答

| 追问 | 一句话 |
|---|---|
| 全参微调和 SFT 什么区别？ | 不同维度：全参/LoRA 说"动多少参数"，SFT/预训练说"用什么数据教什么"；本项目是 LoRA + SFT 组合 |
| LoRA 为什么有效？ | 微调的权重更新量本征低秩，窄任务不需要满秩自由度；低秩旁路 ΔW=BA 可逼近全参微调 |
| LoRA 的 B 为什么初始化为 0？ | 保证训练起点 ΔW=0，模型行为与原模型一致，训练稳定、不破坏预训练知识（A 高斯初始化提供对称性破缺） |
| LoRA 和全参微调差多少？ | 秩足够时窄任务近无损；换来可训练参数 <1%、产物几十 MB、可多 adapter 复用一个底座 |
| LoRA 学习率为什么是 2e-4 这么大？ | 只训旁路新增参数且 B 从零起步，需较大步长；全参微调动的是预训练权重，必须用 1e-5 级保守值 |
| rank（r）怎么选？ | 旁路容量：分类/格式化窄任务 8~16 足够，越大越逼近全参但过拟合与显存上升；可从 8 起步看验证集 |
| SFT 的 loss 算在哪？ | 只算 output 部分，LLaMA-Factory 默认 `train_on_prompt: false`，指令与输入不计 loss |
| QLoRA 是什么，你为什么没用？ | 4bit NF4 量化冻结主干 + LoRA 旁路 bf16 训练，为 12G 卡训 7B+ 准备；本项目 0.6B 在 4090 上 bf16 LoRA 就够 |
| 怎么防微调过拟合？ | 学习率 2e-4、epoch≤3、留 10% 验证集看 loss、数据去重、宁欠拟合保泛化 |
| 量化会掉点吗？ | 训练侧 QLoRA 基本无损；部署侧 Q4 对 0.6B 窄任务影响可忽略，验证集对比确认后上线 |
| 为什么合并导出？ | 把旁路 B·A 加回 W 得独立完整模型，摆脱 peft 依赖，ollama/vLLM 任何框架都能直接加载 |
| 训练和推理的 template 为什么必须一致？ | chat 模板决定 prompt 拼装结构（special token/角色标记），不一致等于输入分布不同，效果劣化 |
| Qwen3 有什么坑？ | thinking 双模：默认先输出 `<think>` 再给答案，毁延迟和纯 JSON；三处关闭——训练端非思考模板、直推 `enable_thinking=False`、ollama `--think=false` 或 `/no_think` |
| 为什么选微调而不是提示词？ | 高频触发 + 窄任务 + 输出格式固定 + 判错可兜底——四个条件都满足，收益稳定；大模型调用省为本地零成本推理 |
| 为什么选 Qwen3-0.6B？ | 量级匹配任务 → 同量级最新一代、指令跟随强、维护活跃 → 我清楚 thinking 双模的坑并做了关闭处理（别只说"模型新"） |

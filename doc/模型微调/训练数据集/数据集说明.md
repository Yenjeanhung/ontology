# 航班运行告警处置训练集说明

> 供 Qwen3-0.6B LoRA + SFT（LLaMA-Factory）使用的第二套训练数据。
> 意图路由数据（手册 §3.2 的 `ontology_router.json`）之外的新任务，
> 两者可合并做多任务 SFT，也可分开训练。

## 1. 数据来源

- 输入：《告警类型.xlsx》→ `告警主规则` sheet（41 条规则，7 个分类 sheet 已做覆盖校验）
- 配置：`alarm_specs.py`（53 个生成类型：40 类告警 + 12 类系统功能，
  每类含触发条件/阈值/可能原因/处置动作/通知对象/告警文案模板/现象描述模板）
- 生成：`gen_alarm_dataset.py`（固定随机种子可复现，运行时自动校验 xlsx 覆盖）

## 2. 任务设计（4 种子任务混合）

| task | 占比 | input | output JSON 关键字段 |
|---|---|---|---|
| dispose 处置建议 | ~79% | 告警卡/值班口语/简短工单 3 种风格 | task, alarm_type, level, level_name, summary, possible_causes, actions, notify |
| operation 功能问询 | ~13% | 功能操作问句（12 类系统功能） | task, item, function, steps |
| identify 现象识警 | ~5% | 现象描述（不给告警名） | task, alarm_type, level, level_name, basis |
| condition 条件问答 | ~3% | 触发条件/阈值提问 | task, alarm_type, condition, thresholds |

output 统一为单行 JSON（与意图路由 JSON 风格一致，0.6B 易学、格式可控）。

## 3. 告警类型覆盖（40 类）

- **飞机故障监控 11 子类**：发动机火警、APU火警、货舱火警、发动机失效/关停、液压系统关停、
  空中颠簸、燃油不平衡、发动机空中启动、起落架未锁定、座舱高度警告、氧气面罩脱落
- **地面/时序**：滑行过久、飞机滑回、二次开门、大面积延误、航班保障节点、超时未落、超时未起、起飞时间告警
- **空中航迹/安全**：偏航、盘旋等待、复飞、中断起飞、高度突变、高度偏差、低高度、飞机实时可用高度、4D15、时刻偏差、起始进近
- **应答机**：7500（非法干扰）、7600（通信失效）、7700（紧急遇险）——全部 1 级
- **油量/运行决策**：油量偏差、低油量、油量缺失、落地保护油、不可预期燃油3%、超重落地、大面积备降、返航备降

告警等级：1 紧急（火警/7500/7700/低油量/座舱高度/起落架等）、2 重要、3 提醒。

## 4. 规模与分布（seed=20260918，目标 4200）

- **总数 4193 = train 3984（`alarm_dispose_train.json`）+ val 209（`alarm_dispose_val.json`）**
- 任务分布：dispose 3324 / operation 540 / identify 206 / condition 123
- 等级分布：重要 2121 / 紧急 1229 / 提醒 843
- 类型分布：头部（故障子类/应答机）约 108 条，尾部（功能类）约 45 条
- input 全局去重；随机维度：航班号/注册号/机型/机场对/航线卡/时间/区域/数值参数/原因/措辞模板

## 5. 质量约定

- 处置动作（actions）为**训练用模板**，基于民航运控通用 SOP 常识构造，
  **不作为真实运行处置依据**；阈值/触发条件与 xlsx 判断方法列保持一致
- dispose 输出的 possible_causes 强制包含告警文案中已给出的原因（自洽性约束）
- val 从同一分布随机切出（5%），训练时用于观察 loss 与 JSON 格式正确率

## 6. 复现与调整

```powershell
# 重新生成（可传目标条数，3000-5000 之间）
python gen_alarm_dataset.py 4200
```

- 调整某类样本量：改 `alarm_specs.py` 中对应 spec 的 `weight`
- 新增告警类型：在 `alarm_specs.py` 加一个 `spec(...)`，并在生成器 `COVER` 补 xlsx 名称映射（如有别名）
- 改 JSON 字段：生成器 `build()` 的各分支 `json.dumps` 字典

## 7. DPO 偏好对数据集（`ontology_router_dpo.json`）

> SFT 之后的第二阶段训练数据（训练步骤见《训练与部署手册.md》§3.2）。
> SFT 教模型「输出什么」，DPO 用偏好对修正 SFT 后残留的系统性错误模式——
> rejected 全部映射线上路由服务 `router_service.py` 的真实兜底分支。

- 生成：`dpo/gen_dpo_dataset.py`（固定 seed=20260920 可复现；
  `cd dpo` 后 `python gen_dpo_dataset.py 1000`，输出到 `finetune/dpo/`）
- 格式：LLaMA-Factory preference——alpaca 基础上平铺 `chosen`/`rejected` 字段，
  `dataset_info.json` 键 `ontology_router_dpo`（columns 已映射）
- query 与 SFT 严格同分布（复用 `gen_router_dataset.py` 的生成函数与配额，
  换随机种子取新样本；EDGE 边界难例加密到 ~10%，是 DPO 的主战场）
- chosen 与 SFT output 严格同构：`{"labels":[...],"confidence":0.0}`
- rejected 六类失败模式（当前 seed 实测分布）：

| 失败模式 | 占比 | rejected 示例 | 线上后果（router_service.py） |
|---|---|---|---|
| wrong_confident 错标签+高置信 | 27% | 图谱问句答 `["kb"]` conf 0.93 | 合法标签误分类被门控放行，按错 mode 精简组合/直答——错而自信最伤 |
| conf_miscalibrated 置信度失准 | 26% | 标签对但 0.91 → 0.56 | 门控失真：标准输入误触发全组合兜底（白调），模糊输入反被放行 |
| enum_drift 枚举漂移 | 15% | `["台账"]` / `["database"]` | 非法 mode → 回落全组合 |
| key_drift 键名漂移 | 13% | `{"label":...}` / `{"conf":...}` | 未兼容键 → 解析失败回落 |
| format_polluted 格式污染 | 12% | ```json 围栏 / 客套前缀 / `<think>` 残留 | `_parse_json_block` 解析失败 → 回落 |
| multi_object 多 JSON 并列 | 7% | 两个 JSON 连排 | 贪婪正则跨对象 `json.loads` 失败 → 回落 |

- 配比取向：语义层（wrong_confident / conf_miscalibrated）合计过半——
  这才是 DPO 相对 SFT 的真正增量；格式层 SFT 已解决大半，保留少量防过训回退
- 规模（目标 1000）：wrong_confident 273 / conf_miscalibrated 256 / enum_drift 146 /
  key_drift 131 / format_polluted 121 / multi_object 73
